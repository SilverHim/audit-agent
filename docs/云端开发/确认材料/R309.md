# R309 确认材料: 独立复核的跳过原因随界面语言显示

## 改动摘要

- 契约: 新增枚举 `CriticReasonCode`, Judgment 加两个字段.
  - 枚举共 10 个值. 跳过的 5 个: critic_off, no_review_model, level_l1, level_l2, not_triggered. 没做成的 5 个: no_evidence, first_round_invalid, second_round_invalid, chain_invalid, review_error.
  - `critic_reason_code`: 原因代码.
  - `critic_reason_detail`: 没做成时的技术细节.
  - 两个字段都缺省为空, `critic_reason` 照旧写中文原句.
- A7 (`agents/review.py`): 写原因的位置都同时写代码.
  - 改动的函数: `skip`, `incomplete`, 新增的 `invalid` (某一轮输出未通过校验时用).
  - L1, L2 经 `LEVEL_CODES` 对应到代码.
  - 中文原句逐字不变.
- 前端:
  - `lib/review.criticReasonText` 按代码取界面语言的文案. 没有代码, 或代码认不出时, 照 critic_reason 原文.
  - 判断卡的独立复核栏 (工作台与复核页共用 `CriticPanel`) 改用它显示, 技术细节另起一行原样显示.
  - 中英文案 `judgment.critic.reasonCodes`. en.ts 用 `satisfies Record<CriticReasonCode, string>` 要求覆盖全部代码, 少一个时 tsc 报错 (已验证).
- 前端客户端重新生成 (openapi.json, types.gen.ts, index.ts).
- 接口文档第 2.1, 2.2, 6 节同步.

## 方案取舍

- **加 code 字段, 不把 critic_reason 改成枚举**:
  - 一致或不一致时, critic_reason 是复核模型写的理由, 不能枚举.
  - 已有用例与审计助理对话都按中文原句读 critic_reason.
  - 因此 critic_reason 原样保留, 另加代码.
- **L1, L2 分成两个代码, 不带参数**: 文案自足, 不依赖判断上的 autonomy_level. 判断级降级 (7.4) 以后若改这个字段, 显示也不会错.
- **没做成的也给代码, 另加 detail**:
  - 英文界面的标题因此也能翻译.
  - 校验错误与异常信息本是系统原文 (校验器的错误为中文), 不翻译, 原样显示. 口径同呈递的失败原因.
  - 不加 detail 的话, 只能显示整句中文, 标题会重复一遍.
- **兼容**:
  - 旧检查点: LangGraph 读回 Pydantic 对象时按字段重建 (`cls(**字段)`), 缺的两项取缺省值.
  - Store: 判断以 JSON 存, model_validate 读回, 缺的两项同样为空. 不需迁移.
  - 新枚举在 models.py 里, 检查点白名单自动登记, 读回仍是枚举.
  - 前端没有代码时照原文显示.
- **lang 属性**: 照原文显示时保留原来的 lang="en". 模型写的理由是英文. 翻译后的文案不设 lang, 随界面语言.
