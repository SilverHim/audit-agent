## 讲解

### 业务背景

- Xero 演示数据集由两部分组成:
  - 快照 `data/external/xero/api/20261017-q1/`: 从 Xero 接口拉取.
  - 补造目录 `data/xero_demo/20261017-q1/`: R63 至 R68 生成, 包括画像, 计划, 合同, 证据, 更正分录, 财报等.
- 补造内容按快照的分录号, 流水号写成. Demo 每 28 天重置一次, 重新拉的快照编号会变. 要是新快照套上旧补造文件, 引用会悄悄错位. 所以载入与取数之前先核对两者是否配套 (设计第 9.2 节).
- 补造画像的 ID 带后缀 (CLIENT-XERO-3C1332BB-Q1), 与旧快照 20261017-mock 的载入器画像 CLIENT-XERO-3C1332BB 不同. 同一个库先后建两个项目时, 这样不会因 "同 ID 同版本, 内容不同" 报 VersionConflict (设计第 2.6 节).

### `Supplements` (adapters/xero_supplements.py)

- 字段: root (补造目录), snapshot (快照目录), dataset ("xero/<快照>"), allow_injected.
- `verify() -> manifest`, 按顺序:
  1. manifest.json 读不出, 或不是对象: 报 manifest.json.
  2. 带 injected 而没有 allow_injected: "测试副本 (injected=<场景>) 只能在 allow_injected 下载入".
  3. manifest 的 dataset 与 snapshot.name 都要等于数据集名, 否则报 manifest.json.
  4. 补造目录: 清单外的文件, 清单有而缺的文件, sha256 不符的文件, 都报文件名.
  5. 快照目录: 去掉 contacts.json 后, 要恰为 snapshot.files 且 sha256 相符; 报出时文件名前加 "快照".
  6. 有任何一项不符, 抛 SupplementMismatch("补造文件与快照不匹配: <文件名, ...>"), 不带文件内容.
- `client_profile(prefix)`:
  - 没有 client_profile.json 时为 None.
  - 不合模型时抛 SupplementMismatch("...: client_profile.json 不合模型"), 不带出校验器原文.
  - id 不以 prefix 开头时抛 SupplementMismatch, 消息含该前缀.
- `planning_presets()`: 没有 planning/ 时为 None; 缺文件或不合模型时抛 SupplementMismatch("...: planning/ 缺文件或不合模型").
- contacts.json 不记哈希, 也不读: 它含登录账号联系人, 测试副本与派生快照里它是过滤版 (设计第 9.2 节).

### `XeroDatasetLoader`

- 构造: `XeroDatasetLoader(root, planning, engine=None, evidence_store=None, *, supplements=None, allow_injected=False)`. 两个根目录都显式传入, 不靠层级推算.
- `supplement(dataset)`:
  - supplements 为空, 或 `{supplements}/<快照>` 不存在时, 返回 None. 这时一切照旧, xero/20261017-mock 的现有测试都不变.
  - 否则核对后返回 Supplements.
  - 快照目录不存在时仍抛 FileNotFoundError (接口 404).
- `load`: 名称先校验. 确认未载入之后, 在 build 里先核对, 再按快照建表. 已载入的项目直接返回, 不读补造目录与快照.
- `client_profile`: 先核对, 再由快照组织信息得出 CLIENT-XERO-{短 ID}, 前缀为它加 "-"; 有补造画像时取补造的. 先核对是为了在 organisation.json 被改坏时报不匹配, 不报数据集不存在.
- `planning_presets`: 有补造计划时取它, 否则取通用模板.
- 本条只做核对, 画像与计划. 合同, 服务完成记录, 证据文件等的载入是后续需求 (设计第 9.3 节第 5 项起).

### 接口

- POST /engagements:
  - client_profile 抛 FileNotFoundError 时 404 NOT_FOUND (原有).
  - 抛 ValueError 时 (SupplementMismatch, 画像校验失败) 422 INVALID_VALUE, 消息原样带出. 不调 EngagementStore.create.
- GET /datasets: 原有的 `except (OSError, ValueError)` 跳过画像读不了的数据集, 不匹配的补造随之跳过.

### 测试

- `tests/test_xero_supplements.py` (需要快照, 没有时整文件跳过; 篡改都在 tmp 副本上):
  - 补造画像与计划: 画像等于 client_profile.json (Q1 v1, Demo Company (AU) Pty Ltd, 25900043021); 3 个目标, 3 条风险; RISK-REV-OCC 的描述开头.
  - 回退: supplements 为空, 或 20261017-mock 没有补造目录时, 取快照画像 CLIENT-XERO-3C1332BB v1 与通用模板.
  - 篡改: client_profile.json 加 1 字节, 快照 journals.json 加 1 字节, 多一个 notes.txt, 补造与快照各少一个文件, 都报对应文件名; planning_presets 同样拒绝; 只改 contacts.json 照常.
  - manifest 的 dataset 不对, 或 manifest 不是合法 JSON.
  - 测试副本 injected=T1: 默认拒绝, allow_injected 下照常.
  - 画像 ID 为 CLIENT-XERO-3C1332BB 或 CLIENT-001 时拒绝, 消息含前缀. 用生成脚本按副本重写 manifest, 排除哈希的干扰.
  - load 先核对: 不匹配时不建表 (build_tables 未被调用).
  - 已载入: 两个目录都不存在也不报错.
  - 补造目录没有画像或计划时, 分别回退.
  - 快照 organisation.json 被改坏 (去掉组织 ID, 非法 JSON) 时报不匹配.
  - 补造画像或计划不合模型时, 消息只列文件名.
- `tests/test_datasets_api.py`: 补造画像的数据集出现在 GET /datasets (法定名称取补造的); 篡改后被跳过; POST /engagements 返回 422 INVALID_VALUE, 消息含 "补造文件与快照不匹配: client_profile.json", 项目数不变.
- `tests/test_persistence_postgres.py` (slow): 同一库先后以 mock 与 q1 各建两次项目, 两个画像并存, 不报 VersionConflict.
