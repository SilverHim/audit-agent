## 提示词正文

你接手 ELEC5620 多智能体审计支持系统 (澳洲法定审计, P0 承接 → P4 报告; 后端 FastAPI + LangGraph + PostgreSQL, 前端 React) 的开发, 目标是用户拍板的 "做到第三级": 在已有 17 条审计程序与第 0 级验收的基础上, 实现第 1-3 级的新程序与机制, 并把演示公司改为 Xero Demo Company (AU). 用户一人负责全部代码 (后端, 数据, 前端都由你做).

### 开工前按顺序读

1. `CLAUDE.md`: 架构, 命令, 约定.
2. `docs/云端开发/计划-第1至3级.md`: 现状, 已定的 15 项决定, 资料位置, 分阶段计划. **这是总纲.**
3. `docs/云端开发/开发流程.md` 与 `docs/云端开发/审核规则.md`: 每条需求怎么做, 怎么审, 怎么提交.
4. `docs/云端开发/需求清单.md`: R01-R61 的写法, 末尾 "待拍板" 里已定的决策.
5. `docs/云端开发/design/xero/设计稿-v2.md`: Xero 演示数据集设计 (补造清单, 各程序预期, 演示剧本, 注入错误测试, 补造文件存放与载入). 第 1-3 级需求的验收数值以它为准.

### 第一件事

做计划阶段 A (设计与数据收尾):
- A1 把决定 13 (分录扫描跳过时间类规则) 与决定 15 (回函如实写 48.53 应计利息, 加核对规则与一条小错报) 纳入设计稿, 重算受影响的数字与剧本计数.
- A3 重写需求清单: 以 `design/tier1-3/` 的草稿与 `critique.md` 的公共底座, 顺序为骨架, 先对照 main 上已经做了的 (计划第 0 节列了: A7 独立复核, 审计助理对话等), 已做的不重复; 验收数值按 Xero 设计稿重推 (Numbat 保留为回归, 原有精确断言不变); 数据库, 规则 SQL, 合成数据, 迁移, API 与前端的工作一并写成需求. 新编号 R62 起, 写进 `docs/云端开发/需求清单.md`.
- 写完后先把清单摘要 (阶段, 条数, 关键路径) 发给用户看, 再按阶段开工, 每条需求按 `开发流程.md` 走完再做下一条, 一直做到用户喊停.

### 必须遵守的规则

**数据**
- 原始数据一律不改 (`data/external/xero/` 的快照与导出, `data/demo/` 的 Numbat). 补造内容只放独立文件, 每份标明 "Synthetic – for demonstration only".
- 要验证错报识别时, 在测试里复制数据到临时目录再注入错误, 断言系统认定出预期错报; 测试结束核对原文件哈希不变.
- Xero 快照的联系人文件 (`contacts.json`, `raw/contacts.csv`) 与网页导出的 Posted By 列含用户本人姓名与邮箱. 用户决定不删, 但你写的任何文件, 测试数据, 回复都不得出现这两个原值; 生成脚本不得拷贝 contacts 或 Posted By.
- 旧快照 `20261017-mock` 是现有慢测试用的, 不要改; 演示用新快照 `20261017-q1`.

**依据与原文**
- 准则, 公司法段落号以 `docs/参考资料/` 原文为准 (用 pdftotext 核). 拿不到权威原文就停下来向用户要, 列出缺哪份, 为什么需要, 相关结论标 "暂缓"; 不要用二手转述加 "未核实" 继续推进.
- AASB 1060 本地只有摘要, 用到其段号前先向用户要正本.

**与用户沟通**
- 全程用中文, 包括思考过程. 交付物要求英文时 (如英文报告) 正文用英文.
- 需要用户拍板的事一律做成选择题 (AskUserQuestion): 推荐项放第一个并标 "(推荐)"; 先给你的意见和每个选项的正反两面; 用白话, 不用程序编号 (如 REV-02), 规则代号与英文字段名; 一次最多 4 问, 同类合并, 不相关的分轮问.
- 用户要先读长解释或图表才能决定时, 本轮只输出内容, 下一轮再弹选择题 (弹窗会挡住正文).
- 用户拿外部审核意见来时, 逐条核实判断成立与否, 不照单全收.
- 措辞: "以 AI 替代审计员, 一人完成审计" 是目标, 不是承诺; 不写 "即可完成", "没有审计员分担" 之类.

**写代码**
- Python 注释与 docstring 用中文半角标点 (`说明: 内容, 内容 (补充).`).
- 改 `src/backend/contracts/` 时同一次提交同步改 `docs/开发接口文档.md`.
- 报告与文档里章节引用写 "Section 2.3" 或 "第 2.3 节", 不用 § 符号.
- 子代理 (含审核子代理) 一律显式指定模型 opus; 纯机械任务可降低推理强度.
- 提交信息 `type: 中文标题`, 不加 `(scope)`, 不加 Claude 署名; 一条需求一次提交; 不直接推 main.

### 环境说明

- 默认测试不连库, 不调真实模型. 能起 Postgres 就跑连库测试, 起不了就跳过并在确认材料里注明.
- 真实大模型测试需要环境变量 `LLM_MODEL=gpt-6-luna` 与 `LLM_API_KEY`; 没配就跳过. 密钥绝不写进文件, 日志与回复.
- CUAD 合同集没放进仓库 (280 MB), 合同抽取评测需要时从 Zenodo 记录 4595826 下载到 `data/external/cuad/` (被忽略, 不入库), 署名 "Contract Understanding Atticus Dataset (CUAD) v1, The Atticus Project, CC BY 4.0".
- 云端连不到悉尼大学 GitHub, 与那边的同步由用户在本地做.
