## 审核结论

### 第 1 轮

第 1 轮通过, 意见 R88-01 至 R88-05 已改:

- R88-01 (minor, 覆盖守卫的 contract_id 取成了合同文件的登记 ID, contracts/{id}/history 实际 404 没调到): 改取合同 ID (`numbat_contracts()[0].id`, 即 CON-001); `responses()` 改为断言 200, 只有白名单 `NOT_OK_ROUTES` 例外 (gate: 图停在 await_events 不在闸门, 404 NOT_AT_GATE), 理由写在测试里.

- R88-03 (minor, 清单本身不受检验): 记录调用的替身 `Recording` (包住 HideOne) 核对 `test_registered_routes_and_tools_call_the_filter`: 调用过滤器的 GET 接口恰为 BLIND_ROUTES, 工具恰为 BLIND_TOOLS (PLAIN_TOOLS 都不调); 停在 await_events 时还没有报告, 测试内放一份引用该判断的合成报告草稿, get_report 才有判断可引. `test_skipped_routes_are_files_or_outside_engagements`: SKIPPED_ROUTES 每项须是现有 GET 路由, 不返回判断与留痕, 且只能是返回文件或不属于项目的接口. 变异核对见下.
- R88-04 (minor, BlindFilter 契约在第 5 节而各处引用第 4 节): 契约段与 Protocol 移到第 4 节 (存储与外部接口, contracts/ports.py), 第 1 节接口一览加一行 BlindFilter (接口在 contracts/ports.py, 实现在 services/blind.py, A 实现, A 与 C 调用).
- R88-05 (nit): `AgentDeps.blind` 改名为 `blind_filter` (与类名一致), 注释点明不是判断公共流程的盲测抽样 (JudgingSteps.blind 不动); 接口文档第 4, 6, 10 节同改.
- 改后 (在 R87 fix 之后的 fix 提交上) 默认测试 1787 个通过, 不可达 DATABASE_URL 同样全过, 连库 27 个通过, 2 个跳过; ruff, format, mypy, 前端 lint 与 typecheck 通过 (generate-client 后只有 review-tasks 接口说明一处变化).

## 改动摘要

- 契约:
  - `contracts/views.py`: `JudgmentView` (字段同 Judgment, 可隐藏的可空, 加 hidden_fields), `TrailEntryView` (payload 可空, 加 hidden_fields).
  - `contracts/ports.py`: `BlindFilter` Protocol, `judgment(eid, j) -> JudgmentView`, `trail(eid, entry) -> TrailEntryView`, 异步.
- `services/blind.py` (新): `PassThroughBlindFilter`, 原样转成视图.
- `agents/base.py`: `AgentDeps.blind_filter` (第 1 轮由 blind 改名), 缺省 PassThroughBlindFilter; `main.build_deps` 构造.
- 接口 (`api/routes/reviews.py`, `api/routes/reports.py`, `api/schemas.py`):
  - review-tasks 的 target, procedures/{pid} 的 judgments, judgments/{jid} 的 judgment 与 versions 改为 JudgmentView.
  - trail 列表与详情改为 TrailEntryView.
  - 复核档位, 金额, 仲裁选项按过滤后的视图计算 (第 1 轮 R88-02 改; 原来按存储的 Judgment, 被隐藏的草稿金额会经金额漏出).
- 对话工具 (`agents/concierge_chat/tools.py`): list_open_items, list_judgments, get_judgment, get_procedure, get_misstatements, get_report, search_trail 经 `deps.blind_filter` 输出; 判断摘要与留痕条目带 hidden_fields; 字段为空时如实给空.
- `orchestration/query.py`: gate 的说明写明以后材料含判断时须经过滤 (现在不含, 预留).
- 前端: `bun run generate-client` 更新 openapi.json 与 src/client; 类型 Judgment, TrailEntry 改为 JudgmentView, TrailEntryView, 可空字段 (结论, 置信度, 建议动作, 推理链, 分项) 为空时显示 "—", 复核档位在置信度为空时按 "须核对证据".
- `tests/fakes.py`: `api_client` 加 concierge 参数 (对话接口用).
- 接口文档第 1 节接口一览, 第 4 节 BlindFilter 契约, 第 6 节 AgentDeps.blind_filter, 第 10 节调用要求与各接口的响应类型, 对话工具一段注明 hidden_fields.
- 新增 `tests/test_blind_filter.py` 8 个 (第 1 轮加 3 个).

## 讲解

### 业务背景

- 规格书第 9.5 节: 审计师作出独立判断之前不得显示 AI 的结论 (盲判, 防止锚定).
- critique C8 指出, 盲判若只在前端或个别接口做会泄露: 复核呈递 (AC-8), 状态切片 (AC-11), 对话 (审计助理的工具可以读到判断). 建议做成后端统一接口, 对话必须调用.
- 本条只定接口与调用点, 空实现不隐藏任何东西; 哪些要隐藏, 怎样遮盖 (先答后看, 争议项不开盲判) 由降级段 MD-15 实现, 只换实现, 不改调用点.
- 第 7 批: 过滤返回视图层对象 (字段可空, 带 hidden_fields), 不往 Judgment 里填占位值, 存储的判断不变.

### 契约 (验收 4)

- JudgmentView 的字段与 Judgment 一一对应且同序, 只多 hidden_fields. 可隐藏 (可空) 的: conclusion, confidence, confidence_parts, reasoning_chain, counter_argument, proposed_action, misstatement_draft 与 critic_ 各字段 (critic_verdict 原有缺省 skipped, 视图里可空).
- TrailEntryView 同 TrailEntry, payload 可空 (隐藏模型调用的原始输入输出).
- BlindFilter 的两个方法为异步: 以后的判定要读 Store (如审计师是否已提交独立判断).
- 接口文档第 4 节写契约, 第 10 节写调用要求.

### 空实现下输出不变 (验收 1, 5)

- `test_views_mirror_store_models`: 视图字段 = 存储模型字段 + hidden_fields (同序). Judgment 或 TrailEntry 加字段时这里失败, 提醒同步.
- `test_pass_through_keeps_everything`: Numbat 真实 Agent 跑到 REV-02 待复核时的全部判断与留痕, 转成视图后除 hidden_fields: [] 外逐字段相同.
- test_api, test_concierge_chat_tools, test_concierge_chat_api 不改断言全过 (它们按键取值, 多出的 hidden_fields 不影响).
- Numbat 全流程与 R55 计数不变 (test_e2e_mock, test_flow 全过).

### 覆盖守卫 (验收 2)

- 场景: Numbat 用真实 Agent 与 mock 大模型跑进 P2, 按第 7 节提交复核 (REV-03 三条), 直到 J-REV-02-1-SI-2026-0612 待复核, 停在 await_events.
- 测试替身 `HideOne`: 该判断的结论, 推理链, 反方论证, 错报草稿与 critic_ 字段置空并列入 hidden_fields; 其模型调用留痕 (REV-02 对 SI-2026-0612 的 llm_call, 含重试) 的 payload 置空, hidden_fields 为 [payload].
- 核对的原文: fixture (tests/fixtures/llm/REV-02/SI-2026-0612.json) 的结论与反方论证各取前 150 字 (对话工具把结论截到 200 字). 它们只出现在该判断与其留痕 payload 的 raw 里.
- `test_hidden_judgment_and_trail_never_leak`:
  - 全部对话工具 (TOOLS 中 13 个, 参数取能查到该判断与留痕的) 的输出都不含这些原文.
  - 全部 GET 接口 (OpenAPI 中的全部 GET 路由, 路径参数取该判断, 该留痕, REV-02 等; 判断另取第 1 版) 的响应都不含. 其中对话接口: 先用同一依赖向审计助理 (规则模型) 问一句待办 (调 list_open_items), 再取对话历史. 证据原件 (返回原件文件, 合并上游后响应类为 EvidenceFile) 与大模型设置页两个接口不调, 理由写在测试里.
  - 合并上游后新增的 GET 接口 (data/summary, data/tables/{kind}, data/accounts/{code}/history, data/requests, data/schemas, contracts/{contract_id}/history) 一并调用; 路径参数补 kind 为 journal_entries, code 为 Numbat 试算表的第一个科目 1010, contract_id 为合同 ID CON-001 (第 1 轮改正, 原来误取合同文件的登记 ID). 这些接口不含判断与留痕, 须为 200 且不含原文.
  - 全部调到的接口须为 200, 只有白名单 NOT_OK_ROUTES 例外: gate 停在 await_events 不在闸门, 404 NOT_AT_GATE.
  - 对照: 空实现下, 输出判断原文或留痕明细的接口 (review-tasks, procedures/{pid}, judgments/{jid} 及第 1 版, trail, trail/{trail_id}) 与工具 (list_open_items, list_judgments, get_judgment, get_procedure) 的输出都含这些原文. 所以去掉其中任一处的过滤调用就会泄露, 断言失败, 消息列出接口或工具名.
- `test_hidden_fields_are_reported`: 判断详情与各版本的 hidden_fields 为替身所列, conclusion 为 null; 留痕详情 payload 为 null, hidden_fields 为 [payload]; get_judgment 工具给 hidden_fields, 推理链与结论为 null.
- get_misstatements, get_report, search_trail 只用判断与留痕作引用或摘要, 不输出结论与明细, 也经过滤 (需求范围所列); 它们在空实现下本来就不含原文, 去掉过滤由守卫二的记录替身抓到 (第 1 轮 R88-03).
- `test_review_task_amount_and_tier_follow_the_view` (第 1 轮 R88-02): 派生字段按视图算, 隐藏错报草稿后金额不再是草稿金额.

### 守卫二 (验收 3)

- `test_routes_and_tools_returning_judgments_are_registered`:
  - 扫 OpenAPI, 响应模型直接或间接引用 Judgment, JudgmentView, TrailEntry 或 TrailEntryView 的 GET 路由, 须恰为清单 BLIND_ROUTES (5 个). 合并上游后新 GET 接口的响应模型 (DataSummary, TablePage, CategoryVersion, DataRequest, TableSchema, ContractVersion, DocumentRef, Contract) 不含判断与留痕, 清单仍为 5 个.
  - 对话工具须恰好分在 BLIND_TOOLS (7 个) 与 PLAIN_TOOLS (6 个) 两张表里, 不重叠; 新增工具不登记即失败. 上游没加工具, 仍为 13 个.
  - 自测: 构造的 OpenAPI 多一个返回 JudgmentView 的路由时报出它.
- `test_registered_routes_and_tools_call_the_filter` (第 1 轮 R88-03): 记录调用的替身核对调用过滤器的接口恰为 BLIND_ROUTES, 工具恰为 BLIND_TOOLS.
- `test_skipped_routes_are_files_or_outside_engagements` (第 1 轮 R88-03): 跳过的接口须现有, 不返回判断与留痕, 且只能是文件或不属于项目的接口.

### 合并上游后的移植

- 冲突:
  - api/schemas.py import: 上游的 `AccountCategory` 与本条的 `JudgmentView` 都留.
  - main.py import: 上游的 `DataService` 与本条的 `PassThroughBlindFilter` 都留; build_deps 里 `data=PostgresDataStore(...)` 与 `blind=PassThroughBlindFilter()` 合并干净.
  - 接口文档对话工具一段: 取上游的 list_open_items 写法 (阶段决定 → 待补交的资料 → 复核任务), 加本条的 "判断经盲判过滤, 判断摘要与留痕条目带 hidden_fields".
  - 前端生成文件 (openapi.json, src/client 的 index.ts, types.gen.ts, react-query.gen.ts, sdk.gen.ts) 不手合: 取开发分支的版本后 `bun run generate-client` 重新生成.
- 语义核对:
  - AgentDeps 字段顺序: 上游的 `data: DataStore` 无缺省, 在 review_llm 之前; 本条的 `blind` 有缺省, 在 features 之后, 合法; 对话测试替身不用改.
  - 对话工具: 上游只在 list_open_items 加了补交请求项 (不含判断), 本条对判断的过滤仍在.
  - 覆盖守卫按新路由补路径参数 (见上), 不补会 KeyError.
  - Numbat 主流程现经 p1_await_data (假数据存储缺省已就绪), 覆盖守卫的场景不用改.

### 变异核对 (本地做, 都被测试抓到, 消息含接口或工具名)

- 去掉 review-tasks, procedures/{pid}, judgments/{jid} 的判断与各版本, trail 列表, trail 详情的过滤 (换成空实现).
- 去掉 list_open_items, list_judgments, get_judgment, get_procedure 的过滤.
- 第 1 轮改后 (只跑 test_blind_filter, 各 1 例失败): review-tasks 金额按存储的判断算; get_misstatements, search_trail 换成空实现 (不经 deps.blind_filter); 测试清单把 get_judgment 挪进 PLAIN_TOOLS; SKIPPED_ROUTES 多登记 misstatements 接口.
