## 方案取舍

- ManualTaskView 加 evidence_types: 各文件作证据时的指针种类, 取判断引擎的 DOCUMENT_EVIDENCE. EvidencePointer.type 必填, 前端据此交真实的种类, 不填等后端改写的占位值, 也不另抄一份映射; 后端写入时照旧按文件登记改写 type 与 reliability (R92 修正), 以后端为准. 列出的文件都有种类, 前端缺了即报错, 不兜底 (第 1 轮修正).
- 复核队列在前端按 kind 过滤. kind 参数只能给一个值, kind=normal 会漏掉 failed, dispute, unattributed 三类.
- 上传后的文件要等 A3 分类成可作证据的类型, 才会出现在可选文件里. 详情页轮询文件登记, 只在还有 received 状态时轮询, 每刷新一次就重取人工队列. 分成了不能作证据的类型时, 写明类型并提示到数据管理页改. 需求写的 "data-api.ts 的 useUploadDocuments" 在现有代码里没有, 上传 hook 放在 manual-api.ts.
- 结果模型名已不在登记里时, result_schema 为空; 提交时后端会拒 (R92-03).
- 前端组件测试的做法: 本机没有 DOM 测试库 (happy-dom, testing-library), 也不能往 node_modules 装. 因此分两部分:
  - 表单换算用 bun 单测;
  - 渲染, 填写, 提交用 Playwright 在草稿副本的 vite dev 上跑, 接口全部用 page.route 模拟.
  脚本与截图都在 scratchpad, 不入库 (同 R300, R302).
- 不在本条: 对话页 (index.tsx) 与待决页 (decisions.tsx) 仍按 pending 列出 manual 任务, 点开是通用决定卡; 协调者另立一条需求. 上传 hook 放在 manual-api.ts, 协调者同意.
