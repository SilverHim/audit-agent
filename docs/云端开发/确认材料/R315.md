# R315 确认材料: 审计计划页与计划审批卡片 (前端)

来由: Issue #47 验收 3, 6. 规模 M, 档位 high, 前置 R314, R206 (都在审核中, 本条从 R316 ac4ef7d 之上接着做). 甲留下的 WIP (f220296) 与本条的改动合成一个提交. 不改接口, 不需 generate-client.

## 改动摘要

- `routes/engagements/$eid/plan.tsx` (新): 计划状态与修订号, 修订历史 (状态, 驳回与信息不足的理由, 批准人与时间), 总体策略与各段 (英文原文, 段名本地化), 重要性, 特别风险, 时间表, 项目质量复核建议与专家评估 (批准后另列批准时确认的两项), 程序表. 停在 PLN-15 且后台不在执行时出决定卡片; 计划过期时顶部提示可以退回重拟. 后台执行起止或闸门变化时重新取计划.
- `lib/plan.ts` (新, 纯函数): 程序表的行 (接上审计目标与总览的程序行), 修订历史, 当前计划, 方法与范围的标签, PLN-15 决定被拒的文字.
- `components/gate-form.tsx`: PLN-15 批准时的三项确认 (是否需要项目质量复核, 默认取 AI 建议; 依据, 必填, 默认取 AI 建议的依据; 不需要审计师的专家, 不勾时提示只作记录), 提交体带 plan_confirmation; 材料面板段名本地化, 加 "打开审计计划页" 链接; 提交出错按错误码显示文案. 工作区当前事项用的是同一个 GateDecisionCard, `index.tsx` 不用改.
- `components/engagement-shell.tsx`: 导航项 "审计计划", 只在项目功能集含 planning 时出现, 放在 "审计程序" 之前, 停在 PLN-15 时带待办标记.
- `lib/timeline.ts`: GATES 加 PLN-15. `lib/errors.ts`: 导出 apiDetail. `locales/zh.ts`, `en.ts`: planPage 一组文案与 VERSION_MISMATCH. `routeTree.gen.ts` 由 vite build 的路由插件生成.
- 后端 `agents/concierge_chat/rule_model.py`: GATES 话术加 PLN-15; `tests/test_concierge_chat_service.py` 按闸门参数化 (zh, en).

## 审核结论

第 1 轮普审通过 (5 minor, 4 nit). 修正提交 (甲, 接在本条之后):

- R315-01: 决定卡片的 key 用 `lib/engagement.decisionCardKey` (闸门, 呈报对象, 版本), 工作区, 计划页, 表单视图与签字卡片四处共用; 退回后 PLAN-2 v1 的卡片重新挂载, 确认的初值按新修订取.

- R315-03: planning 关闭的项目直接打开计划页, 显示 "本项目未启用总体审计计划"; "尚未起草" 只用于功能打开而还没有计划时.
- R315-04: 计划叙述抽成 `PlanNarrative` (gate-form.tsx 导出), 计划页与闸门材料共用.
- R315-05: 程序表的程序名下可展开 "性质、时间与范围", 取当前计划 procedure_notes 中该程序的说明 (英文原文).
