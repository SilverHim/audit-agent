## 方案取舍

- **按程序分流, 不按对象键**: 需求原文是 "只有这五个程序走真实模型". 意外的对象也交真实模型, 例如 DOC-06 把符号抽反后 CSH-02 还会判断 BA-090, 不会落到没有固定输出的 mock. 硬性另查 15 个对象都真的交给了模型 (unrouted), 防止合同已有, DOC-04 根本没调模型.
- **"结果或 failed 任务" 同 R311 的口径**: failed 后重跑一次仍没结果, 判硬性不过; hard 段的数值本来就要求有结果.
  - 带规则例外的对象 (ORC1026, BA-091) 失败时转 unattributed, 不能重跑, 同样记缺结果.
- **重跑放进测试台**: 下游要看到重跑后的结果 (REV-03 重跑完才跑 REV-02), 所以只能在分层执行中间做. 其余用例不传 rerun, 行为不变.
- **判断按 (程序, 对象) 取最近一次**: 重跑的判断 ID 是 -2-. 只有 CSH-02 断言 J-CSH-02-1-BA-091, 因为 BA-091 带 D04, 不会被重跑.
- **DOC-06 按银行账户 (fixture_key) 取**: 预期里写 BA-090, 不写 C-BA-090, 与分流和调用次数同一个键.
- **A7 仍读运行副本**: Xero 没有 GEN-09 的固定输出. 真实模型若对 BA-091 建议 accept, 会触发 A7, 记 "独立复核没有完成", 不计入检查.
- **预算 45** = 15 个对象 x 3 次尝试. 重跑也在这 45 次之内, 超限即失败.
- **离线自测注入错的余额日, 不注入错的符号**: 符号错了, CSH-02 会判断 BA-090, 而它的失败一路会撞上下面的问题.
