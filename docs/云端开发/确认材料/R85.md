## 讲解

### 业务背景

- 原来重放 (stored_outputs) 按 `AGENT_FIELDS[writer]` 取字段: 执行它的 Agent 能写的字段都取.
- critique C11 与 verify G3, G4, G5 指出, 后续各组加字段后会出错:
  - A6 加带 run_id 的单对象 going_concern 后会被当成列表取回, 且波及全部 A6 程序的重放.
  - AP-3, AP-11 的重放会带进别的程序的产出.
  - A8 的错报没有 run_id.
- 取 critique 推荐: 程序声明自己写的字段, 每个字段登记取回方式.
- 单对象取 Store 最新版本, 沿用现有评分卡的回退一致性规则. 没采 verify G3 "取回 v1": 闸门材料须与 Store 当前版本一致, 否则回退后决定绑定的版本对不上.

- 与现有 Agent 片段的键逐一对过: 合并校验 (run_agent 的 check_patch) 现在查声明. 声明少了哪个字段, 该程序的执行就会以 merge_rejected 失败, Numbat 全流程 (R55, R27, 连库) 的断言就不成立; 这些测试全过.
- 本次执行的任务 (含 A1 代写的 failed 任务) 照旧总按 run_id 取回, 不看声明.

### 取回方式登记 (验收 2)

- `FIELD_REPLAY`:

| 方式 | 字段 | 取法 |
|---|---|---|
| by_run | exceptions, judgments, review_tasks | 该 run_id 下各 ID 的最新版本 |
| latest_all | confirmations, audit_objectives, risk_register, report_versions, misstatements | 全部最新版本 |
| documents | documents | FinancialDataStore.documents 中本程序 document_types 所列类型的文件 |
| singleton | acceptance_scorecard, analytics, materiality_candidates, uncorrected_schedule | 固定 ID 的最新版本, 并取回本程序之后的执行 (同现状) |
| by_procedure | (新字段用) | 各 ID 最新版本中 run_id 属于本程序的, 并取回之后的执行 |

- misstatements 现由 DecisionSubmit 写, 先为之后的 A8 登记.
- singleton 的模型带 run_id 时, 取到的最新版本的 run_id 须属于本程序 (查 Store 中本程序的执行), 否则作节点错误. 现有 4 个 singleton 模型都不带 run_id.
- "取回之后的执行" 原来按 "片段中有单对象字段" 判断, 现在按 "片段中有 singleton 或 by_procedure 字段" (LATER_RUNS).
- 补齐例外只在声明了 exceptions 时做 (原来按 Agent 写入范围); 补齐任务与执行记录照旧.

### 重放只取本程序的文件类型 (第 9 批 Q4 选 b)

- 问题: 改造前后 documents 都取 `FinancialDataStore.documents(eid)` 的全部文件. 合并上游后其中多了审计师上传的文件 (A3 分类后为发票, 会议纪要等) 与导入账表的原件 (type other, media_type text/csv). 第一次执行时 DOC-04 只交回合同类, DOC-06 与 CSH-04 只交回回函, 重放却会把这些文件也带进状态 documents, 与第一次执行不一致.
- 做法: 模板加 `document_types`, 写在 YAML 里 (与 outputs 同处声明):
  - DOC-04 [contract]: 第一次执行取 `documents(eid, contract)`.
  - DOC-06 [confirmation]: 第一次执行取状态中函证的回函, 都是 CSH-04 以 confirmation 存档的.
  - CSH-04 [confirmation]: 存档的回函.
- 用到这个声明的两处:
  - 重放: `stored_outputs` 对 documents 只取 document_types 所列类型的文件.
  - 启动校验: documents 与 document_types 须成对出现, 声明写漏在启动时报出.
- 合并时不查文件类型 (第 1 轮 R85-02 裁定): CSH-04 存档按哈希去重 (EvidenceStore.save), 若审计师先上传了同内容的回函而其类型不是 confirmation (分类失败仍为 other, 或按补交请求定为别的类型), 存档取回的就是那份登记. 合并时查类型会让 CSH-04 失败, rerun 也过不去, 是本条带来的回退. 去掉后在线行为与改造前一致.
- 只到类型粒度, 与第一次执行的差异 (接受的残差, 接口文档第 3 节写明):
  - DOC-04: 合同类上传文件第一次执行也会被取到 (同类), 没有差异.
  - CSH-04 去重取回审计师上传的别类文件时, 第一次执行交回它, 重放不带回.
  - 审计师上传并由 A3 分类为 confirmation 的回函副本 (只记抽取版本, 不关联函证) 不在 CSH-04, DOC-06 的在线片段里, 重放会按类型带回状态 documents.
  - 下游 (DOC-06, A6 的 CSH-02) 都按函证的 reply_document_id 找回函, 两种差异都不影响结果. 要逐份一致可改为只取函证 reply_document_id 引用的文件, 本条不做.
- 测试 `test_a3_a5_documents_replay_only_declared_types` (DOC-04, DOC-06, CSH-04 三例): 财务存储登记合同 CON-001.pdf, 回函 BA-01-reply.pdf (bank_direct), 审计师上传后分类为发票的 INV-77.pdf (classified), 导入账表的原件 gl.csv (other, text/csv). DOC-04 只取回合同, DOC-06 与 CSH-04 只取回回函, 片段字段恰为 outputs 加 procedure_runs.

### 已知问题 (第 1 轮 R85-04, 改造前即如此, 本条不改)
