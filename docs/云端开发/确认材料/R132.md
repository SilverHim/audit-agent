## 方案取舍

- **名称规范化与区域设置无关:**
  - 先做 NFKD 分解并去掉附加符 (两侧用同一组码位区间), 同 R136 的 node_name_part: "Café" 同 "Cafe" (第 1 轮审核 05).
  - 之后只认 ASCII 字母与数字: 转小写用 translate, 正则按 "C" 规则. 中文等非拉丁字母与 ß 当分隔符.
  - 两套数据的分录说明, 单据号, 客户与流水说明里都没有非 ASCII 字符 (实测 0 行), 结果不变.
- **前缀与后缀的匹配:**
  - 两者都取匹配的最长一个. 前缀以字母或数字结尾时须是整词: "payment to" 不吃掉 "Payment Tools".
  - 没有可比的名称本身时返回 NULL (Python 为 None), 不与任何名称相等: 裁定写的是空串 (全是非拉丁字符, 只剩前缀); 只剩公司后缀 ("王小明 Pty Ltd", "Limited") 同样没有名称本身, 也按 NULL. 原来只剩后缀时保留后缀, 两个非拉丁名的公司会都得 "pty" 而配上.
- **迁移编号:** 开发分支已有 0016 (关系图, R136) 与 0017 (R215 的签字前提产出), 本条为 0018 (down_revision 0017).
- **作废对标记的位置:**
  - 标记是 SQL 注释: YAML 块标量里写不了 YAML 注释, 注释里也不用冒号 (text() 会当绑定参数).
  - 止标记放在 voided 的括号内. CSH-02 其后接 `)`, GEN-05 其后接 `), hits AS (`, 这样标记之间的文字才能相同.
  - 守卫: 凡写了 `reversal AS (` 的规则都须带标记, 且标记之间的文字相同.
- **新规则的门槛:** 四条都只出金额超过明显微小的例外 (设计稿第 5.3 节的通用约定). 原有规则不加.
- **R10:**
  - 命中行取 receivables 分类的贷方行; "本期发票" 按开票日在期内判断.
  - matched_invoices 按 (开票日, ID) 排序: 验收里五张发票按发票号列出, 实际顺序是 SI-1d1b (ORC1008) 在前.
- **R11:**
  - 名称取凭证 ID 最小一行的 source_doc. "号码" 取凭证号的末段数字; 距离并列时取凭证号字节序小的.
  - 一笔重记被几个原凭证选中时只出一条.
- **R12:**
  - "同一客户" 按 customer 原文比较, 不规范化. 有没有记录看 delivery_notes 里有没有该发票的行.
  - 只对挂了分录的发票出例外, 没挂分录的不出也不报错 (第 1 轮审核 03 的裁定, 去掉原来指向发票的退回).
  - 成组条件只写一处: 以 paired_invoices 非空为准 (审核 02).
  - 本期没有发票也记 not_executable.
- **删 XJ-430 的用例:** 在已建好的 Xero 项目里临时删去 3 行, 用完原样写回, 不另建项目.
- **设计稿的计数:** 第 5.3 节原写 "Numbat 同日同额组有 56 组", 按 (客户, 开票日, 金额) 实测为 55 组, 已改 (审核 09).
