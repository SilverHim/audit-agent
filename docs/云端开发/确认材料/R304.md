# R304 确认材料: 文件登记变动只让读该类文件的程序过期

## 改动摘要

- 契约:
  - `DataChange.document_types`: documents 变动时, 登记变了的文件的类型. 其余变动与旧数据为空.
  - `ProcedureTemplate.document_reads`: 程序读哪几类文件的登记.
  - `DataStore.bump_version` 加关键字参数 `document_types`.
- 存储: data_changes 加列 document_types (JSONB, 可空), 迁移 0020, down_revision 0019. `record_changes` 只在 documents 那一行写类型, 按 DocumentType 顺序去重.
- 补登记 (`DataService.save_details`): 记 documents 时带这一批各文件的类型.
- 过期判断 (`staleness.reads_change`):
  - documents 变动带了类型时, 只有 document_reads 含其中某类的程序算读到.
  - 没带类型的照旧按 reads 含 documents 判.
- 程序 YAML: REV-03 与 REV-02 读 [contract], CSH-02 读 [confirmation].
- 程序库加载校验 (`document_read_problems`): reads 含 documents 与 document_reads 须同时写.
- 接口文档第 2.8, 3, 4, 8.1, 9, 10 节已同步.

## 方案取舍

- **类型记在变动上**: data_changes 原主键 (项目, 版本, 种类) 不动, 只加一列数组. 一次补登记的几类文件都记在一行里. 迁移只加一列, 可重复执行.
- **新字段, 不复用 document_types**: document_types 是产出侧, 指本程序交回的文件, 只管重放. document_reads 是读取侧, 只管过期. 两者各管各的, 例如:
  - DOC-04 交回合同文件而不读登记.
  - REV-03 读合同登记而不交回文件.
  - CSH-04 交回回函而不读登记.
  - 若复用, CSH-04 也会因回函登记过期.
- **DOC-04, DOC-06 不读登记** (按 10-20 改正后的验收 1):
  - 同 R90 第 8.1 节: 它们抽文件内容, A6 重跑时登记取自存储.
  - DOC-04 是 P1, 在 FIN-01 处不能重跑. 若算它过期, 依赖它的 REV-03 与 REV-02 重跑后仍会一直过期.
- **验收 2 取 "必须声明"**: reads 含 documents 而没写 document_reads 时, 程序库加载即报错. 反过来, 写了 document_reads 而 reads 没有 documents 也报错. 不留 "按任何文件变动都过期" 的兜底.
- **旧数据**: 迁移之前的 documents 变动没有类型, 数据集载入记的全部各类里的 documents 也没有. 这两种照旧按 reads 含 documents 判, 让三条程序都过期 (验收 3).

## 验收对照

1. 带类型的变动:
   - 参数化用例: financial_statements 没有程序过期; contract 让 REV-03 与 REV-02 过期; confirmation 让 CSH-02 过期; 两类都有时三条都过期; 其他类型没有程序过期.
   - Numbat 停在 FIN-01 时 (经总览):
     - 新登记一份待审财报并补登记: 没有程序过期.
     - 补登记回函: 只有 CSH-02 过期.
     - 补登记合同: REV-03 与 REV-02 过期. 这一例是原 R90 用例, 期望由三条改为两条.
2. 现有程序都已声明 (守卫用例). 程序库副本里去掉 REV-03 的声明, 加载即报错.
3. 不带类型的旧变动: R274 的 documents 一行照旧是 REV-03, REV-02, CSH-02. 连库: 迁移降级时写的旧行, 升级后读回为空.
4. R274 与 R90 用例逐条不变, 只改了以下三处:
   - 补登记的数据变动断言里加上类型 (一处假存储, 一处连库).
   - 一处 monkeypatch 的 bump_version 签名加 `**_`.
   - 上述合同例的期望 (CSH-02 不再过期).
   - R287 的用例不在本分支. Numbat 回归见下.
