## 讲解

- **为什么不核对哈希.** 概览在处理中每 3 秒轮询一次. 完整核对要读约 90 个补造文件和快照算哈希, 太慢. 所以 available 只看目录在不在. 发起导入时 DataService.demo_import 照常完整核对, 篡改报 INVALID_VALUE (R269).
- **suggested 的判断.**
  - 闸门用 R291 的 gate_now, 等数据用 runner.awaiting_data (confirm_ready 与总览用的同一判断). 都是现成的.
  - 只有 available 时才读检查点. Numbat 与新客户的概览 (含连库测试里 GraphRunner(None, ...) 构造的服务) 不碰检查点.
  - 自己跑了 -m slow, 全过.
- **为什么 stages_done 读全部留痕, last 用 last_of.** 已导入阶段要看每一条 demo_import; 最近一次结果按裁定用 last_of. 两者都只在 available 时读.
- **补登记表单只提交改了的项.**
  - 后端的 None 是 "不改", 本版不支持清空文件日期, 所以清空日期视为没改.
  - 关联对象用逗号 (含中文逗号) 或换行分隔.
  - 都没改时前端提示至少改一项, 不发请求.
  - INVALID_VALUE 附后端的说明 (如关联对象重复).

## 验收

1. 接口:
   - 带补造目录的 Xero 项目 202, 后台作业期间 summary.processing 不为 0 (test_import_from_the_data_page_follows_the_flow).
   - 其余数据集与没有数据集 422 INVALID_VALUE, 阶段为 manual 422, 锁定 423 (test_rejected_requests_and_unavailable_summary, 5 例); 忙 409 (test_busy_is_409).
   - summary.demo.available 只对带补造目录的数据集为真; stages_done 按已完成阶段 (同上两例与 test_summary_follows_where_the_flow_stops).
   - 作业中途出错 (第 10 份上传抛错) 记 status failed 的留痕, 错误类别为 OSError, 不含错误文本; 概览 last 读得到, stages_done 不含这一阶段; 再执行后与一次做完相同 (test_demo_import 的 test_failure_midway_then_again_ends_like_one_run).
   - 作业期间 processing 为 2 (两份承接文件). 用例让作业先停住再读概览, 不靠时序.
2. 前端:
   - 按钮只在 available 时显示, 阶段按 suggested, 为空时不可点并说明; 上次结果的文字含失败的一次 (demo-import.test.ts).
   - 补登记表单提交 PUT details, 只带改了的项; 校验失败显示错误码文案 (document-details.test.ts).
   - bun run lint, typecheck, test, build 通过.
3. Numbat 项目的概览 available 为假 (前端不显示卡片); 现有前端与 API 测试不变.
4. 没有数据集的项目 (新客户): available 为假, 请求 422 INVALID_VALUE.
