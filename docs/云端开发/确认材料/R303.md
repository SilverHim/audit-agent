# R303 确认材料: 对话页与待决页不再按通用决定卡列出人工任务

来由: R94 只让复核队列页过滤掉 manual 任务. 对话页与待决页仍把待决的 manual 任务当通用决定卡列出, 提交的不是 manual_result, 会被后端拒绝. 规模 S, 只改前端, 免审.

## 改动摘要

- `lib/review.ts`: 新纯函数 `splitManual(views)`, 把待决任务分成 (复核任务, 人工任务), 各自保持原顺序. 复核队列页原来的内联过滤改用它, 三处口径相同.
- 对话页 (`engagements/$eid/index.tsx`):
  - 人工任务成为一种事项 (kind manual), 排在复核任务之后.
  - 显示一张入口卡: 程序编号与名称, 要做什么, "稍后处理", "去执行" (到 `/engagements/$eid/manual/$taskId`). 不出决定卡.
  - 页头 "表单视图" 对人工任务也指向人工程序页.
- 待决页 (`decisions.tsx`):
  - 复核决定一组只列复核任务.
  - 人工任务另起一组 "人工程序", 每行 "去执行" 到人工程序页. 金额, 建议处理, 复核档位为 "—".
  - 筛选的计数含这一组, 与侧栏 "待决定" 的数字一致.
- 文案: 中英 `workspace.manualIntro`, `workspace.performManual`, `decisionsPage.manual`, `decisionsPage.perform`.
- 测试: `tests/review-rank.test.ts` 加 splitManual 一例 (人工任务夹在复核任务中间, 两组各自保持原顺序).

## 方案取舍

- 保留入口, 不直接不列:
  - 侧栏 "待决定" 的数字与对话页页头的待决数都来自总览的 pending_tasks, 其中含人工任务. 不列的话, 数字对不上页面.
  - 主图停在人工程序等人时, 对话页会显示 "没有待处理的事项", 审计师找不到该做什么.
  - 入口只是一张卡或一行链接, 改动小.
- 对话页的人工任务排在复核任务之后, 可以 "稍后处理" (同其他事项, 记作该任务的稍后处理). 审计师先处理复核, 不被人工任务卡住.
- 不改后端与接口: 待决任务的列表本来就带 kind 与 manual_request.

## 验收对照

1. 有待决 manual 任务时, 两页都没有可提交通用决定的卡片. Playwright 实看: 对话页 focus 到人工任务时决定按钮数为 0, 入口卡的 "去执行" 点开即到该任务的人工程序页, 页上有任务的说明; 待决页人工程序一组的链接指向人工程序页.
2. 普通复核任务不变: 对话页 focus 到第一条复核任务仍是决定卡 (决定按钮 1 个); 待决页 4 条复核决定的 "处理" 仍指向对话页.
3. 前端 lint (biome), typecheck (tsc -b), bun test (94 pass), build 通过.

## 审核结论

免审 (只改前端, 规模 S), 由协调者核对.
