# R302 确认材料: 证据弹窗显示客户画像字段

来由: R128 第 1 轮审核意见 07 (10-20 协调者). R128 起判断可引用客户画像 (source_type client_profile, locator 为画像顶层字段名). 前端对这类指针只显示 "画像 ID · 字段", 点开是 "无法打开". GEN-03, GEN-01 (R139, R141) 起会引用申报的关联方清单, 审计师要能看到所引内容. 另并入 R128 第 2 轮审核意见 08: 争议呈递证据列表的 React key 不含 locator.

规模 S, 档位 high. 协调者指示直接做, 从开发分支 f3e9823 开; 提交前变基到开发分支头 279d46a (其间只有测试, 数据与文档的改动, 前后端源码相同), 无冲突. 做下来没有遇到要拍板的点.

## 改动摘要

- 新 `src/frontend/src/lib/profile-evidence.ts` (纯函数):
  - `adoptedProfile(view)`: GET /engagements/{eid}/client-profile 的 history 中, 版本等于 engagement_profile_version (本项目采用的版本) 的那一版. 不取 profile (最新版).
  - `profileEvidence(view, pointer, words)` 返回四种结果之一:
    - shown: 采用版本号, 以及所引字段的内容;
    - not_adopted: history 里没有采用的那一版;
    - other_profile: 指针的 source_id 不是本项目客户的画像;
    - unknown_field: locator 不是画像自身的字段 (原型上的键如 toString 不算).
  - `profileField(key, value, words)` 把字段整理成四种:
    - undeclared: null, 空白串, 空列表, 空对象;
    - text: 标量;
    - rows: 列表按行, 每行是标量或一组键值;
    - pairs: 对象按键值.
  - 值的显示:
    - 名称以 _cents 结尾的为 AUD (formatAud);
    - 名称中有 pct 一节的为百分比 (formatPct);
    - 布尔为是, 否;
    - 嵌套的列表用分号连接, 嵌套的对象写成 "键: 值". 以数据为键的字典 (如各年收费占比 dependency_pct_by_year) 沿用字段名的单位.
  - `humanize` 从 evidence-link.tsx 挪到这里, 证据弹窗的数据行与画像字段共用.
- `src/frontend/src/components/evidence-link.tsx`: EvidenceBody 加 client_profile 分支 ProfileBody.
  - 取数用生成的 `engagementsGetClientProfileOptions`, 即现有接口.
  - 显示 "管理层申报" 标签, "客户画像第 n 版 (本项目采用)", 字段内容 (列表每行一个框, 对象为两列键值), 以及一句 "管理层申报的资料, 未经审计组核实".
  - 字段为空时显示 "未申报". 显示不了时各写原因.
  - 其他来源 (文件, 准则, 留痕, 数据行) 的分支没动.
- `src/frontend/src/lib/presentation.ts`: 新 `pointerKey(pointer)` = `source_type:source_id:locator:page`.
  - PointerList (evidence-link.tsx) 与争议呈递的证据列表 (concierge.tsx) 都改用它.
  - 后者原为 `source_type:source_id:page`. R128 起同一画像的不同字段在后端各算一项, 原 key 会重复 (审核意见 08).
- 文案 (`locales/en.ts`, `zh.ts`): `evidence.profile` 下的 declared, version, undeclared, note 与三种原因. 布尔沿用 clientPage 的 yes, no.
- 测试: 新 `src/frontend/tests/profile-evidence.test.ts`, 10 例.
- 后端, 接口文档与生成的客户端不改. 不新增接口, 理由见讲解.

## 讲解

- **为什么用现有接口.** GET /engagements/{eid}/client-profile 已经给出 history (第 1 版到最新版) 与 engagement_profile_version (Engagement.client_profile_version, 本项目采用的版本). 前端从中挑出采用的那一版即可, 不需要取单字段的新接口. 一次请求带回全部版本, 但画像只有几 KB; 同一弹窗再打开时先用 react-query 的缓存. 画像改了 (invalidateEngagement 按 eid 失效) 会重新取.
- **"本项目采用的版本" 取 Engagement.client_profile_version.** GEN-09 (R128) 读的是状态中的 client_profile_version. 两者在 ACC-01 更新资料时一起改 (decisions.update_client_profile), 恢复时以 Engagement 为准对齐到检查点 (recovery). 接口给的正是前者.
- **字段名不翻译.** 弹窗标题沿用原来的 "画像 ID · 字段" (pointerLabel 没改), 键值的键用 humanize 后的英文字段名. 这与数据行弹窗 (RecordTable) 一致: 画像的扩展字段目前也没有中文标签.
- **"管理层申报" 写在哪里.** 标签放在版本旁边, 底部另有一句说明. 画像是询问所得, 未经核实 (ASA 550 第 13 段; R128 把它的可靠性定为 internal_copy). 审计师从弹窗就能看出这不是外部证据.
- **0 不是未申报.** 只有 null, 空白串, 空列表与空对象算未申报. 审批限额为 0, 是否上市为否 (false) 都照常显示.

## 验收

1. client_profile 指针点开后显示所引字段的内容与画像版本, 字段为空时显示 "未申报":
   - `profile-evidence.test.ts`: "字段为空即未申报" (6 种空值), 标量, 列表 (标量与对象), 对象 (含嵌套与以数据为键的字典) 的显示.
   - 界面核对见下.
2. 显示的是本项目采用的版本:
   - "画像改出新版本后, 采用旧版本的项目照旧显示旧版本的内容": history 有第 1 版 (没申报关联方) 与第 2 版 (申报一个). 采用第 1 版时为未申报, 采用第 2 版时为一行.
   - 界面核对: 同一客户的项目 A 采用第 1 版, B 更新资料后采用第 2 版, 两边的弹窗各显示自己的那一版.
3. 其他指针来源的弹窗不变:
   - EvidenceBody 其余分支没改. 界面核对时同一列表里留痕指针的弹窗照旧显示摘要与明细.
   - 前端 lint, typecheck, test, build 通过 (数字见环境限制).
   - Playwright 中英文各 3 张截图, 见下.
- 并入的 R128-08: "证据列表的 key" 两例. 同一画像的不同字段 key 不同; 文件按页与 locator 分开, 没有页时页为空.
