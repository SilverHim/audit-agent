# R90 确认材料: 上传文件的补登记 (文件日期, 可靠性与关联对象, 按对象取文件)

来由: DA-12. 文件改由审计师上传, A3 只认类型; 可靠性先按类型取缺省 (多为副本), 登记里没有文件日期与关联对象. 本条让审计师补登记这三项, 并能按关联对象取文件. 演示数据导入 (R269) 按补造清单代填, 数据管理页的手工补登记在 R270.

## 审核结论

规模 M, 档位 high. 开工前交了方案 (scratchpad/plan-bing-R90.md), 裁定 (主代理):

1. 还在导入确认单里, 未确认的文件 (staged) 不能补登记.
   - 理由: 确认导入时会按确认单改类型与可靠性, 先补的会被盖掉.
   - 确认时没勾选而未导入的 (not_imported) 同样不能补.
2. 补登记过可靠性的文件, 之后改类型时保留可靠性; 只有可靠性从没补登记过的, 才取新类型的缺省.
   - "补登记过" 用现有记录判断: extraction_versions 里有 target_type document, 且 field 含 reliability 的版本. 不加新字段.

开工后补的两处裁定 (协调者, 10-19, 记入需求清单第 13 批):

   - R274 合入后, 过期按程序 reads 与数据变动判断. DataInput 加 documents (文件登记), 补登记记 bump_version(eid, DataInput.documents).

## 讲解

- 补登记即 "文件登记的一次修改", 写法照合同与回函的抽取结果修改:
  - 同一把项目锁, 同一个事务 (登记, 版本, 数据版本).
  - 先写库后写留痕, 写不成的补写.
  - 修改前的一版由 A3 补记; 重试幂等.
- 版本内容: data 为 {type, reliability, document_date, related_ids}. field 只写这一次改了的字段. 给了而与当前相同的项不算改动. 三项都没改时报 INVALID_VALUE (重试除外).
- 关联对象:
  - 各 ID 去首尾空白后存, 有空串或重复即拒绝.
  - 不校验对象是否存在: 可以是分录号, 银行流水, ACN, 客户编号等, 按 ID 原样匹配.
- 过期, 读 documents 的程序怎么定 (裁定 5 的判定依据, 逐处 grep 过 reliability 的读者):
  - 证据可靠性取自文件登记的只有一处: `judgment_engine.document_pointer`. OutputValidator 解析 document 指针时, 按文件登记改写 type 与 reliability.
  - 经它出判断的是 `JudgmentEngine.judge`, 调用方是 A6 的判断程序 REV-03, REV-02, CSH-02 (`agents/judging.py`). GEN-09 在 A6 的执行里调用, 随之过期.
  - REV-08, CSH-05 是规则程序, 指针指向行, 可靠性按行类型 (`ROW_EVIDENCE`), 不读文件登记.
  - DOC-04, DOC-06 抽文件内容, 登记改了不影响抽取. DOC-06 写进函证的回函指针记的是抽取当时的可靠性; CSH-02 的 D01 例外不沿用它, 按回函当前的登记经 document_pointer 重新取 (第 1 轮审核 R90-01, 原先这里写 "用到它的 CSH-02 已在内", 不对).
  - CSH-04 回函的可靠性按收函渠道 (`reply_reliability`). RPT-03 引用判断, 不引用文件页. ACC-04 的指针指向留痕.
  - 审计助理的对话工具 (concierge_chat) 现取现用, 不产出要过期的结果.
- 可靠性的保留 (裁定 2 与 6):
  - 原先指定类型后, 后台抽取 (DocumentIntake.classified) 会按类型缺省再写一次可靠性. 所以只改 set_document_type 不够, 改成所有改类型的地方都经同一个函数.
  - 暂存与未导入的文件不能补登记, 确认导入时其实不会遇到补登记过的文件. 那里也走它, 只为一处实现.
- 演示数据导入 (R269) 用 set_document_details 一批传多份, 接口一次一份.
