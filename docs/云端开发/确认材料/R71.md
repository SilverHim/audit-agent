## 讲解

### 业务背景

- ACC-04 (客户承接) 要查 ABN 与 ASIC 登记, CSH-04 (银行函证) 要发询证函, 收回函. 本版两者都是 mock, 从数据集目录读 JSON 与 PDF.
- 原来 main.build_deps 把两个 mock 固定在 data/demo, 所以 Xero 项目也查 Numbat 的登记, 读 Numbat 的回函.
- 现在按项目的数据集定位目录 (设计第 9.3 节第 5 项):
  - Numbat (demo) 读 data/demo.
  - xero/20261017-q1 读补造目录 data/xero_demo/20261017-q1. R64 写了登记 mock, R65 写了两份银行回函与 receipts.json.
  - 没有补造目录的 Xero 数据集 (20261017-mock) 查不到登记, 函证为未回函. 结果与改动前一样 (原来读 data/demo 也查不到 Xero 的号码与账号).

### 契约

- `RegistrySource` 两个方法加 eid 首参, 与存储方法 "首参 eid" 的约定一致 (主代理裁定第 4 批). JR-3 将要新增的 asic_extract, asic_person 同样以 eid 为首参.
- `ConfirmationChannel.submit` 原本就带 eid, 签名不变, 只改说明.

### 实现

- `dataset_directory(engagements, directory, eid)`:
  - 用 EngagementStore.get 取项目. 没有该项目时抛 LookupError.
  - 返回 `directory(engagement.dataset)`, 即 RoutingDatasetLoader.supplement_dir.
- `DatasetRegistrySource(engagements, directory)`:
  - 目录为 None, 或目录下没有 registry/ 时返回 None.
  - 否则交给 MockRegistrySource(目录).
- `DatasetConfirmationChannel(engagements, directory, receipt_root)`:
  - 先取项目, 不存在抛 LookupError.
  - 同键已有回执时直接返回, 不解析目录. 已发出的函证不因补造或快照后来的变化而取不回.
  - 否则按项目数据集取目录, 交给 MockConfirmationChannel(目录或 None, receipt_root).
  - 回执仍按 `receipt_root/{eid}/sha256(幂等键).json` 持久化. 所以两个项目同账号同键互不影响, 新建实例后同键仍返回同一回执.
- `MockConfirmationChannel`: dataset_dir 为 None, 或没有该账号的回函 PDF 时, 四项 (replied_at, reply_file_name, reply_bytes, receipt_channel) 都为空, 也不读 receipts.json. 原来没有回函时仍会读 receipts.json, 目录不存在就会报错.
- XeroDatasetLoader.supplement_dir 沿用 R70 的核对: 补造与快照不匹配时, 登记查询与函证都抛 SupplementMismatch.
