## 讲解

### 业务背景

- 外部与终验段要用六个注入场景 (T1 至 T6, 设计第 8.2 节) 验证各程序能发现人为埋入的错误.
- 决定 6 规定: 错误只能注入在测试的临时副本里, 原快照与补造目录一律只读.
- 本条只交付这套机制与空补丁 T0. 各场景的补丁内容与断言由后续需求写.

### 补丁格式 (`Patch`, extra=forbid)

- 顶层: `{scenario, title, ops}`. ops 按 `op` 字段区分六种.

| op | 字段 | 作用 |
|---|---|---|
| set | file, 定位, field, before, after | 改字段. field 用点号写嵌套字段, 为空时指定位到的元素本身. before 为 null 表示改前不存在 |
| delete | file, 定位, before | 删数组元素, 对象的键或 CSV 行. before 为被删的整个值 |
| add | file, key 或 append, after | 加对象原来没有的键, 或追加到数组 / CSV 末尾. CSV 行须按表头给全部列 |
| add_file | file, content | 加新文件, 目标须原来没有. content 为字符串原样写, 否则写成 JSON |
| tb_shift | code (字符串), delta_cents (整数) | 副本期末试算表该科目的余额加 delta_cents |
| render | what (registry_pdfs) | 按副本的登记 JSON 重绘登记 PDF |

- file 以 "api/" 或 "xero_demo/" 开头, 分别相对副本快照与补造目录, 不能跳出副本目录.
- 定位三种, 恰好给一个:
  - match: JSON 数组中各字段都存在且相等, 须恰好命中 1 个.
  - key: JSON 对象的键.
  - row: CSV 首列 (各补造 CSV 的首列都是 id).
- 比较都连类型一起比 (规范化的 JSON): 0 与 false, 1 与 1.0, "1" 与 1 都算不同. before 与 match 同口径.
- 执行前断言当前值等于 before. 不等时报 "文件 定位 字段: 当前值与 before 不符", 不写当前值.
- CSV 的 set: field 须在表头内; field 为空 (整行替换) 时 after 须按表头给出全部列.

### `xero_case(tmp_path, scenario)` (设计第 8.1 节七步)

1. 记两个原目录的逐文件 sha256. 目标目录下已有副本时先报 "已有副本".
2. 复制到 tmp_path/api/20261017-q1 与 tmp_path/xero_demo/20261017-q1.
3. 联系人与快照子目录:
   - 只复制快照的顶层文件, raw/ 不复制.
   - contacts.json 在内存中去掉登录账号联系人 (口径同校验脚本: 双否且有 FirstName 与 EmailAddress), 断言恰好去掉 1 条, 副本剩 82 个.
   - 过滤在 filtered_contacts 内完成, 调用方的栈帧里没有原列表.
4. 逐条执行补丁.
5. tb_shift 原地改副本期末试算表:
   - 按余额方向改写该科目的 YTD Debit 与 YTD Credit, 余额为 0 时两列都写空.
   - 合计行的这两列随之重算. 本月两列不维护, 载入器与各程序只读 YTD 两列.
   - 全部执行后断言两点: 副本试算表借贷合计为 0; 副本分录推出的期末余额等于试算表 (plug_entry 为 None). 不一致报科目代码.
6. 重写副本 manifest:
   - 用生成脚本的 write_manifest, injected 为场景名.
   - 补造与快照哈希按副本重算, contacts.json 不在清单.
   - 再用校验脚本的 scan_login_contact 扫描两个副本. 原值取自原快照, 只在内存比对, 断言不含, 失败只报文件名.
7. 收尾再比一次原目录哈希. 比对写在 try/finally 里, 第 2 至 6 步 (build_case) 失败时也比:
   - 原目录被改时报改动的文件, 原异常留在 `__context__`.
   - 原目录没改时, 原异常原样抛出.

- 返回 `XeroCase(scenario, snapshot, supplements, loader, dataset)`.
  - loader 为 `XeroDatasetLoader(tmp_path/"api", planning, supplements=tmp_path/"xero_demo", allow_injected=True)`.
  - 可传 engine 与 evidence_store, 供以后连库的场景用.
- 没有本地快照时 pytest.skip("没有本地 Xero 快照").
- `snapshots` 与 `supplements` 参数只供本机制的自测换成自造目录.
- 夹具 `xero_case(场景, base=None, **选项)`: 同一用例成对断言 (基线 T0 与注入场景) 时, 给不同的 base 子目录名.

### 会话级哈希守护 (`xero_originals_unchanged`)

- 会话开始与结束各算一次两个原目录的逐文件哈希, 不同即失败, 只报文件名.
- 目录不存在时为空: 没有快照时只核对补造目录, 两个都不存在时不做事.

### 测试 (`tests/test_xero_case.py`)

- `test_patch_model_is_strict`: 以下都被拒绝: 多余字段, 两种定位, 没有定位, add 同时给 key 与 append, 未知 op, tb_shift 的 delta_cents 为 "5" / true / 5.0, code 为整数. T0 可读.
- `test_t0_copy_loads_like_the_original` (需要快照):
  - 副本的七张表与原目录逐行相同, 含发票的 customer 与 customer_abn; 合同 PDF 逐字节相同.
  - 副本 manifest 带 injected=T0, 快照清单不含 contacts.json.
  - allow_injected 为假的载入器抛 SupplementMismatch.
  - 联系人条数 (副本, 原快照) 为 (82, 83), 只比整数; 副本中没有登录账号联系人; 没有 raw/.
- `test_before_mismatch_and_match_count_fail`: before 不符 (消息含文件, 定位与字段); match 命中 0 个; match 命中多个.
- `test_moving_a_journal_needs_tb_shift`:
  - 把期后收款 637 (10-06, 借 090 贷 610 各 550) 改到 09-30, 不调试算表: 失败, 消息含 090 与 610.
  - 配 tb_shift 090 +55000, 610 -55000: 通过, 副本试算表两科目随之变动.
  - 科目不存在时报出.
- `test_add_delete_add_file_and_csv_rows`:
  - 删 CSV 行再追加, 加对象的键, 加新文件.
  - 以下失败: add_file 目标已存在, file 前缀不对, 路径跳出副本.
- `test_set_row_changes_one_csv_line`: SR-ORC1026 的 signed_date 改为 10-02, 载入结果随之变; 其余行逐字节不变. 表头外的列与不全的整行替换都被拒.
- `test_delete_whole_journal_with_tb_shift`: 以整笔分录为 before 删去 499, 配 710 -75000, 711 +82500, 820 -7500.
  - 结果: 710 与 711 为 0, 两列都写空; 820 为 -126697; 合计行等于各行之和.
  - before 有一处不同时被拒.
- `test_before_null_and_strict_types`: 字段原来不存在时 before null 可加; 字段有值时被拒; 布尔字段 before 写成整数时被拒.
- `test_json_object_and_array_ops`:
  - 一次补丁做 5 件事:
    - set + key 换掉人员检索的 roles (数组整值).
    - delete + key 删一个回函键.
    - append 追加风险清单.
    - add_file 写 JSON.
    - render.
  - 结果:
    - 人员检索 PDF 随 JSON 变.
    - 新文件进副本 manifest, PDF 的哈希等于副本文件.
    - 载入器核对通过.
  - 不合用法的被拒: 对象上 append, 加已有的键, 删不存在的键, JSON 上用 row.
- `test_render_registry_pdfs_follows_copy`: 改副本的公司摘录名称后 render, 副本 PDF 文本层是新名称, 原目录哈希不变.
- `test_contact_filter_and_scan_on_synthetic_snapshot`: tmp 自造快照, 只有合成联系人.
  - 过滤去掉合成的登录账号联系人, 不复制 raw/.
  - 扫描报出植入合成姓名的文件.
  - 0 条或 2 条时失败.
- `test_hash_guard_helpers`: 改动, 新增, 删除都报文件名; 目录不存在时为空.
- `test_skips_without_snapshot`: 快照目录不存在时跳过.
- `test_fixture_is_bound_to_tmp_path`: 夹具绑定本用例的 tmp_path, 载入器 allow_injected. 同一目录再建副本时报 "已有副本"; base 换子目录后可再建, 两份载入结果相同.
- `test_match_compares_types`: `{"a": 1}` 不命中 a 为 true 的元素; 5.0 不命中 5; 字段不存在不命中.
- `test_originals_compared_on_failure_paths`: 用 tmp 自造的原目录, 把 build_case 换成改动原目录的假函数, 核对 xero_case 收尾的三种情况.
  - 构建失败且原目录被改: 报改动的文件, 原异常留在 `__context__`.
  - 构建成功但原目录被改: 失败.
  - 原目录没改: 原异常原样抛出.
