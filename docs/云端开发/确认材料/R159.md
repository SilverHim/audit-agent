## 方案取舍

- **纯函数放在 services/review_queue.py:** 同 attribute_exceptions. 放 decisions.py 会让 agents 依赖 orchestration, 循环导入.
- **一条通用规则:** "凡判断置 confirmed 且带载荷, 按载荷写错报". confirm, 对判断认定错报, 仲裁 a6_upheld 由此生效. 人工判断带人给的载荷, 由同一规则生效.
- **仲裁不收载荷:** a7_upheld 与 neither 建的人工判断不带载荷, 错报不写. FIN-03, FIN-09 为 L2, A7 不复核, 现不出争议任务. 自主度提到 L3 后要另立需求.
- **字段规则按模板类别叠加:** 不在 REVIEW_FIELDS 加按程序的行. 允许的决定不变 (T12 不限制).
- **版本与一致性在算效果时查:** VersionConflict 由 _deciding 转为 VERSION_MISMATCH, ValidationError 转为 INVALID_VALUE, 都不写. kind 与对象在字段之后查.
- **写入者:** 决定确认时为 A1 (同一事务), 自动确认时为 A8 (片段). 迁移表与写入归属已同步.
- **节点读回不改:** FIN-03 的 outputs 含 misstatements (latest_all). 节点恢复时重放取回最新版本, 用例 9 断言.
- **载荷没写的字段不改:** 人给的分类只写 type 时, origin 与 objective_id 保持原值. communicated 时一律置 needs_recommunication.
- **测试装配:** R160 接节点前, 完成节点改为只执行 FIN-03. 检查点以 fan_in 身份写入 P2 已结清的 Xero 状态, 真实 A8 读 Xero fixture.
- **R158 的舞弊用例:** 按载荷手工构造错报的后半段删去, 改由本条用真实确认写出的版本断言, 免得两处重复.
- **验证载荷:** FIN-09 尚未落地. 效果用 review_effects 纯函数测. 经 DecisionSubmit 的不合格验证载荷, 用载荷类别改为 verification 的 FIN-03 副本测.
