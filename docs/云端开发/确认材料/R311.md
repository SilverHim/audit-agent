# R311 确认材料: 演示走通用例的真实大模型变体

## 改动摘要

- 新增 `tests/test_demo_walkthrough_live.py`, 只改测试, 不动产品代码.
- 驱动 `drive`: 只经 HTTP 接口照页面的做法走, 每次停下按当时的状态办:
  - 有待决任务先逐条决定;
  - 概览建议导入就导入;
  - 等数据就绪就确认数据已齐;
  - 停在闸门就按闸门决定.
  - 进度记在 `LiveWalk`, 中途失败也能写出汇总.
- 审计师的决定: 按演示决定表 `decision_table` 期望的结论下, 不看模型的建议动作.
  - 表的内容同 R287: BA-091 与 XJ-499 认定错报, XJ-575 推翻为接受, 其余确认.
  - 争议任务: 原判断与期望一致时维持, 否则 "两者都不采用" 给出期望的结论, 期望错报时附草稿.
  - 无解释的例外: 认定错报或推翻.
  - failed 任务: 重跑, 同一对象第二次失败即判失败.
- 闸门决定:
  - FIN-01 按汇总表的候选意见决定 (`candidate_opinion`), 错报闭环接入前为保留意见.
  - RPT-01 先退回一次, 再批准 (同 R287).
- 检查与汇总:
  - `evaluate` 汇总用量 (调用与 token 取预算, 尝试与失败级别取留痕), 各判断的建议动作与固定输出的对照, 签字报告的意见类型, 解析不了的指针, 缺模型结论的对象.
  - `assert_hard` 做硬性检查, `warn_soft` 对软性差异只告警.
  - `real_walk` 在组装根的真实依赖上走一遍, 汇总写 var/eval/demo-live-<UTC>.json.
- 用例:
  - 真实模型用例 `test_demo_walkthrough_live`: slow, live (max_calls 150, live_budget), external.
  - 自测 4 条: 离线三遍 (固定输出; 一对象先失败再重跑; 带规则例外的对象失败), 连库一遍 (大模型换成组装根的 mock).
  - 决定请求体的单元用例 1 条.

## 方案取舍

- **驱动按状态走, 不按固定停点**: 真实模型可能在 P1 出 failed 任务, 停点顺序不固定. 每步都处理 "任务, 导入, 数据已齐, 闸门" 四种情形, 别的情形判为流程停住. 这样一个驱动同时走得通固定输出与真实模型.
- **复用 R287 的走法而不改它**: test_demo_walkthrough 的 walk 是固定停点的断言用例, 不加参数. 新文件只复用其常量与 xero_link, 以及 R287 的决定 (xero_journal_reviews, 草稿, 重要性, 批注).
- **硬性的 "每个对象有模型结论"**:
  - 带规则例外的对象 (如 ORC1026) 判断失败时, 复核队列建 unattributed 任务, 不能重跑.
  - 这时驱动按决定表推翻, 照常走完, 但该对象缺模型结论, 硬性检查不过, 这正是需求的 "得出结果或 failed 后重跑一次". 自测里有这一例.
- **证据指针全部解析**: 范围同 R56 的 everything (判断, 合同, 函证, 例外, 评分卡, 人工结果). 客户画像指针按项目采用的画像解析.
- **调用上限 150**: 固定输出一遍 46 次. 余量给 A7 两轮复核 (随模型输出触发), 校验重试与重跑. LIVE_MAX_CALLS 可覆盖.
- **自测怎么注入**: 自测把模型换成固定输出, 外面包同一个预算 (SwitchableLLMClient). FIN-01 选无保留意见, 因为固定输出的报告两稿按它写. 真实模型按候选意见起草.
- **汇总落点**: 真实模型的汇总写 var/eval (不入库). 自测的汇总写临时目录, 不在 var/eval 留文件.

   - 走到归档, run_error 始终为空 (驱动每步断言).
   - 17 个判断对象都有模型结论, 重跑至多一次.
   - 证据指针全部解析通过 (自测为 313 个).
   - 签字报告一份, 意见类型等于 FIN-01 决定, 意见段首行为该意见的标题.
   - 合同 3 份, 函证 2 户.
3. 软性: 建议动作与固定输出不同的逐条 warnings, 汇总的 differences 也列出.
4. 汇总: 调用次数与 token (分程序), 尝试与失败级别, 各判断的对照, 报告意见类型, FIN-01 决定与候选意见, 重跑与非 normal 任务, 决定计数.

  - 离线与连库都走到归档, 硬性检查过, 无差异, 无重跑, 调用 46 次 (同 R287).

  - 带规则例外的 ORC1026 失败: 转 unattributed, 硬性检查记为缺结论.
