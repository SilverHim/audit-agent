## 讲解

### 业务背景

- critique C8: 草稿里有两套抽样函数.
  - AC-4 用 `int(sha256(f"{eid}:{judgment.id}")[:8], 16) / 2^32`.
  - MD-16 用 sha256 对 10000 取模.
  - 建议统一为一个函数, 按用途加盐.
- 现状: cedb576 的 `review.sampled` 只按判断 ID 的 sha256, 不含项目号, 不分用途.
- 第 7 批裁定: critic 用途沿用现有公式不加盐, 只有新用途 (blind 等) 加盐.
- 用途要分开: 同一判断在 A7 复核抽样与盲测抽查里是否抽中应当互不相关. 否则两种抽查总落在同一批判断上.

### 函数 (验收 1)

- `sample_point(purpose, key)`:
  - 对一段文字取 sha256, 十六进制前 8 位折成整数, 除以 2^32, 落在 [0, 1).
  - critic 用途: 那段文字就是键本身, 与原 review.sampled 逐值相同.
  - 其余用途: 那段文字是 "{用途}:{键}".
- `sampled(purpose, key, rate)`: 抽样点小于 rate. 抽样点在 [0, 1) 内, 所以 rate ≤ 0 恒不中, rate ≥ 1 恒中, NaN 恒不中.
- purpose 的类型为 `Purpose = Literal["critic", "blind"]`, 拼错的用途由 mypy 挡住.
- 测试 `tests/test_sampling.py`:
  - `test_same_input_same_point_and_purposes_differ`:
    - 同输入同值.
    - critic 与 blind 对 J-REV-02-1-X1 不同 (0.2563 与 0.5514).
    - 2000 个 ID 的抽样点都在 [0, 1).
  - `test_rate_and_independence_between_purposes`: 2000 个判断 ID (J-REV-02-1-X0 至 X1999) 在 rate 0.05 下, 两种用途各抽中 60-140 个, 交集不超过 20 个.
  - `test_critic_purpose_keeps_previous_formula`:
    - J-CSH-02-1-BA-091 的 critic 抽样点四位小数为 0.1453.
    - 2000 个判断 ID 逐个与旧公式 (测试里原样抄录) 相同.
    - blind 用途等于对 "blind:J-REV-02-1-X1" 取哈希.
  - `test_rate_bounds` (第 1 轮 R84-01 加): rate 0, -0.5, NaN 一个不中; 1, 1.5, inf 全中.
- 本地另算过一组 (J-REV-02-1-SI-0000 至 1999): critic 抽中 95 个, blind 104 个, 交集 2 个.

### 键只用判断 ID (验收 2)

- 不含项目号, 与 AC-4 草稿不同.
- 理由写进接口文档第 6 节:
  - 判断 ID 确定, 重放与恢复结果不变.
  - 连库测试每次新建项目, 加项目号会使抽中的对象随项目号变, 计数不稳定.

### 现有测试与 Numbat (验收 3, 4)

- `test_sampling_is_replayable` 改用 `sampled("critic", ...)`, 断言不变 (60-140 个, 抽中的那个 ID 触发 sample).
- `test_assumption_step_triggers_review_without_main_rule` 中 plain 判断仍未抽中 (critic 用途与旧公式逐值相同).
- Numbat:
  - J-CSH-02-1-BA-01 由主规则复核 (L3, 建议 close), 不靠抽样.
  - REV-03, REV-02 为 L2, 跳过.
  - R55 计数不变 (test_e2e_mock 全过).

### 不在本条 (验收 5)

- MD-16 验收中依赖旧公式的数 (如 206) 由降级段按本函数的 blind 用途重算, 本条不改.

### 合并上游后的移植

- 上游没动 review.py, test_review_agent.py 与抽样相关的代码; 接口文档第 6 节合并干净, 没有冲突.
- 语义无交集: 上游的上传分类与数据体检不抽样.
