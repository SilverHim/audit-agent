# R350 确认材料: 闸门材料里的例外明细按金额与比例格式显示

## 改动摘要

- `lib/exception-detail` (新): `detailRows(detail, labels)` 把例外的 detail 逐字段转成显示行.
  - 以 _cents 结尾的按全站金额格式 (formatAud); 以 _pct 结尾的按百分比, 一位小数 (formatPct 加 digits 参数, 缺省 2 位). 数字串 (数据库 numeric 列的序列化) 一并按数解析, 不是数的照原文.
  - 其余按文本: 布尔取是否; 该字段认得的取值换成文案 (现为 basis 的 balance_sheet, profit_or_loss); 空值与空数组为 "—".
  - 对象逐个字段展开. 数组: 元素是对象的各自展开, 否则以逗号连接.
  - 字段名取文案的标签, 没有的退回字段名.
- `components/exception-detail` (新): `ExceptionDetail` 按这些行显示两列的定义表, 对象缩进一层. 两处共用:
  - 闸门材料的例外列表 (gate-form). 删去只认 PLN-07 一种明细的 `FluctuationDetail`, 以及它用的 `planning.fluctuation` 文案.
  - 复核页无归因任务的失败原因 (concierge 的 FailureDetail). 原来按 "字段: 原值" 拼, 金额是原始分数, 对象显示为 [object Object].
- 中英文案加 `exceptionDetail`: 字段标签 16 个, 取值按字段分组, 是否.

## 方案取舍

1. **一个通用的按字段显示, 不留 PLN-07 的专用句式**: 原来的专用分支要求金额是数, Xero 的 numeric 列序列化成字符串就落到 JSON 原文 (截图里的现象).
   - 通用写法按字段名后缀定格式, 各程序的明细都适用, 加规则不用改前端.
   - 代价: PLN-07 不再是一句话, 改成逐项列出 (科目, 比较口径, 本期, 上期, 比较基数, 变动).
2. **比例只认 _pct 后缀**: 程序 YAML 规则 SQL 的输出列里比例只有 change_pct. 不按数值大小猜.
3. **标签只给常见字段**: 未知字段退回字段名, 不影响显示; 以后看哪些字段常见再补.
4. **取值文案按字段分组**: "Balance sheet, opening" 只对 PLN-07 的 basis 成立, 别的字段取值同为 balance_sheet 时照原文.
