## 方案取舍

- **事实子模型只写一处:** `TermsFacts` 放 models.py. `EngagementTerms(TermsFacts, Versioned)` 在其上加核对与关联, `EngagementTermsExtraction(TermsFacts)` 为抽取输出, 两者字段不会走样 (用例核对字段恰为 framework 至 year_change). 代价是字段顺序 id, version 之后先是事实, run_id 在事实之后.
- **文件可能不写的事实一律可空:** 日期, 签署人, 股数, 比例等; `votes_pct` 不在模型里限 0 至 100, 越界留给 R199 判语义失败.
- **核对结果用枚举 `TermsCheckStatus`**, 守住检查点读回不退化为字符串; 核对项编号 `T01`-`T07` 用 Literal.
- **项放错类为结构失败:** 要素与确认共用 `TermsItem`, 模型校验只查各放自己那一类的项. 各项恰好一次由 R199 的 OutputValidator 查.
- **YAML 的 outputs 与 reads:** 验收没列这两项, 按 R200 的片段写 outputs [engagement_terms, judgments, exceptions, documents] 与 document_types [engagement_letter, minutes]; reads [documents], 因为建议判断引用约定文件的页. 承接阶段的执行不判过期, 与 ACC-04 一致.
- **GateId 先加, 登记表行由 R201 加:** 现有的 test_gates 用例按 `list(GateId)` 取闸门, 没有登记行就取不到, 改为按登记表 (GATES) 取. 没有闸门停在 ACC-08, 决定提交先报 NOT_AT_GATE, 不会走到取登记行.
- **前端客户端本条重新生成 (第 1 轮裁定, 改原做法):** 重新导出的 openapi.json 与 generate-client 生成的 types.gen.ts 只差 GateId 多 'ACC-08' 与枚举说明. 之后 tsc -b 只报中英文案表按 GateId 穷举而缺 'ACC-08' 键 (engagement-shell, gate-form, decisions, gate, 项目页与项目列表共 10 处), 在 zh.ts, en.ts 的 gates, gateQuestions, verdicts, verdictHints 四张表补上 ACC-08 (约定条款与委任核验) 后 tsc -b, biome 与前端用例 (94) 通过. 闸门页本身仍由 R211 做; 入库的 openapi.json 与后端一致, 防止落后的守卫另立 R307.
- **报告框架复用 ReportingFramework (裁定):** 不另立 TermsFramework, 特殊目的写 spfr (同客户画像), 约定书没写明为 None (同 "文件没写的事实填 null"), 不另设 unknown; YAML 的 acceptable_frameworks 与抽取提示词同改. R199 的 extract.json 与 R211 的核对表须照此取值.
- **出具与签回带页指针 (裁定):** TermsFacts 加 `letter_evidence` (缺省空列表, locator 写字段名, 同委任子模型的一个 evidence 列表). TermsCheck 是否自带证据 (R211 跳页) 没有裁定, 本条不加.
- **A2 越权用例换字段:** A2 现在可写 judgments, test_merge 与 test_nodes 中 "A2 写 judgments 被拒" 的两个用例改用 confirmations, 测的还是写入范围.
