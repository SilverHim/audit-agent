## 讲解

### 业务背景

- critique C7 指出三处问题:
  - 后续多个需求要在判断与分类之间插步骤 (判断级降级, 盲测抽样), 顺序没定.
  - 判断的自主度取模板, 而 A7 的触发规则读程序的运行时级别 (Procedure), 两者可能不同.
  - OutputValidator 的 if-elif 链将被 10 个分支改动.
- 现状核对:
  - cedb576 已在 judge 闭包里于判断后, 分类前调用 A7.
  - JudgmentEngine.judge 取 template.autonomy_level.
  - classify 读判断的级别.
- 本条把判断流程抽成公共模块并固定插入顺序, 自主度统一取运行时级别, 输出校验改为登记表.

### 判断公共流程 (验收 1, 2)

- `judge_all(deps, ctx, subjects, critic, steps=DEFAULT_STEPS)`:
  1. 按 in_scope 筛选对象.
  2. 组装任务说明与 JudgmentContext. autonomy_level 为 `ctx.procedure.autonomy_level`.
  3. 并发调 `deps.judgments.judge`.
  4. 有判断时依次: `critic.review` → `steps.downgrade` → `steps.blind`. 判断失败的对象不经这三步.
- `judgments_patch(deps, ctx, judged)`: 原 FieldworkAgent.judgments_patch 的逻辑, 逐个对象 classify 后 make_task 或自动确认. 逻辑不变.
- `JudgingSteps`:
  - frozen dataclass, 两个字段 downgrade 与 blind, 类型 `Step = Callable[[RunContext, Judgment], Awaitable[Judgment]]`.
  - 缺省都是 `unchanged` (原样返回).
  - 由后续需求替换: 判断级降级在规格书第 7.4 节 (A7 之后), 盲测抽样在第 9.2 节.
- `Critic` 协议只要 `review(ctx, judgment)`; ReviewAgent 满足.
- FieldworkAgent:
  - `judge_all` 与 `judgments_patch` 两个方法改为调 judging, 传入 `self.reviewer` 与 `self.steps`.
  - CSH-02 的 cash_patch 照旧经 judgments_patch.
- 规则程序 (REV-08, CSH-05) 走 run_rules 与 rule_exceptions, 不进本流程.

测试 (`tests/test_judging.py`):
- 记录调用的替身:
  - RecordingEngine: 判断引擎.
  - RecordingCritic: A7, 写上 consistent.
  - recording_step: 降级与抽样, 记下收到的判断的 critic 结论.
  - RecordingQueue: 记 classify 与 make_task; 有判断的一律分为 normal, 以便走到 make_task.
- `test_steps_run_in_fixed_order`: REV-03 一个 L3 accept 判断. 调用表恰为 judge, critic, downgrade (consistent), blind (consistent), classify, make_task (normal).
- `test_failed_subjects_skip_critic_downgrade_and_blind`: REV-02 三个对象:
  - A 成功: 走全程.
  - F (failed) 与 U (unattributed, 带规则例外): 只有 judge, 再各一次 classify 与 make_task (failed, unattributed).
- `test_rule_programs_do_not_enter_judging`: REV-08 与 CSH-05 各一例, 只调规则引擎, 调用表为空.
- `test_default_steps_return_judgment_unchanged`: 缺省两步返回同一对象, A6 缺省用 DEFAULT_STEPS.
- 验收 2: R40-R49, test_review_agent, test_dispute, test_review_tiers, test_fieldwork_judging 等原有用例不改断言全过 (含 J-CSH-02-1-BA-01 consistent, 置信度 0.65).

### 自主度取运行时级别 (验收 3)

- `JudgmentContext.autonomy_level` 由 judge_all 填 Procedure 的运行时级别.
- `JudgmentEngine.judge` 取 `ctx.autonomy_level or template.autonomy_level`: 其他调用方不填时取模板, test_judgment_engine 不变.
- 这样判断的级别, A7 的触发规则 (读 ctx.procedure) 与 classify (读判断) 三处一致.
- 测试 (真实判断引擎, mock 读 tests/fixtures/llm/REV-03/CON-001.json, 只判 CON-001, 模板 L2):
  - `test_runtime_l3_above_template_l2_is_reviewed_and_confirmed`: Procedure L3.
    - 判断 J-REV-03-1-CON-001 为 L3.
    - A7 两轮 (脚本模型 CON-001-r1, CON-001-r2): 第一轮只引用判断给出的合同第 2 页与 AASB15-P31, 第二轮 consistent.
    - 判断 v1 即 confirmed, 不建任务.
  - `test_runtime_l1_below_template_l2_skips_critic_and_gets_task`: Procedure L1. 判断为 L1, critic skipped, 不调复核模型, 建 normal 任务 T-J-REV-03-1-CON-001-v1.
  - `test_context_carries_runtime_level`: Procedure L4 时 JudgmentContext.autonomy_level 为 L4.

### OutputValidator 分派表 (验收 4)

- `CheckResult`: output, level, unsupported, errors, notes.
- `Check = Callable[[OutputValidator, str, Any, ValidationContext], Awaitable[CheckResult]]`.
- `OutputValidator.CHECKS` (类属性) 与 `register(model, check)` (类方法).
- validate:
  - 语法与结构两级不变.
  - 按 `output_model(template)` 查 CHECKS, 未登记抛 NotImplementedError (同现状).
  - 按校验函数的结果出报告, retryable 为假.
- OutputValidator 类与各校验函数之后登记 7 种, 各自调原来的私有方法, 结果与原 if-elif 相同:
  - JudgmentDraft → check_judgment.
  - ContractExtraction, ConfirmationExtraction → check_extraction (回函抽取另核账号, 渠道不符只记提示).
  - ReportDraft → check_report.
  - CriticIndependent → check_critic (问题只记下, 不判失败).
  - CriticVerdictOut, DocumentClassification → structure_only (上传文件分类: 类型取值已由结构校验限定, 没有证据指针).
- 键为模板声明的输出模型 (原来按 isinstance 判断输出对象). 结构校验保证输出就是该模型, 结果相同.
- 测试 (test_output_validator):
  - `test_every_referenced_output_model_is_registered`: 程序库全部模板 (含未启用的) 与 ingest.CLASSIFY, review.VERDICT_SPEC 引用的输出模型都在 CHECKS 中 (第 1 轮 R83-01 加).
  - `test_dispatch_table_covers_existing_models`: CHECKS 的键恰为 7 种, DocumentClassification 登记的是 structure_only.
  - `test_unregistered_model_is_not_implemented`: 临时模型 ProbeOut 未登记时抛 NotImplementedError, 消息含模型名.
  - `test_registered_check_decides_report`:
    - register 登记 ProbeOut 的校验后, 奇数出 semantic 失败, 带错误与提示.
    - 偶数通过, 输出取校验函数改写的.
    - 结构不过时不调用校验函数.
    - 用 monkeypatch 换一份 CHECKS 的副本, 登记只在本用例内有效.
  - 原有 74 个用例全过; 上游的 test_documents_upload (A3 上传分类经 validate) 不改断言全过.
