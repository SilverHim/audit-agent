## 1 事实

### 1.1 载入器决定的口径

以下按 `src/backend/adapters/xero_dataset.py` 推出, 是只读阅读的结论.

- **分录号与行号**:
  - 分录号是 `XJ-{JournalNumber}`, 行号是 `XJ-{n}-{k}`.
  - k 是 mock JournalLines 中金额非零的行的顺序号. 例如 XJ-499-1 是 710 科目借方 750, XJ-499-2 是 711 科目贷方 825, XJ-499-3 是 820 科目借方 75.
- **制单人与审批人**:
  - 全部行的 `created_by` 是常量 "xero", `approved_by` 全部为空.
  - 所以 JE-R04 (制单人与审批人相同) 和草稿里的 R07 (非常规制单人) 在 Xero 上**不能执行**. 这符合真实的 Xero Journals 接口: 它本来就不返回用户字段.
- **录入时间**: `created_at` 取 mock 的 CreatedDateUTC. mock 把导出的 Posted Date 当作悉尼当地时间换算成 UTC, 所以转回 Australia/Sydney 后等于 Posted Date 原值. 换句话说, 规则看到的录入时间就是 Demo 重置时生成的时间.
- **作废对全部入库**: 冲回分录的说明是 Reference, 形如 "Reversed: ... - Reversal of ID n". 但行上如果有自己的 Description, 就取 Description, 这时候这一行的说明里不出现 "Reversal". 所以识别冲回要在**同一分录号的任一行**上匹配.
- **调整分录标志**: `is_adjustment` 为真的有两类. 一是 MANJOURNAL. 二是没有 SourceType 且说明以 Conversion Balance, Reconciliation adjustment 或 opening balance 开头的分录. 表里没有 source_type 列.
- **销售发票**:
  - ID 是 `SI-{InvoiceID}`, `amount_cents` 取含税 Total.
  - 只收已生效的 ACCREC 发票, 不收贷项通知单.
  - `journal_entry_id` 指向该发票最后一次过账的分录里记应收的那一行, 例如 ORC1003 指向 XJ-405-2.
- **银行流水**: ID 是 `BT-{科目}-{序号}`, 按对账单全部行的日期排序编号, 不按期间过滤. 下面引用的序号取自现有 mock 快照. dataset.json 改成 09-30 后如果重新拉取, 序号可能变化, 标 "待载入器确认".
- **客户画像**: ID 是 `CLIENT-XERO-3C1332BB`. `directors` 为空, 也没有关联方字段.

## 5 风险与不确定处

1. **AASB 1060 正本缺失**: AASB 124 AusB1 写明它不适用于 Tier 2 主体. GEN-03, GEN-01 的关联方定义和披露结论, 依据要待 AASB 1060 正本. 现在提示词和测试数据里只能引 ASA 550 第 10(b)(i) 段, AASB 124 第 9 段只作参照.
2. **作废对全部入库**: 载入器不剔除作废对. 新规则剔除作废对时, 要在同一分录号的任一行上匹配 "Reversal of ID n", 原分录则要靠这个编号反查. 冲回分录的行如果自带 Description, 说明里就没有 "Reversal" 字样. 这部分标 "待载入器确认". 也可以请载入器加一个作废标志列, 但那是 B 的表结构改动.
3. **往来单位没有 ABN**: Xero 的往来单位没有 ABN, 不能像 Numbat 那样用 ABN 与 ACN 匹配. 关联方交易只能用名称规范化匹配 (去掉 "Pty Ltd" 再比). 名称写法不一致时会漏, 例如对账单写 "Maddox Publishing", 往来单位写 "Maddox Publishing Group".
4. **对象 ID 的稳定性**: 银行流水序号与 SourceID 依赖现有 mock 快照. dataset.json 改成 09-30 后如果重新拉取, 或者 Demo 每 28 天重置, 日期, 金额和 ID 都可能变. 预期值应该由转换器从快照算出, 或者用 sha256 锁定快照.
5. **重要性是假设的**: 本文的重要性 324.31 / 243.23 / 16.22 是按 Numbat 比例假设的. 如果明显微小超过 296.95 或 75, R11-1 和 #499 的结论会受影响.
6. **个人检索是否列持股待核**: ASIC 的个人检索是否列出持股, 没有原文. 设计里让 Alex 在三家公司都担任职务, 规避了这个问题.
7. **号码与名称可能撞真**: 补造的 ACN 与 ABN 没有和真实登记查重. "Victoria Property Agency" 和 "Harbourview Nominees" 这两个名字可能与真实公司重名, 补造件必须带 FICTITIOUS 页眉.
