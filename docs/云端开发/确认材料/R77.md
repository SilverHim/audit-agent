## 讲解

### 业务背景

- 计划决定 1 (critique T1 选项 1) 定下新程序后接入. 后续每组都会加程序 YAML 与大模型 fixture.
- 原来几处测试写死了计数或下标, 每加一条程序都要改, 新 fixture 一加守卫就红 (critique C13, C14; verify G1, G2, G5):
  - test_all_procedures_load 写死 18 条.
  - 固定集按下标 10 切.
  - fixture 全用断言要求 tests/fixtures/llm 下每个文件都被读到.
  - 两个 fixture 守卫只认 Numbat 的目录.
- 本条把它们改成 "集合包含" 加 "基线精确集", 只看本次启用的程序, 守卫按数据集登记.
- Numbat 回归的断言值不变.

### 程序数 (验收 1)

- BASE_18: Demo 的 17 条加 GEN-09.
- `count_guards(root)` 返回两条守卫的差集, 都为空才通过:
  - BASE_18 中全部模板 (含未启用) 没有的程序.
  - 基线启用集与 BASE_18 的对称差.
- 第二条保证新程序必须挂功能名: feature 为空的程序会进基线启用集, 使它不再等于 BASE_18.
- `test_count_guards_on_extra_templates`: 复制 knowledge 到 tmp, 以 REV-02 的 YAML 为底 (去掉 triggers 与依赖):
  - 加 X-J (feature journals): 两条都过.
  - 再加 X-B (feature 为空): 第二条失败, 差集为 {X-B}.

### 固定集与装配 (验收 2)

- FIXED = {ACC-04, ACC-01, DOC-04, PLN-07, PLN-01, PLN-03, FIN-04, FIN-01, RPT-03, RPT-01}.
- `test_fixed_set_is_baseline` (原 test_fixed_set_has_ten_programs): 固定集的 ID 集合等于 FIXED, 条数为 10, 都不在 P2 阶段.
- 装配后程序包的前段仍是原固定集 (前缀断言, 不写死下标), 新增的追加在后.
- 新增的 7 条与顺序 [CSH-05, CSH-04, DOC-06, CSH-02, REV-03, REV-08, REV-02] 不变.

### fixture 全用断言 (验收 3)

- `enabled_programs(deps)`: 程序库启用视图的 ID.
- `assert_fixtures_used_once` 只取 fixture 根下目录名在启用集中的文件, 与 llm_call 留痕的 (程序, fixture_key) 比对, 并要求每次一次通过 (attempt 1, 无失败级别).
- 未启用程序的目录不比对, 所以后接入的程序可以先放 fixture.
- R55 (test_every_fixture_used_once_and_passes) 与 R56 (连库) 比对 15 个文件, 按程序计数为: CSH-02 1, DOC-04 3, DOC-06 2, GEN-09 2, REV-02 2, REV-03 3, RPT-03 2. R57 的中断恢复用例同样传启用集.
- `test_fixture_guard_compares_enabled_programs_only` 用 tmp 复制的 fixture 根与合成的 llm_call 留痕 (启用程序的每个文件一行) 测这个辅助函数:
  - 原样时比对 15 个, 计数同上.
  - 多放 FIN-03/default.json (FIN-03 未启用) 仍过.
  - 多放 REV-03/CON-999.json (启用的程序多一个文件) 失败.

### 登记表与两个守卫 (验收 4)

- `FixtureSet` 字段:
  - name: 登记名, 作 pytest 参数 ID.
  - dataset: 数据集名.
  - fixtures: 测试 fixture 根.
  - runtime: 运行副本根.
  - manifest.
  - expected_document: 期望 PDF 函数, 可空.
- 本条只登记 numbat: tests/fixtures/llm, data/demo/llm, data/demo/manifest.json, `numbat_expected_document` (即原 expected_document, 逻辑不变).
- `test_fixture_document_ids_in_manifest[numbat]`:
  - 每个 document 指针的 source_id 在该 manifest 中, 页码不超过页数.
  - 有期望 PDF 函数时还须指向它给出的 PDF.
  - numbat 行的指针计数 (12 项) 与原断言相同.
  - 没有登记计数的行只核对指针合格; 登记了计数的名字须都在登记表里.
- `test_runtime_fixtures_match_test_fixtures[numbat]`: 运行副本与测试 fixture 文件集合与内容 (JSON) 相同. 运行副本根不存在时报 "运行副本未生成" 失败, 不跳过.
- test_fake_documents_from_manifest 的 5 份 PDF 断言不变; manifest_documents 改取登记表的 numbat 行.
- 自测:
  - `test_document_check_without_expected_function`: 期望 PDF 函数为空的行, 合格指针不报, 未知 ID 与页码超出各报一条.
  - `test_runtime_check_fails_without_runtime_copy`: 运行副本根不存在时报 "运行副本未生成"; 复制的副本通过; 副本多一个文件时失败.

### 约定 (验收 5, 接口文档第 4 节)

- 新程序的 fixture 按数据集放.
  - Xero 演示: tests/fixtures/llm_xero/{程序}/{对象}.json, 运行副本 data/xero_demo/20261017-q1/llm/ 由补造文件生成脚本同步 (T1 推荐).
  - 不再往 tests/fixtures/llm (Numbat) 加新程序的 fixture.
- FIXTURE_SETS 的 Xero 一行由 R78 登记.
- 全流程测试只比对本次启用程序的 fixture 目录.
