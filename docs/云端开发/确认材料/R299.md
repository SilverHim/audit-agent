## 所选做法

按需求的推荐 (1): `src/frontend/src/components/pdf-viewer.tsx` 的两处引入改用 pdfjs-dist 官方的 legacy 构建, 主线程 `pdfjs-dist/legacy/build/pdf.mjs`, worker `pdfjs-dist/legacy/build/pdf.worker.min.mjs?url`. 版本不变 (6.4.299), package.json 与 bun.lock 不动; 类型照旧 (legacy/build/pdf.d.mts 转出 pdfjs-dist 的类型, `TextItem` 的引入不变). 没有走 (2) polyfill 或 (3) 降版本: (1) 可行, 不用自己维护补丁, 也不放弃新版本的修正.

legacy 构建由 pdf.js 用 core-js 编进了标准构建依赖的较新内置方法, 主线程与 worker 各一份. 6.4.299 的 legacy 构建里登记了 `Map.prototype.getOrInsertComputed`, `Map.prototype.getOrInsert` 与两者的 WeakMap 版, Iterator 的各辅助方法 (map, filter, take, drop, toArray 等), Set 的集合运算 (union, intersection, difference 等), `Promise.try`, `Math.sumPrecise`, `URL.parse` 等. 这些是 Chrome, Edge, Firefox, Safari 近一两年才各自补上的, 标准构建只面向各浏览器的最新版.

支持的浏览器范围: pdfjs-dist 的 README 写明较旧的浏览器用 legacy 目录的构建, 具体范围以 pdf.js FAQ 的 "supported browsers" 一节为准. legacy 构建面向比各浏览器最新版更旧的版本, 需求要的主流浏览器 (Chrome, Edge, Firefox, Safari) 最近两个大版本应在其内; 本条只实测了预装的 Chromium 141.0.7390.37 (无头, Playwright), 其余浏览器没有实机, 未测.

## 验收

1. Chromium 141 上用 Playwright 打开合同 (Numbat CON-001.pdf, 3 页), 回函 (Numbat 回函, 2 页) 与登记摘录 (R64 合成的 900043030.pdf, 2 页) 三张文件详情页, 逐页翻. 测试脚本不补任何方法, 不改 worker 的响应.

   | 文件 | 改前 (44b6c38) | 改后 |
   |---|---|---|
   | 合同 3 页 | 各页画布全空; pageerror `TypeError: this[#methodPromises].getOrInsertComputed is not a function` | 3 页都画出 (取样不透明且非近白的像素 202, 146, 149) |
   | 回函 2 页 | 同上 | 2 页都画出 (145, 92) |
   | 登记摘录 2 页 | 同上 | 2 页都画出 (107, 85) |

   改后整轮没有 pageerror, 也没有别的控制台错误. 字体 (`@fontsource-variable` 的 woff2) 经 vite 的 `/@fs` 读主检出 node_modules 时 403, 与本条无关 (worktree 的 node_modules 链接到主检出; 协调者已知), 不计.
