## 方案取舍

- **自然序:** 凭证号中每段数字补足 10 位, 再按字节序 (COLLATE "C") 比较. 这样 PostgreSQL 不必另建 ICU 排序规则 (那要迁移). 并列时取 ID 小的, 也按字节序比较.
- **行金额:** 取借贷两侧绝对值之和, 即非零的那一侧.
- **工作时间:** business_hours [7, 20] 按 [07:00, 20:00) 理解. Xero 实测 49 笔, 与验收数相符.
- **receivables_categories 本条不加:** 现有守卫 (test_account_mapping) 要求每个 `*_categories` 参数都被规则 SQL 用到. 它只给 R10 用, 由 R132 随 R10 一起加. entry_nos 照验收写为 null, 本条 SQL 不用它 (JR-6c 用).
- **R06 两项检查的顺序:**
  - 先看录入时间是否可信, 再看是否已发出错报沟通.
  - 结果: Xero 的理由是数据集说明, Numbat 的理由是 "尚未发出错报沟通, 本规则只在增量实例执行".
- **两条理由文字:** R04 为 "本期分录都没有审批人 (approved_by 全为空)", R07 为 "本期分录的录入人少于 2 个, 无从比较". R07 计数时, 连接器占位的录入人 ("xero") 也算一个.
- **R03 的范围:** 付款 = 贷记 cash 分类科目的凭证, 取其中非 cash 科目的借方行. 没有标准分类的科目算非 cash.
- **R05 的范围:** 窗口 [期末 - 3, 期末] 取闭区间, 且不早于期初. 摘要或单据号含 "revers" 或 "冲销" 即命中, 不区分大小写.
- **GEN-05 不写 inputs:**
  - 缺审批人时由 R04 记 not_executable, 不让 GEN-05 等数据. 否则 Xero 没有审批日志, GEN-05 就永远不执行.
  - 接口文档原写 "GEN-05 实现时写 inputs 并删 USED_FOR 中的对应项", 改为 GEN-05 不写 inputs, USED_FOR 中它的两项保留.
- **改动的现有测试:** GEN-05 是第一个真实的固定集与功能程序, 以下 6 个测试原先默认没有这样的程序, 按实际更新:
  - test_knowledge 的两个: 固定集模板只有 GEN-05; dataset. 引用表; 画像取 Numbat 的.
  - test_assemble 与 test_features 的装配列表: 开 journals 时多 GEN-05.
  - test_merge: outputs 表加 GEN-05.
  - test_agents_base: 注册表只映射启用的程序.
  - test_persistence_postgres: 全部规则 SQL 的连库循环补 GEN-05 的参数, 并加 SJ-2026-0612 的三条期望.

## 审核结论
