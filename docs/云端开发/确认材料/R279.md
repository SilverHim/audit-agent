## 讲解

### 授权与回调 (验收 1, 2.1, 2.2)

1. 审计师点连接, 前端取 `GET /data/xero/connect` 的 `{authorize_url}` 跳到 Xero. 先查: 项目未锁定 (423), 已配 XERO_CLIENT_ID (503 XERO_NOT_CONFIGURED), 加密主密钥可用 (503 SETTINGS_KEY_MISSING / SETTINGS_KEY_INVALID; 现在就报, 不等回调后才发现存不了).
2. 有 client secret 时按 Web app (换令牌用 Basic 认证), 没有时按 PKCE. scope 为只读 scope 加 offline_access; XERO_PAID_ENDPOINTS=live 时另申请 Journals 与 Bank Statements Plus.
3. state 与 PKCE verifier 只存在进程内存 (Q1 a): 按 state 的 sha256 登记 (不存原值), 绑定项目与发起人, 10 分钟有效, 取用即作废; 用过的另记 1 小时, 期间再用报 state_used. 授权途中重启后端, 那次授权作废 (报 state_invalid), 再点一次连接即可.
4. Xero 回到 `GET /api/v1/integrations/xero/callback?code&state`. 不要求登录, 靠 state 认出项目与发起人. 按顺序核对, 第一条不过即 302 带 `?xero=error&reason=<原因代码>`:

| 原因代码 | 情形 | 跳到 |
|---|---|---|
| state_invalid | state 缺失或不认识 (不是本系统发起的, 或重启过) | 前端首页 |
| state_used | state 已用过 | 该项目数据管理页 |
| state_expired | 发起超过 10 分钟 | 同上 |
| denied | 审计师在 Xero 拒绝授权 (带 error) | 同上 |
| exchange_failed | 没有 code, 或换令牌, 取组织失败 | 同上 |
| not_found | 项目不存在 | 前端首页 |
| locked | 项目已锁定 | 该项目数据管理页 |
| busy | 项目正忙 (图在执行, 导入, 同步) | 同上 |
| no_organisation | 授权里没有组织 | 同上 |
| settings_key | 加密主密钥不可用 | 同上 |
| internal_error | 其他意外错误 (如存库失败; 日志只记异常类型, 第 1 轮补) | 该项目数据管理页 (认不出项目时为首页) |

5. 成功时持项目锁: 令牌 (访问令牌, 刷新令牌, 到期时间) 以 Fernet (SETTINGS_SECRET_KEY, 同设置页的模型密钥) 加密存库, 组织列表与实际 scope 存在连接行. 只有一个组织时自动选定; 多个时等审计师选. 写 data 留痕 `xero_connect` (组织数, 选定的组织名, scope). 302 到 `{FRONTEND_URL}/engagements/{eid}/data?xero=connected`.
6. 跳转地址只带 xero 与 reason 两个参数, 不带 code 与 state. 回调地址本身的查询串带 code 与 state: 给 uvicorn.access 装了过滤器, 访问日志里记成 `?<redacted>`.
7. 重新连接 (如授权失效后) 整行替换: 状态回到 connected; 原来选的组织仍在新授权里时保留, 否则清空等重新选; 最近一次同步的时间与表保留.

### 多个组织 (验收 2.6)

`GET /data/xero/tenants` 取连接时存下的组织列表, 不调 Xero. `PUT /data/xero/tenant {tenant_id}` 只能选列表中的 (否则 422 INVALID_VALUE), 持项目锁, 改了才写留痕 `xero_tenant`, 返回概览里的 Xero 连接. 未选时概览的 organisation 为空 (前端据此显示选组织), 同步报 409 XERO_TENANT_REQUIRED.

### 令牌与失效 (验收 2.4)

- Q2 a: XeroClient 经 `ConnectionTokens` 读写库里的密文. Xero 刷新时会轮换刷新令牌 (旧的随即失效), 所以刷新后立即加密写库, 并记下换得时间 refreshed_at.
- 刷新返回 invalid_grant (被撤销, 已轮换, 或超过 60 天) 时连接置 expired. refreshed_at 超过 60 天的也按 expired 显示, 同步时一并置 expired. 失效后同步报 409 XERO_RECONNECT_REQUIRED, 须重新连接.
- 换了主密钥, 已存的令牌解不开, 同步报 503 SETTINGS_KEY_INVALID, 须重新连接 (断开照样能断, 只是 Xero 侧撤销不了, revoked 为 false).
- 命令行 login, tenants, pull 与令牌文件 var/xero/token.json 保留, 与网页连接互不读写 (测试核对网页连接, 同步, 断开前后令牌文件逐字节不变).

### 同步 (验收 1, 2.3)

1. `POST /data/xero/sync` 在请求里依次查: 锁定 423; 取项目锁并登记作业, 忙 (图在执行, 导入, 另一同步) 409 ENGAGEMENT_BUSY; 连接可用 (没有 409 XERO_NOT_CONNECTED, 失效 409 XERO_RECONNECT_REQUIRED, 多组织未选 409 XERO_TENANT_REQUIRED); 访问令牌 (快到期先刷新一次; invalid_grant 置 expired 报 XERO_RECONNECT_REQUIRED; 其他 Xero 错误 502 XERO_UNAVAILABLE). 后几项在 `DataService.launch` 的 prepare 里做, 不过时注销作业, 放锁并报错, 不起作业. 这样授权失效当场就能看到, 不用等后台作业.
2. 通过后返回 202 `{tables}` (计划写的表: live 六张, off 与 mock 四张), 后台作业:
   - 按项目审计期间与上期期末 (起始日前一天) 取数, 与命令行 pull 同一套取数 (`adapters/xero.fetch`). 原始响应只在内存中 (Q3 a), 不写快照目录, 用完即丢.
   - 经 `build_tables` 转成标准表, 以 `write_tables(source="xero", actor=发起人)` 写成一个新数据版本: data_changes 按表记 (R274 的过期判定随之生效), 每表一条 data 留痕 sync (version_entry), 写完体检一次. Xero 不提供录入人与审批人, 按现有规则提出补交审批日志.
   - 再记下同步时间与实际写的表 (概览的 last_synced_at 与 scope), 写 data 留痕 `xero_synced` (tables 为实际写的表, skipped 为没写的表与原因).
3. 写的表 (Q7 a): 科目, 试算表, 总账分录, 销售发票, 银行账户, 银行流水; Xero 没有发运单与审批日志, 不写, 已导入的保留.
4. 付费接口 (Q5 a): 只在 XERO_PAID_ENDPOINTS=live 时申请并取; mock 按 off (mock 读开发者本机的网页导出, 不适合网页同步). 没取到 Journals 时 (off, mock, 或 live 下 Journals 接口 401, 403) 总账从单据反推并按试算表补齐 (同数据集载入), 不算同步失败. 没取到银行对账单时银行账户与银行流水这一对都不写, 已导入的保留 (原因 paid_off: off, mock; statements_forbidden: live 下对账单接口 401, 403), 见下 "偏离方案与说明" 第 1 条.
5. 作业失败时不写数据, 写 data 留痕 `xero_sync_failed` (reason 加 HTTP 状态码): 授权失效 expired (另置 expired; 起作业后取数时 401 再刷新得 invalid_grant 也是, 令牌接口回 400 或 401 都一样), Xero 报错 xero_error, 付费接口以外的资源 401/403 forbidden (另带资源名), 中途主密钥不可用 settings_key, 转换出错 mapping (只记异常类型); 写库失败记 write 后上抛, 由后台任务记日志. 锁随作业结束释放.
6. 同步期间概览里计划写的表为 converting, processing 按表计数; 再同步, 导入或选组织报 ENGAGEMENT_BUSY.

验收 2.3 的推算: 快照 20261017-mock 期间 2026-07-01 至 11-30, 项目期间与之相同, 上期期末 06-30. 假 Xero 按 live 作答 (含 Journals 与对账单), 同步写入的六张表与 `build_tables(该快照)` (即作为数据集载入时的表) 逐行相同 (测试比对行的摘要, 不在断言消息里带出行): 科目 62, 试算表 38, 分录 1017, 发票 42, 银行账户 2, 流水 146. 数据版本 +1, 体检 1 次, 补交请求里有 REQ-approval_log. 连库测试另在真实存储上把同步的项目与载入该快照的另一项目逐表比对, 六张表都相同, 发运单为空.

### 断开 (验收 2.5, Q6 a)

`DELETE /data/xero` 持项目锁 (忙 409; 锁定的项目也能断开, 只删令牌, 不写数据): 用刷新令牌调 Xero 撤销接口, 然后删除本项目的连接行 (令牌随之删除). 撤销失败 (网络, 4xx, 令牌解不开) 也删, 返回 `{revoked: false}`, 由前端提示到 Xero 后台的 Connected apps 手动移除. 已同步的数据与版本不动, 概览回到 not_connected. 写 data 留痕 `xero_disconnect` (revoked, 组织名).

### 密钥 (验收 2.7)

- 令牌, 授权码与 client secret 不进日志, 留痕, 响应与异常消息: 留痕 payload 只有组织名, 组织数, scope, 表名, 资源名, 原因代码与状态码; 客户端错误消息先把用过的令牌, 授权码, verifier, secret 与 Basic 凭据换成 ***, 再丢掉仍像令牌的值; 连接对象不含令牌, 库里只有 Fernet 密文; state 登记只存哈希, PendingAuth 的 verifier 不进 repr.
- 测试 `test_tokens_code_and_secret_never_leak`: 假令牌, 假授权码, 假 client secret 与 Basic 凭据都是可辨认的假值; 走一遍连接 (含回显授权码与 secret 的换令牌失败), 同步 (中途刷新), 后台同步失败, 失效, 断开 (含撤销失败); 扫各接口响应体与响应头 (含 Location), DEBUG 级日志 (含 httpx 与异常栈), 全部留痕, 概览与 state 登记, 都没有这些值. 断言消息只说 "有密钥出现在输出里", 不带出值.
- 访问日志过滤器单独测 (测试里没有 uvicorn), 含 `--root-path` 前缀的路径; 另测 create_app() 确实装上了 (第 1 轮补). 审核员另用真实 uvicorn 起 create_app() 核对过访问日志 (探针 test_probe_real_uvicorn_access_log_redacts_callback).

## 本地验证 (验收 3, 云端做不了)

真实授权要在本机用 Xero Demo Company 走一次. 令牌, 授权码与 client secret 只在本机 .env 与浏览器里出现, 不要贴进 issue, 回复或日志.

1. Xero 开发者后台 (developer.xero.com, My Apps, 选本应用, Configuration):
   - Redirect URIs 加 `http://localhost:8000/api/v1/integrations/xero/callback` (网页连接);
   - 保留 `http://localhost:8765/callback` (命令行 login 仍用);
   - 应用类型为 Web app 时 client secret 在这里生成; PKCE 应用没有 secret.
2. 本机 `.env`:
   - `XERO_CLIENT_ID`, `XERO_CLIENT_SECRET` (Web app; PKCE 应用留空);
   - `XERO_REDIRECT_URI=http://localhost:8000/api/v1/integrations/xero/callback` (本机 .env 里原来的值多半还是命令行地址, 要改);
   - `XERO_CLI_REDIRECT_URI=http://localhost:8765/callback`;
   - `SETTINGS_SECRET_KEY` 已配 (生成方法见 .env.example);
   - `FRONTEND_URL` 留空 (取 FRONTEND_ORIGIN, http://localhost:5173);
   - `XERO_PAID_ENDPOINTS=off` (应用没开通付费接口时; 开通了可设 live, 连接时会另申请两个 scope).
3. `uv run alembic upgrade head` (到 0009), 起后端 `uv run fastapi dev src/backend/main.py` 与前端 `bun run dev`.
4. 新建一个项目, 期间取 Demo Company 有数据的一段, 过 ACC-01 后进数据管理页.
5. 连接: 点 "连接 Xero", 在 Xero 登录并选 Demo Company (AU) 授权. 回到数据管理页, 地址带 `?xero=connected`, 卡片显示已连接与组织名.
   - 现有卡片 (R282 之前) 已按这三个接口写好, 单个组织时连接, 同步, 断开都能点; 授权给到多个组织时, 要到 R282 才能在页面上选, 之前可在 http://localhost:8000/docs 调 `PUT /data/xero/tenant`.
6. 同步: 点 "重新同步". 返回 202, 表状态先为转换中, 完成后各表有数据, 数据版本 +1, 时间线有 sync 留痕, 体检跑一次并提出补交审批日志. off 时银行账户与银行流水都不写 (已导入的保留), 202 返回四张, 时间线的 xero_synced 写明原因 paid_off. Demo Company 每 28 天重置, 数据与云端快照对不上是正常的.
7. 断开: 点 "断开连接". 状态回到未连接, 已同步的表与数据版本保留. Xero 后台 (Settings, Connected apps) 里本应用的连接已移除. 若页面提示 Xero 侧未能撤销, 到那里手动移除.
8. 可选:
   - 连接后在 Xero 后台手动移除授权, 过 30 分钟 (访问令牌到期) 再同步: 应报授权已失效, 状态变 expired, 重新连接后恢复;
   - 命令行 `uv run python -m backend.adapters.xero login` 仍用 8765 端口回调, 令牌文件与网页连接互不影响.
