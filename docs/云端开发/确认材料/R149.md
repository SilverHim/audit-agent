## 讲解

### 抽样 (验收 1)

R84 已统一为 `services/sampling.sample_point(purpose, key)` 与 `sampled(purpose, key, rate)`, 本条不改代码, 只补确切值的测试 `test_known_points_and_counts`:

| 用途 | 判断 ID | 抽样点 | 0.05 下 |
|---|---|---|---|
| critic | J-CSH-02-1-BA-091 | 0.1453 | 不中 |
| critic | J-CSH-02-1-BA-01 | 0.2221 | 不中 |
| critic | J-GEN-06-1-XJ-626-2 | 0.8845 | 不中 |

J-REV-02-1-X0 至 X1999 共 2000 个 ID 在 0.05 下 critic 抽中 98 个. 需求清单第 13 批删去了 blind 用途的断言, 本条不测 blind 用途 (R84 原有测试里的 blind 一行由 R295 删). rate 的边界 (≤ 0 恒假, ≥ 1 恒真, NaN 恒假) 与重复调用结果相同由 R84 的测试守着.

### 判定顺序 (验收 2)

1. 跳过 (先于一切触发规则): critic 关闭, 没有复核模型, 运行时自主度 L1, L2 (同现状).
2. main: L3, L4 且建议 accept 或 close.
3. internal_copy (collab): 第一轮会给出的证据中非准则指针至少一个, 且可靠性全为 internal_copy. 可靠性取 `given_evidence` 按来源解析后的值 (数据行按类型, 文件按登记), 不采信判断里存的值; 解析不了的指针不算.
4. assumption: 推理链有 assumption 步骤.
5. unsupported (collab): 推理链有 status 为 unsupported 的步骤.
6. sample: `sampled("critic", judgment.id, GEN-09 的 params.sample_rate)`.

都不中记 skipped, critic_reason "未命中独立复核的触发规则", critic_trigger 为空. collab 打开时命中的那条写进 critic_trigger. 单元测试 `test_trigger_order_and_sample` 逐条核对顺序与开关, 准则指针不算证据, 只有准则时 internal_copy 不中.

### Xero 发票判断 (验收 3, `test_collab_triggers_internal_copy_and_unsupported_in_order`, `test_collab_l2_skips_before_any_trigger`)

测试的 Xero 判断 (REV-02, Procedure L3) 的指针为发票行与分录行; 测试辅助的 `invoice_pointer`, `entry_pointer` 补上可靠性 internal_original (同校验器改写后的样子), 用到它们的现有测试断言都不变. 先断言该判断 ID 在 critic 下未抽中, collab 打开:

| 情形 | critic_trigger | 复核模型收到 |
|---|---|---|
| 建议 misstatement, 无 assumption | 空 (skipped) | 无 |
| 指针全换成测试登记的 DOC-IC-1 (发票复印件, internal_copy) 第 1 页 | internal_copy | -r1, -r2 |
| 复印件之外再留一个发票行指针 | 空 (skipped) | 无 |
| 第 1 步 status unsupported | unsupported | -r1, -r2 |
| Procedure 改 L2 (复印件, unsupported, 主规则三种) | 空 (skipped, L2 跳过规则) | 无 |

另测: 主规则命中记 main; 第一轮输出解析不了 (not_applicable) 时 critic_trigger 照留 main.
