# R342 确认材料: 审计助理按工作语言回答

来由: Issue #51 验收 4. 规模 S, 档位 high. 分支 yi-r342, 叠在 R339 (3330352) 上. 不需迁移.

## 改动摘要

- `agents/concierge_chat/service.py`: 回答语言 answer_lang 取总览里项目的工作语言, 读总览时定下 (记在 ChatTurn 上); 系统提示用它; 提问带的 lang 只作界面语言 ui_lang 交给对话图, 决定 tool 事件的提示文字. 留痕 payload 记 ui_lang 与 answer_lang; 还没读到总览就中断的一轮, 回答语言取项目当时的工作语言.
- `loop.py`: ChatContext 的 lang 改名 ui_lang. `memory.py`: Turn 的 lang 改为 answer_lang; 旧留痕没有 answer_lang 时取当时的 lang (那时回答跟它走), 都没有为 zh; 中断的回答按回答语言写明中断. `rule_model.py`: 按系统提示的 "Language:" 行取回答语言 (函数改名 answer_language), 中英文案沿用原有的.
- `prompts/concierge/system.md.j2`: 变量 lang 改名 answer_lang, 说明取项目的工作语言.
- 契约 `contracts/conversation.py`: ConciergeQuestion.lang 注明只管界面文字; ConversationTurn.lang 改为 answer_lang (每轮的回答语言). 接口文档第 6.1 与第 10 节同步; 重新生成 openapi.json 与 src/client (前端没有用到这个字段).
- 测试: tests/test_concierge_chat_service.py (新用例, 规则模型的用例改按项目语言), test_concierge_chat_api.py, tests/chat_fakes.py (project_state).

## 方案取舍

- **两个变量:** 代码里分成 ui_lang (界面语言, 只给工具提示) 与 answer_lang (回答语言, 只给系统提示与留痕), 不再有一个两用的 lang. 请求体字段名 lang 不改 (前端照旧发界面语言), 只改说明.
- **回答语言在一轮开始时定:** 取这一轮读到的总览; 这一轮当中改了工作语言, 下一轮才生效.
- **留痕键:** 新写 ui_lang 与 answer_lang, 不再写 lang. 旧留痕的 lang 当时既是界面语言又是回答语言, 重建时作回答语言的缺省, 不另迁移.
- **ConversationTurn 字段改名:** lang 改为 answer_lang, 说清是回答语言 (接口返回的字段变了, 前端没有用到).
- **mock 回答:** 规则模型照旧读系统提示里的 "Language:" 一行, 这一行改由项目的工作语言渲染, 中英文案不另写.

## 验收对照

1. `test_answer_follows_working_language_and_tool_label_follows_ui`: 项目 zh 界面 en, 回答中文, 工具提示 "Checking engagement progress"; 项目 en 界面 zh, 回答英文, 工具提示 "查看项目进度"; 留痕记两种语言.
2. `test_new_language_applies_to_new_turns_only`: 改工作语言后新一轮为新语言, 旧一轮的回答语言与原文不变. `test_turns_before_r342_read_back_with_the_language_they_were_asked_in` (旧留痕 en, zh, 都没有, 已记的四种). `test_turn_cut_before_overview_records_the_project_language`.
3. `test_system_prompt_states_the_working_language`: 系统提示的 "Language:" 行与末尾的语言要求随项目的工作语言, 与界面语言无关. 规则模型的现有用例改为按项目语言给定 (rule_ask 的界面语言取另一种), 断言不变, 都通过.

变异核对: 回答语言取界面语言, 工具提示取回答语言, 旧留痕不回落到 lang, 中断时回答语言取界面语言, 四个都被上面的用例杀掉.
