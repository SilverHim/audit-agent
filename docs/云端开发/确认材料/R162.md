# R162 确认材料: 等待客户更正与更正通知 (后端)

来由: 草稿 MD-8 拆分的后端部分. 规模 M, 档位 xhigh, 严审. 分支 ding-r162, 叠在 R161 第 1 轮修正 (82708a8) 之上 (原在 88587a3 上开发, 修正后变基: 接口文档校验表一行与 test_misstatement_communication 的装配冲突, 两边都保留). 不需迁移 (decisions 表的 kind 为文本列).

## 改动摘要

- 契约: `CorrectionNotice` (models, 第三种决定); 状态 `correction_notices` (append_unique, 登记缺省值); 总览 `awaiting_correction`, `awaiting_correction_ids` (都带缺省).
- `orchestration/nodes.py`: await_correction 在节点内等更正通知; `awaiting_correction` (等更正的错报), `after_notice` (错报新版本), `apply_notice` (载入更正分录与错报新版本同一事务, 提交后写总账新版本的 data 留痕).
- `orchestration/decisions.py`: submit 收 CorrectionNotice (`check_correction_notice`, `check_notice_fields`, `_write_notice`, `notice_trail`); 决定 ID 查重加更正通知.
- `orchestration/runner.py`: `correction_wait`; review_waits 不含等待更正; resume_required 计入更正通知.
- `orchestration/recovery.py`: `catch_up_correction` (排在复核决定之后). `orchestration/query.py`: 总览两项. `orchestration/waits.py`: `correction_payload`.
- `persistence/models.py`: decisions 表加 CorrectionNotice. `api/errors.py`: NOT_AWAITING_CORRECTION 为 409.
- 重新生成 openapi.json 与前端类型 (总览多两个可选字段).
- 文档: 接口文档第 0 节 (ID), 2.5 节 (模型), 3 节 (状态与节点), 5 节 (DecisionSubmit), 7 节 (更正通知一段, 校验表, 恢复, 等待种类), 9 节 (decisions 表), 10 节 (总览, 错误码); Demo需求文档第 6 节 (等待更正的期限与提醒本版不做).
- 测试: test_correction_notice (新), test_correction_notice_db (新, slow), test_misstatement_communication (装配可改停点), test_state_compat (新通道).

## 方案取舍

- **同一事务的接口形状:** 不改端口. apply_notice 在 output_store.transaction 内调 load_adjustments; Postgres 下各存储共用一个引擎, db.transaction 嵌套为 savepoint, 一起提交或回滚. 连库用例以 "已有内容不同的错报 v4" 触发回滚, 断言更正分录也没载入.
- **data 留痕:** 提交后按 backfill_trails 的取法 (data_service.version_entries) 补写本项目各数据版本的留痕, 同键跳过; 节点写完 Store 后被杀再重放时载入幂等, 不再出新版本, 这一版的留痕由重放补上 (第 1 轮审核后改). data_service 引用 orchestration, 用时再导入.
- **通知写入不另查同版本冲突:** 同复核决定与过期重跑请求, 决定 ID 已经 _check_decision_id 查过, 写入时撞不上.
- **一次执行一份通知:** 部分通知后经 verify_correction 由 after_verify 回来, 载荷只列其余的; 载荷 records 恒为空 (与其他等待同形), 恢复补做只比检查点状态中的通知.
- **"须重新沟通" 的错报:** 载荷只列不须重新沟通的 communicated, 校验只查 "都在载荷中", 不另写一条.
- **等待更正不算等复核:** review_waits 去掉 correction, 总览 awaiting_review 为假, 复核决定报 NOT_AWAITING_REVIEW "当前不在等复核".
- **留痕记在 FIN-08 下:** 验收 2 写明; 摘要为种类与所列错报.
- **校验通知时不查 "等待中的节点出错":** 读回通知后出错时通知已在 Store 而不在检查点, 先报 RESUME_REQUIRED.
- **数据集为空或没有更正分录:** 同报 INVALID_VALUE "没有可载入的更正分录"; 停止等待照常收.
- **测试装配:** 沿用 R161 的 Xero 装配 (at_communicate 加停点参数), 两条 v3 communicated 时分诊与沟通空执行, 直接到 await_correction; 更正分录用 XeroFakeDatasetLoader 预置的补造分录 (只记调用). 帮手用 R161 修正收进 fakes 的 latest, submit_and_wait, entries, record_writers. 总账新版本, 数据版本 +1 与 data 留痕在连库用例里断言 (相对值).

## 审核结论

第 1 轮严审通过 (0 blocker, 0 major), 4 minor, 3 nit, 在 5860e2b 之上一个修正提交:
- R162-01: apply_notice 提交后补写本项目数据版本的 data 留痕 (取法抽成 data_service.version_entries, 与 backfill_trails 共用: 数据集载入的版本不记, 同键跳过), 写 Store 后写留痕前被杀时重放补上; 连库用例 test_data_trail_written_on_replay_after_crash.
- R162-02: 验收 2 的默认用例断言 load_adjustments 调用时在写错报的事务内 (载入移出事务的变异默认用例下被杀).
- R162-03: ports.load_adjustments 与接口文档第 4 节写明在 AuditOutputStore.transaction 块内调用时加入该事务.
- R162-04: 补复核决定 ID 作通知 ID 被拒, 不在等待更正时无理由的 stop_waiting 报 NOT_AWAITING_CORRECTION; 带重新沟通标记的一例构造不出, 在用例 docstring 写明由载荷保证.
- R162-05: catch_up_correction 的两个防御分支各一例 (RuntimeError).
- R162-06: Demo需求文档第 4.1 节, waiting_payloads, test_misstatement_communication 的说法改成现行; 项目没有数据集另报一句, 不拼 None (另补用例).

修正后的变异: 载入移出事务, 重放不补留痕, 不查数据集, ID 查重不含复核决定, 字段先于等待, 补做不查多份或不查等待, 7 个都被杀.
