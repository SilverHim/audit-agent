## 改动摘要

- `tests/external.py` (新):
  - `external_dir(name, has=...)`: 候选来源依次为 `EXTERNAL_DATA_ROOT/<name>`, 仓库的 `data/external/<name>`, 主工作副本 (`main_checkout`: `git worktree list --porcelain` 的第一项; repo 须是列出的工作树之一, bare 仓库时不用) 的 `data/external/<name>`; 取第一个存在且含 has 里全部路径的 (第 1 轮改为按路径逐个来源查); git 不可用时略过第三项.
  - `require_external(name, files)`: 第一个文件齐全的来源; 都没有时 `pytest.skip`, 原因含 `data/external/<name>` 与缺的文件名.
  - `require_xero_snapshot(name)` 取第一个有 `api/<name>/organisation.json` 的 xero 来源, `require_xero_supplements(name)` 取 `data/xero_demo/<name>`. 仓库跟踪了的, git ls-files 列出的每个文件都得在, 缺一个即失败 ("仓库跟踪了快照却找不到" / "仓库跟踪了补造目录却找不到"), 不静默跳过; 没跟踪又找不到时跳过. 两者都在时按补造 manifest 的快照哈希表 (`snapshot.files`) 逐文件核对 (只读表里列的文件, contacts.json 不在表内, 不打开), 不符时跳过 "快照与补造不匹配, 预期值失效", `EXTERNAL_STRICT=1` 时改为失败.

## 讲解

### 为什么要这样

- 外部数据 (Xero 快照, CUAD 合同) 在不同环境里位置不同: 云端或本地的 worktree 里可能没有 (不入库的数据集只在主检出), 也可能用环境变量另指. 以前各测试各拼路径, 找不到就静默跳过: 快照被误删或 worktree 没带上时, 一批测试悄悄不跑, 看起来全绿.
- 现在三条规则: 找得到就用; 找不到时跳过并写明缺什么; 但仓库明明跟踪了这份快照却找不到, 就失败 (这是环境坏了, 不是 "本机没有"). 快照换了而补造没跟着换时, 预期值 (按补造写的金额与命中) 不再成立, 跳过并写明 "预期值失效", 严格模式下失败, 免得拿新快照对旧答案得出误导的失败.
- 真实大模型测试以前只认 .env 文件 (test_e2e_live) 或只认进程环境与仓库 .env (其余两个): CI 或云端常把密钥放在环境变量里, worktree 里又没有 .env. 现在统一一个入口, 认环境变量, 显式指定的 LLM_ENV_FILE 与本仓库 .env, 不去猜别的目录 (第 1 轮: 猜主检出的 .env 在某些目录布局下会读到别的项目的密钥); 两项须在同一来源配全, 都没有时跳过并点名配了一半的来源. live 必须同时标 slow, 保证默认测试 (`-m 'not slow'`) 永远不联网.

### 验收

1. `test_external_dir_prefers_environment_then_repo` (环境变量优先, 指的目录下没有时退回仓库, 都没有为 None), `test_external_dir_falls_back_to_main_checkout` (在 tmp_path 里 git init 一个主检出并 `git worktree add`: worktree 没有时取主检出的, 自己有时取自己的; git 不可用时略过主检出), `test_external_lookup_goes_by_the_wanted_path`, `test_no_main_checkout_outside_own_repository_or_for_bare` (第 1 轮).
2. `test_require_external_skips_with_what_is_missing`.
3. `test_snapshot_hashes_checked_against_supplements`: 相符时返回目录, 只读表里的 organisation.json 与 accounts.json (contacts.json 没被读); 改快照一个字节 → 两个函数都跳过, 原因含 "快照与补造不匹配, 预期值失效" 与文件名; 设 EXTERNAL_STRICT=1 → 失败. `test_snapshot_without_supplements_is_not_checked`: 没有同名补造时不核对 (20261017-mock 即此情形); 都没有时跳过.
4. `test_tracked_snapshot_that_is_missing_fails` (假仓库里提交了 journals.json: 没有 organisation.json 时失败; 从工作区删掉后失败 "仓库跟踪了快照却找不到"), `test_partly_missing_tracked_snapshot_fails`, `test_tracked_supplements_that_are_missing_fail` (第 1 轮); `test_repository_snapshots_are_found_and_match` (本仓库实测: `git ls-files` 列出 q1 的 journals.json, require_xero_snapshot("20261017-q1") 返回目录且与补造的快照哈希表相符, 不跳过).
5. `test_live_settings_from_environment_only` (只设环境变量, 没有 .env → 取到, LLM_MODE live, LLM_BASE_URL 为空, 进程的 LLM_MODE 仍是 mock), `test_live_settings_from_first_env_file_with_both_keys`, `test_live_settings_skip_without_leaking_the_key` (假密钥 "sk-test-0123456789" 只在环境变量里, .env 只有模型名: 跳过并点名两处, 原因与日志都不含值), `test_live_settings_skip_with_only_the_model_in_environment`, `test_llm_env_files_order`.
6. `test_live_without_slow_is_a_collection_error` (直接调 conftest 的收集钩子), `test_markers_registered`. 默认 `uv run pytest`: 本条前 (e8cb472) 收集 2269 个 (2268 通过, 1 跳过), 57 个 slow 被筛掉; 本条后 2285 个 (2284 通过, 1 跳过), 57 个筛掉, 只多出 test_external 的 16 个.
7. `fakes.xero_snapshot()` 改用 require_xero_snapshot("20261017-mock"); 用到它的现有测试结果不变 (默认测试全过); `test_repository_snapshots_are_found_and_match` 断言它取到的是 mock 快照.
8. `test_live_tests_are_marked_slow_and_live` (三个联网用例都标了 slow 与 live). 只设环境变量时取到配置见验收 5 (断言值相等用的是假密钥, 没有输出真实值).
