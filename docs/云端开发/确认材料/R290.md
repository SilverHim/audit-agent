## 偏离需求原文之处

1. AsicExtract 结构扩了: 需求原文写 "按 R129 的 AsicExtract 结构", 又在范围里列了 ABN 与注册地址, R129 的结构没有这两项. 按裁定 7 加了可空的 abn 与 registered_address. 另加 `document_id` 与 `evidence`, 让 ACC-04 的指针指向上传的文件, 页码取抽取时的指针. 都可空或缺省为空, 数据集的 mock 不填, 补造数据不改.
2. 运行中的演示 (mock 模式) 抽不出摘录:
   - DOC-REGISTRY 的固定输出放在上传处理的公共目录 (tests/fixtures/llm_variants/upload), 测试经 LayeredMockLLM 读.
   - 没有同步进运行副本. 新客户读 Numbat 的运行副本 data/demo/llm; 那是 Numbat 数据集目录, 按数据规则不改. tests/fixture_sets.py 的 `UPLOAD_RUNTIME` 也没有加 DOC-REGISTRY.

   - 真实大模型按提示词抽取. 云端没有真实 ASIC 摘录, 也没调真实大模型验证.
   - 要让演示里抽得出, 有两种做法, 留给协调者定: (a) 把 DOC-REGISTRY 加进 UPLOAD_RUNTIME 并重新生成 Numbat 运行副本 (改 data/demo/llm); (b) 另给新客户一个 fixture 目录.

## 讲解

- 新客户的流程 (`test_new_company_waits_for_the_extract_then_checks_it` 跑一次):
  1. 建项目后图从 p0_inputs 开始, 查 ABN: Victoria Property Agency 有 ACN 900043030, 是公司, 还没有摘录.
  2. ACC-04 出新版本, 状态 awaiting_data, data_request_ids [REQ-registry_extract], 写 transition 留痕. A3 体检提出补交请求 "ASIC 摘录" (used_for ACC-04).
  3. 路由回 p0_inputs, 再进来没有变化, `interrupt({awaiting: inputs, procedure_ids: [ACC-04]})`.
  4. 审计师对着请求上传 900043030.pdf: 类型取请求的 (registry_extract), A3 抽取得第 1 版, 记数据变动, 请求转 received.
  5. 上传作业结束时 DataService 以 INPUTS_CHANGED 恢复图. p0_inputs 见到有摘录, ACC-04 回 planned, 往下到 p0_intel.
  6. ACC-04 四项都按摘录通过, 公司两项的指针指向摘录文件 (status, officeholders 页 1, external_copy). 停在 ACC-01.
- 为什么单独成节点: p0_intel 里已有 "ACC-04 失败等人" 的 interrupt(). 同一节点里两种等待共用恢复值, LangGraph 按出现顺序配对, 会串 (同 p1_await_data 的做法).
- 以 Store 为准: p0_inputs 写完 ACC-04 后若留痕失败, 节点出错重来. 重来时 Store 的版本比状态新, 取 Store 那一版, 补写留痕, 不重复写.
- 不等的情形 (都不改 ACC-04, 不写 Store, 直接到 p0_intel):
  - 有数据集 (不查 ABN);
  - 不是公司 (ABN 登记没有 ACN);
  - ABN 查不到;
  - ABN 查不了 (ACC-04 执行时同样待人工确认);
  - 已有一份 registry_extract 文件;
  - 请求标了客户无此类资料.
- ACC-04 对新客户 (`extract_checks`):
  - ABN 查不到或没有 ACN: 公司两项待人工确认, 指针指向 ABN 查询留痕.
  - 一份可用的摘录都没有 (标了无此类资料, 或抽取没成): 记一条 ASIC "没有查询" 留痕 (reason no_extract), 两项待人工确认.
  - 有摘录而 ACN 都对不上: company_registered 不通过 (出例外), directors_match 待人工确认.
  - 有该 ACN 的摘录:
    - company_registered: 状态 Registered 且名称规范化后与画像法定名称相同.
    - directors_match: 画像董事与摘录 director 的姓名集合 (规范化同 name_match) 相同, 秘书不比. 不一致时 detail 列出两边各多出的姓名.
- 旧检查点 (补充裁定 1): 新拓扑读回旧拓扑的检查点, 核对结果如下.
  - 做法: 导出 a3d83b6 的副本, 用旧代码把 Numbat 项目 (画像名称有错字, ACC-04 出 name_match 例外) 跑到 ACC-01 闸门, 存下 InMemorySaver 的检查点, 写入与审计产出. 新代码读回后更新客户资料到第 2 版, `aupdate_state(as_node=gate_acc01)`, 再 `ainvoke`.
  - 结果:
    - 读回时 next 为 ('gate_acc01',), 评分卡第 1 版;
    - 越过闸门后 next 为 ('p0_inputs',), 有数据集直接通过;
    - p0_intel 重跑 ACC-04, 回到 ('gate_acc01',);
    - 执行记录 RUN-ACC-04-1, RUN-ACC-04-2; 评分卡第 2 版, 依据画像第 2 版, 没有例外; 无异常.
  - 其他位置的旧检查点: 停在 p0_intel 内 "失败等人" 的, p0_intel 的节点与出边都没变, 恢复照旧. 进程在 p0_intel 中途退出留下的 (待执行的任务是 p0_intel), 恢复后照旧执行 p0_intel; 新客户这样会跳过一次 p0_inputs, 不等摘录, ACC-04 照 "没有摘录" 待人工确认, 之后的 rerun 照常经过 p0_inputs.
- 数据版本: 抽取 (上传, 改类型, 智能导入确认) 与修改都在同一事务内记数据变动 registry_extracts. 读它的只有 ACC-04, 而 ACC-04 不判过期 (偏离第 3 条).
