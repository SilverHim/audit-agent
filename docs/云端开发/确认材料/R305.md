# R305 确认材料: 审计助理发给模型的数据遮蔽人员节点 ID

来由: 需求清单 R305 (R137 第 1 轮严审意见 01). 基于开发分支 08c952e, 叠在 R307 的提交之上 (两条互不依赖). 普审. 第 1 轮的修正叠在 82b1105 上.

## 改动摘要

- `contracts/models.py` (放在 node_name_part 旁):
  - `mask_person_node_ids(value)`: 结构化数据版本, 是共用函数. 递归处理字典的键与值, 列表与元组, 每个字符串里的 `PER-{姓}-{名}-{yyyymmdd}` 换成 `PER-{姓}-{名}`; 末段为 NODOB 的不变. 在序列化或渲染之前调用, R139, R141 也照此先遮蔽数据再渲染.
  - `mask_person_text(text)`: 纯字符串版本 (错误文本用).
    - 边界: 前面不接字母数字, 8 位日期后不再接数字.
    - 前面是 JSON 转义 (`\n`, `\t`, `\uXXXX`) 时也算边界, 已序列化的文本误交进来也不漏.
- `agents/concierge_chat/tools.py`, 只改出口一处 (`ToolBox.call`):
  - 工具结果先 minimize, 去掉 engagement_id 与 birth_date.
  - 再在 json.dumps 之前做 mask_person_node_ids, 之后再序列化与截断.
  - 错误文本经 `failure` 先 mask_person_text 再序列化.
  - 执行改为私有的 `_run`, 它的结果不得直接外发; 模块说明改为 "minimize 与遮蔽都在 call 出口做".
  - get_evidence 对登记摘录类 (registry_extract) 文件不发 file_name.
  - 引用 (cites) 给前端, 原样.
- 审计助理的系统提示词与接口文档第 6.1 节各加一句: 人员节点 ID 发给模型时已去掉出生日期, 同名者可能显示为同一 ID, 须按关系与证据区分.
- 接口文档第 0 节改写函数的用法: 先遮蔽数据再序列化, 不对渲染后的文本做.
- 用例 (`tests/test_concierge_chat_tools.py`, 本条共 17 例):
  - 两个函数的参数化 6 例;
  - 结构化版本遮键与嵌套值 1 例;
  - 转义前缀 7 例 (换行, 制表符, 回车, 控制字符, 箭头, 汉字, 单引号紧邻 ID; 工具出口与文本版各查);
  - 四种工具结果 1 例;
  - 登记摘录文件名 1 例;
  - 先遮蔽再截断 1 例.

## 方案取舍

- 遮蔽放在 ToolBox.call 出口, 所有工具 (含以后的 GEN-08 关系图工具) 都经这里, 不逐个工具改.
  - 在序列化之前对结构化数据遮 (第 1 轮裁定): 按原文的边界判断, 不受 json.dumps 转义影响.
  - 文本版也认 JSON 转义的前缀, 多遮一些不要紧. 两份审核探针 (工具出口与 tojson 渲染) 都通过.
- 遮蔽后的写法直接去掉日期段. 用不可逆的编号要另存对照表; 用日期的哈希也不行, 日期只有几万种, 能反推.
  - 同名而出生日期不同的两人遮蔽后相同, 写进了接口文档与系统提示词. 后续需求若要求区分, 再给两人编序号.
- 登记摘录类文件不发文件名, 不在出口按文件名规则遮.
  - 人员检索的存档文件名 `{姓}-{名}-{yyyymmdd}.pdf` 没有 PER- 前缀, 而且姓名也在里面.
  - 模型按文件 ID 与类型引用, 用不到文件名. 其他类型的文件照发文件名.
- birth_date 字段直接去掉 (同 engagement_id): 模型用不到出生日期.
- 发给模型的就是遮蔽后的文本: 对话留痕 (llm_call) 记的也是它, 字符预算按遮蔽后的长度算.

## 验收对照

1. 用例里个人节点 ID 都是合成的 PER-MORGAN-ALEX-19790412; R137 未收进来, 关系图取 tests.fakes.ownership_graph.
   - `test_person_ids_reach_the_model_without_birth_dates`: 四种结果发给模型的文本都没有 19790412 与 1979-04-12, 都有 PER-MORGAN-ALEX: 关系图 (整体 model_dump), list_exceptions (detail.via 与 source_ids), search_trail (摘要), 查不到的 get_judgment (错误文本).
   - 同一例里: 关系图节点没有 birth_date, 前端的引用 label 是原文.
   - `test_registry_extract_file_name_is_not_sent`: X-GEN-08-1-R01-1 的证据指向登记摘录 MORGAN-ALEX-19790412.pdf. list_exceptions 与 get_evidence 两次发给模型的文本都没有两种日期写法, get_evidence 结果里没有 file_name; 业务约定书照发文件名.
2. 守卫同时查两种写法; NODOB 的 ID 原样. 参数化用例另查: 单名, 嵌在键里, 前面是下划线, 七种转义前缀, 不是个人节点 ID 的 8 位数字.
3. 审计助理现有用例照过 (见下).
   - 变异核对: 去掉出口遮蔽, 不去掉 birth_date, get_evidence 照发登记摘录的文件名, 文本版不认 JSON 转义: 各有用例失败.
