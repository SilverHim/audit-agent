# R351 确认材料: 基准金额不为正时不列为重要性候选

## 改动摘要

- 契约: `MaterialityCandidate` 加 `not_applicable: Literal["loss", "not_positive"] | None = None`, 即本期不适用的原因. 税前利润为负记 loss, 其余不为正的记 not_positive; 类型别名 `MaterialityInapplicable`.
- A4 (`agents/risk_assessor`): 新增 `inapplicable(basis, base_cents)`. `materiality_candidates` 按它给每个候选标上, 候选仍照常列出, 金额照算.
- 闸门 (`gates.check_materiality`): 仍按基准金额不为正拒绝 (INVALID_VALUE, 消息含基准名), 消息改为 "本期不适用: 基准金额不为正".
- 前端:
  - `lib/materiality` (新): `selectableCandidates` 只取适用的; `initialChoice` 取第一个可选的 (原在 gate-form, 按金额判断).
  - gate-form: 候选列表中不适用的一项显示原因, 不显示比例与区间; 基准下拉只列可选的.
  - 中英文案 `planning.notApplicable` 两条; openapi.json 与 client 重新生成.
- 接口文档: 第 2 节 MaterialityCandidate 加字段说明; 第 7 节校验表一句. Xero 数据集设计第 5.6 节 PLN-01 M01 一行注明 loss.

## 方案取舍

1. **标记不适用, 不从材料里删**: 照 Q18 已定的口径 (候选照常列出, 审计师看得到亏损), 只把它从可选项里拿掉并写明原因.
   - 标记在 A4 整理候选时给 (需求说不在 SQL 里过滤).
   - 金额照算: 材料各字段的含义不变 (区间 = 基准 × 比例); 前端遇到不适用的就不显示区间.
2. **原因用代码不用文句**: 前端按界面语言显示, 免得英文界面混进中文 (同 R349 的问题).
   - 分两个代码: 税前亏损是常见情形, 写得具体; 其余基准为零或为负少见, 共用一句.
3. **闸门按金额判断, 不看标记**: 本条以前存下的候选没有标记 (检查点与 gate_materials 读回为空), 照样被拒. test_decisions 的 loss_making 就是这种没标记的材料.
4. **依据**: ASA 320 第 A5 段 (税前利润不宜作基准时改用收入等其他基准), 已按 docs/参考资料 原文核对. 不为正的基准乘比例得不出重要性.
