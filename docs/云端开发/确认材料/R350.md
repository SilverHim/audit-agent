# R350 确认材料: 闸门材料里的例外明细按金额与比例格式显示

## 改动摘要

- `lib/exception-detail` (新): `detailRows(detail, labels)` 把例外的 detail 逐字段转成显示行.
  - 以 _cents 结尾的按全站金额格式 (formatAud); 以 _pct 结尾的按百分比, 一位小数; 数字串 (数据库 numeric 列的序列化) 一并按数解析, 不是数的照原文.
  - 其余按文本: 布尔取是否; 认得的取值换成文案 (balance_sheet, profit_or_loss); 空值为 "—".
  - 对象逐个字段展开. 数组: 元素是对象的各自展开, 否则以逗号连接.
  - 字段名取文案的标签, 没有的退回字段名.
- gate-form: `ExceptionDetail` 改为按这些行显示一个两列的定义表, 对象缩进一层. 删去只认 PLN-07 一种明细的 `FluctuationDetail`, 以及它用的 `planning.fluctuation` 文案.
- 中英文案加 `exceptionDetail` (字段标签 16 个, 取值两个, 是否).

## 方案取舍

1. **一个通用的按字段显示, 不留 PLN-07 的专用句式**: 原来的专用分支要求金额是数, Xero 的 numeric 列序列化成字符串就落到 JSON 原文 (截图里的现象).
   - 通用写法按字段名后缀定格式, 各程序的明细都适用, 加规则不用改前端.
   - 代价: PLN-07 不再是一句话, 改成逐项列出 (科目, 比较口径, 比较基数, 本期, 变动).
2. **比例只认 _pct 后缀**: 程序 YAML 规则 SQL 的输出列里比例只有 change_pct. 不按数值大小猜.
3. **标签只给常见字段**: 未知字段退回字段名, 不影响显示; 以后看哪些字段常见再补.

   - 未知字段, 空值, 不是数的 _cents, 空的明细.
