## 方案取舍

与验收 1 字面的差异, 协调者 10-20 裁定按推荐做, YAML 注释写明:
- depends_on 先为 []: FIN-08 还没有模板, 程序库不丢弃不存在的依赖. R161 加 FIN-08 时补上.
- manual_result_allowed 先为假: 程序库拒绝 P2 以外的程序开这一项. R165 改为真.
- misstatement_update_kind 不写: 模板字段由 R159 加.
- outputs 不含 exceptions: A8 的写入范围没有 exceptions. 由 R165 产出 V02 例外时一并加.

其余取舍:
- V01 的前缀写成 `CAST(:adjustment_prefix AS text)`. 原因: length 有多个重载, 参数不带类型时 PostgreSQL 推不出 (同 GEN-05 的写法). 语义同验收里的 SQL.
- 校验缺 expected_residual_cents 或 entry_account_codes 时抛 ValueError (`verification_context`). 这是调用方的错, 不算大模型失败: call_llm 在调用大模型之前就查 (审核 R164-05), 同准则片段未注册的 LookupError.
- entry_account_codes 定为匹配凭证各行的科目中错报科目以外的 (错报没有科目代码时为全部, 审核 R164-03 的做法 (1)). 这样子集校验同时挡住错报科目本身, 不另加上下文字段; other_accounts 另查不重复. R165 照此传入.
- 提示词把规则算出的已更正额与剩余额交给模型, 写明不要另算. 模型只判断更正是否完整, 以及对其他科目的影响是否恰当.
- 剩余额不为 0 的情形按 R165 验收 5, 6 的口径写进提示词 (审核 R164-02): 部分更正, 方向相反或没更正, 超额. 建议动作: 部分更正可 accept 并在结论写剩余额; 规则对不上 (V02) 且输入不足以认定新错报时 more_evidence; 更正分录本身造成新错报 (其他科目, 或超额更正错报科目) 时 misstatement. T12 不限制, 只写指引, 不加校验.
- "不写科目代码" 的守卫查规则 SQL, 参数与提示词中有没有 3 到 4 位的数字. 不查 YAML 注释 (注释里有 "ASA 450" 等段号).
