## 讲解 (按验收)

1. 接口: 200 TaskPresentation, 字段恰为验收列的 12 项 (`test_dispute_shows_both_sides_evidence_union_and_records_each_opening` 按字段集合守住, 防日后加上比较两方或推荐决定的字段). 任务不存在 404 NOT_FOUND 且不写留痕; 项目锁被占 (主图在执行时就是这样) 与项目已锁定时照常 200 并写留痕; 仲裁之后已决定的任务也可呈递 (`test_normal_task_deferral_missing_busy_and_locked` 与争议用例).
2. 留痕: 每次调用一行 kind presentation, actor 为当前用户, procedure_id GEN-11, run_id 为任务的 (RUN-CSH-02-1), summary "呈递复核任务 {task_id}", payload 恰为 {task_id, task_version, target_type, target_id, target_version}, 不带 idempotency_key: 连调两次写两行, ID 不同. 前后 Store 的对象与提交次数, 检查点 ID 都不变. 呈递时间可注入 (`test_presentation_entry_time_is_injected`, 供 R153 用).

### 方案之外的取舍

- 工作台在相关查询都返回后才确定当前事项 (第 1 轮审核后取代原先的 0.8 秒计时器): 各查询陆续返回时, 当前事项会先闪过一条复核任务 (补交资料还没读到, 随即换成补交资料卡), 先定下来就会给审计师并没打开的任务记一次呈递. 表单页没有这个问题, 打开即呈递.
- 争议两方并排时, 功能 collab 打开且任务待决, 判断卡不显示两方的建议动作与错报草稿: 决定卡的 "两方的建议" (R150, 取复核队列) 已并排显示, 同一字段只取一处 (Q4). 已决定的任务 (表单页不出决定卡) 与 collab 关闭时在两栏里各显示本方的 (第 1 轮审核后改).
- 带对象的失败卡标题改为 "{对象} 的判断没有做成": 这类任务的执行记录是成功终态, 原先写 "第 1 次执行失败" 与 "没有记录失败原因" 都不对. 整次执行失败的卡照旧 (原因已在执行记录上, 呈递的 failure 不重复显示).
- PresentedFailure 多给 trail_id (取的那行 llm_call 留痕), 便于追查; 验收没要求.
- TaskPresentation 不带 draft_rules: 验收的字段表没有, 决定卡照旧取复核队列的.
