来由: 草稿 MD-14; critique C6, C7; 决定 2; T10 (并入 R154 的两点). 规模 M, 档位 xhigh, 前置 R168, R83, R81, R11. 只在功能 autonomy 打开时生效, 关闭时现有行为与测试都不变; 不改 contracts/ 与 API.

## 改动摘要

- `agents/base.py`, `main.py`: AgentDeps.autonomy (AutonomyPolicy), 组装根按 library 建一次; `tests/fakes.make_deps` 随换掉的程序库重建.
- `orchestration/nodes.py`: 新函数 `assembled_procedure` (P2 程序第 1 版: 关联目标, 功能打开时为装配级降级的级别与理由), assemble_pack 改用它; 测试台 `tests/xero_harness.run_programs` 原来自己拼一份, 也改用它.
- `agents/judging.py`: `downgrade` (判断级降级) 与 `judging_steps(deps)` (功能打开时换上 downgrade, 关闭时 DEFAULT_STEPS); 步骤另收该对象的规则例外; A6 (`fieldwork.py`) 改用 judging_steps.
- `services/review_queue.py`: `missing_evidence` (关键证据缺失); classify 在功能打开时把它也算作交人; `subject_amount` (交易行金额) 从 `api/routes/reviews.py` 挪来, 复核档位与降级共用.
- `services/features.py`: 常量 AUTONOMY.
- 文档: 接口文档第 3 节 (程序执行范围), 第 5 节 (自主度降级的接入一条, 需要人表加一行), 第 6 节 (AgentDeps, 判断公共流程); Demo需求文档第 6 节.

## 方案取舍

- **AutonomyPolicy 放 AgentDeps**: 同 queue, judgments, 组装根建一次, 节点与 Agent 共用. 开关仍看 features (同 collab, planning), 不拿 "为空" 表示关闭, 免得两处说法.
- **fixed_procedures 不改**: 它建的程序 (P2 以外) 都没有关联目标, 按规则不降级, 调用 assembly_level 只会得到模板级别. P2 固定集 (GEN-05, GEN-02) 经 assemble_pack, 同样不降.
- **降级步骤收规则例外**: 本次执行刚建的例外 (CSH-02 的 D01, D04) 不在状态中, 判断金额要它们; 与 A7 收的同一组. 交易行金额照复核档位的取法读行, 所指错报与执行重要性取状态.
- **关键证据缺失受功能 autonomy 控制**: 规格书把它列在第 7.4 节降级表的判断时点; 不受控的话功能关闭时 L3 判断的自动关闭也会变. classify 收参数 key_evidence, 由 judgments_patch 取 judging_steps(deps).key_evidence (第 1 轮 R170-05: 开关只在 judging_steps 读, 不再读程序库的功能集). "取得" 按验收写法: 受支持步骤里有该种类的指针, 不看可靠性.
- **争议优先不另写**: classify 原本先看 inconsistent, 降级只改级别与理由.
- **验收 4 怎么到 L1**: Numbat BA-01 置信度 0.65 只命中 low_confidence (L3 → L2). 用例把执行重要性设为 40,000 澳元, 函证差异 50,000 超过, 才到 L1; 对照组运行时 L2, A7 跳过, 置信度 0.5625.
- **验收 6 越过下限**: 默认表从 L3 最多降两级, 正好到 L1. 用例把模板的 unsupported_steps 覆盖为 −2, L3 −1 −2 截在 L1.
- **验收 8**: 由 Xero 的 BA-091 覆盖 (模板 L3, 程序 L2, 判断 L2 [high_risk]). 功能关闭时判断取程序级别, 由 R83 的 test_judging 用例覆盖 (模板 L2, 程序 L3 与 L1).
