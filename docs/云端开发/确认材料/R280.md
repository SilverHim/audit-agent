## 讲解

### 业务背景

- R272 之后, 缺资料的程序会一直等. 客户确实没有某类资料 (如本年没有保留发运单) 时需要出口, 否则流程永远停在等数据.
- 出口要留下审计师知情的记录: 理由必填; 等它的程序记 "未执行 (无数据)", 与 "测过无异常" 分开; FIN-01 材料列出, 由审计师在决定意见时考虑. 不拦截 FIN-01.

### 标记 (`DataService.mark_unavailable`)

- 在 `holding(eid, [])` 内做:
  - 取项目锁, 补写留痕.
  - 结束时图若在等程序要的数据就交锁恢复, 与导入同一条规则 (R272).
  - labels 为空, 不计进 "处理中".
- 按顺序拒绝:
  - 锁定 423, 忙 409.
  - 请求不存在 404.
  - 理由去首尾空白后为空 422 MISSING_FIELD (同改分类的写法).
  - 不是 open 409 REQUEST_NOT_OPEN (已有码, 同 "稍后处理").
  - 就绪必需的三张表 422 INVALID_VALUE: 它们由 P1 等数据保证, 前端也不给入口.
- 通过后:
  - 请求转 unavailable, 记理由 (去首尾空白), 标记人, 时间, 经 `DataStore.mark_unavailable` 写入 (只改仍为 open 的; 读过之后被改了报 REQUEST_NOT_OPEN).
  - 写 data 留痕 `request_unavailable`: actor 为审计师, 摘要 "客户无此类资料: 发运单", payload 带 reason 与 used_for.
- 标记是定论 (选择题 2): `reconcile` 不重开也不改 unavailable 的请求; 客户之后又给了资料, 照常收进数据管理, 已记未执行的程序不自动重做. 本版没有撤销入口.

### 程序转 no_data (`inputs.input_versions`)

- 现有资料 (`OnHand`) 多了 `unavailable`: 标了客户无此类资料的资料, 由 `resources` 读请求得到.
- 直接一层: ids 中 planned, executing 或 awaiting_data 的程序, 缺的资料里有 unavailable 的 → no_data, data_request_ids 为这些请求 ID. 还缺别的也不再等: 缺了这一项本来就不能执行.
- 传播 (选择题 1):
  - 在整个程序包里, 状态为 planned, executing 或 awaiting_data 而前置为 no_data 的, 也记 no_data, data_request_ids 为前置的并集, 按 depends_on 顺序.
  - 反复扫到不动点, 链上的下游逐轮跟上, 后变成 no_data 的前置也并进来, 与程序包顺序无关 (第 1 轮 R280-06).
  - 例: 没有发运单 → REV-08 no_data → REV-02 no_data; 没有合同 → DOC-04 → REV-03.
  - 传播不限于 ids: await_data 只重查等数据的程序, 而 REV-02 可能是 planned (前置未完成), 也要跟上.
- no_data 不在可重定的状态里, 是终态.
- 状态变为 awaiting_data 或 no_data 时跑一次 A3 体检, 让请求跟着变 (见下).
- after_fan_in: P2 程序全部结清 (completed 或 no_data) 且没有程序在等数据 → completion. 依赖 no_data 的程序已被传播成 no_data, 不会卡在 planned.

### 请求的撤回 (withdrawn)

- 程序都转 no_data 后, 只有它们要的其他资料 (例: 只有三张表时标发运单, REV-08 与 REV-02 都不执行, 销售发票就没人要了) 不该再挂着 "待补交", 也不能算 "已收到".
- `reconcile` 传入现有资料, 待补交而这次不再需要的请求:
  - 资料现在有 → received (原规则).
  - 是体检请求的资料 (在 USED_FOR 中: 必需三张表, 审批日志, 报表草稿) → received. 保持 R15 原规则, 例如审批人随总账一并补上.
  - 否则 (程序请求而资料仍没有) → withdrawn.
- withdrawn 写 `request_withdrawn` 留痕. 之后又有程序要它时照原规则重开.
- 不传现有资料的调用 (R15 的测试) 一律按收到, 行为不变.

### FIN-01 材料

- `gates.fin01_view` 从程序包取 no_data 的程序, 按编号:
  - `requests` 为其 data_request_ids 对应的请求 (含理由, 标记人, 时间).
  - `via` 为传来理由的前置: 模板 depends_on 中同为 no_data, 且 data_request_ids 与本程序的有交集 (第 2 轮 R280-10 改; 只按记 no_data 时存下的理由列).
- 审计助理读闸门材料 (get_gate) 自然带上.
- 前端 FIN-01 一节列出: 程序编号与名称, "前置程序 X 未执行", 资料名与理由.

  - 弹框写明后果 ("等这项资料的程序将记为未执行, 并列入完成阶段的材料"), 理由去空白后非空才能确认; 成功后提示并刷新.
