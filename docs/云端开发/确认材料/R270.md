## 讲解

- **为什么不核对哈希.** 概览在处理中每 3 秒轮询一次. 完整核对要读约 90 个补造文件和快照算哈希, 太慢. 所以 available 只看目录在不在. 发起导入时 DataService.demo_import 照常完整核对, 篡改报 INVALID_VALUE (R269).
- **suggested 的判断.**
  - 闸门用 R291 的 gate_now, 等数据用 runner.awaiting_data (confirm_ready 与总览用的同一判断). 都是现成的.
  - 只有 available 时才读检查点. Numbat 与新客户的概览 (含连库测试里 GraphRunner(None, ...) 构造的服务) 不碰检查点.
  - 自己跑了 -m slow, 全过.
- **为什么 stages_done 读全部留痕, last 用 last_of.** 已导入阶段要看每一条 demo_import; 最近一次结果按裁定用 last_of. 两者都只在 available 时读.
- **补登记表单只提交改了的项.**
  - 后端的 None 是 "不改", 本版不支持清空文件日期, 所以清空日期视为没改.
  - 关联对象用逗号 (含中文逗号) 或换行分隔.
  - 都没改时前端提示至少改一项, 不发请求.
  - INVALID_VALUE 附后端的说明 (如关联对象重复).
