# R346 确认材料: 闸门决定后刷新时 GET /gate 报 404

来由: R315 开发截图时报告, 各道闸门原来就有. 规模 S, 档位 high. 待拍板 Q30 取选项 1: 不在闸门是常态, 不再当错误回.

## 改动

- 后端 `api/routes/gates.py`: GET /gate 不在闸门时回 200, 响应体 null (返回类型 GateView | None); 停在闸门但材料缺失仍 404 NOT_FOUND (查询抛 LookupError, 经 catch_api).
- `api/errors.py`: NOT_AT_GATE 进错误码表为 409, 去掉 http_for_decision 里按码改 409 的特例与 "GET 闸门由路由单独返回 404" 的注释; `api/routes/deferrals.py` 不再显式传 status=409.
- 前端 `components/gate-form.tsx`: useGate 去掉对 NOT_AT_GATE 的不重试判断; 表单视图 (GatePanel) 的 "当前没有待作出的阶段决定" 改看 `data === null`. 其余用处 (工作区, 计划页, 客户页, 签发表单) 只读 `gate.data?.…`, null 与 undefined 一样处理, 不用改. 前端已没有按 NOT_AT_GATE 判断 GET 结果的代码.
- openapi.json 与 src/client 由 generate-client 重新生成 (GET /gate 的 200 为 GateView | null, 说明文字).
- 接口文档第 10 节: GET /gate 一行改为 "GateView; 不在闸门 200 null; 停在闸门但材料缺失 404 NOT_FOUND"; 错误码表 404 一行删去 "NOT_AT_GATE（GET）", 409 一行 "NOT_AT_GATE（POST）" 改为 "NOT_AT_GATE".
- 测试: test_api 的 404 参数化去掉 gate 一项, 新增 `test_gate_not_at_gate_returns_null`; 演示走通的两个驱动 (test_demo_walkthrough, test_demo_walkthrough_live) 原来靠 200 判断在闸门, 改为另断言响应体不为 null. R88 的 NOT_OK_ROUTES 已随盲判过滤一并删去 (d84d018), 没有可改的. 其余引到 GET /gate 的用例 (test_xero_profile.at_gate 等) 按 200 取 json, null 即不在闸门, 照过.
- 浏览器走查 (R345, `tests/e2e/walk.mjs`): 去掉对 "GET /gate 404 NOT_AT_GATE" 的特殊处理 (原来不算失败, 只记进 known 计次), 连同结果里的 known 与报告的 "不算问题的已知情况" 一栏 (`tests/e2e/harness.write_report`); 现在任何 4xx 都记为该步的失败请求.
- 前端没有加用例: 不在闸门已不是错误, 没有要单独测的纯函数; 行为由下面的浏览器走查核对.
