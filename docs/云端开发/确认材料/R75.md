## 讲解

### 业务背景

- 计划第 1 节决定 1 定下: 新程序与新机制 "后接入". 新程序包括 A7 复核, 降级, 新闸门与新节点. 它们都按功能名开启, 关闭时系统与现状一致.
- 这样 Numbat 回归可以一直跑现有 17 条程序, 各功能组也能分批接入.
- A7 独立复核 (GEN-09, cedb576) 现在默认开着. 本条把它登记为基线功能 critic, 缺省开启.
- 所以 Numbat 回归说的 "全关", 是关掉全部新功能而保留 critic. R55 的 GEN-09 计数 (2 行) 与 BA-01 置信度 0.65 都不变.

### 登记表 (`services/features.py`)

| 功能 | 内容 | requires |
|---|---|---|
| critic | A7 独立复核 GEN-09 (基线) | |
| collab | 智能体协作增量: 争议中状态, 判断呈递, 停留时长 | critic |
| journals | GEN-05, GEN-02 | |
| related_parties | GEN-08, GEN-03, GEN-01 | |
| going_concern | GEN-07, GEN-06, GEN-04, FIN-02 与 gate_fin 两步, 报告持续经营段 | |
| misstatement | FIN-03, FIN-08, FIN-09, 等待更正, FIN-04 按状态累计, P3 骨架节点 | |
| autonomy | 动态降级, 盲判, 盲测抽查 | |
| acceptance | ACC-08 与其闸门 | |
| planning | PLN-15, PLN-19 与其闸门 | misstatement |
| presign | FIN-12, FIN-15, FIN-07, FIN-18, FIN-10, RPT-08, RPT-07, 签字前清单 | misstatement |

- requires 是建议值, 各组的首条需求可改.
- 通用化改动与人工处理队列机制不设开关.
- `parse_features("critic, journals")` 按逗号拆分, 去掉空白与空项. 空串为空集, 即全部关闭, 含 critic.
- `check_features` 有两种报错, 都抛 ValueError:
  - 未登记的名字, 如 "未登记的功能: foo".
  - requires 不满足, 如 "功能依赖不满足: presign 需要 misstatement".

### 配置与组装

- `FEATURES: str = "critic"`.
- `Settings.features` 拆分并校验. build_deps 第一步就取它, 所以名字写错时应用不启动.
- `ProcedureLibrary(KNOWLEDGE_ROOT, features)` 与 `AgentDeps(features=features)` 用同一个功能集.

### 程序库

- 启用条件: 模板 feature 为空 (基线), 或在 features 中. 模板写了未登记的名字时, 构造即报错, 消息为 "程序编号: 名字".
- 各方法只看启用的模板:
  - `all()`: 启用的模板, 按文件名顺序. 所以固定集 (runner.fixed_procedures) 不含未启用的程序.
  - `match`: 装配不会匹配到未启用的程序.
  - `closure`: 只在启用的模板中补依赖. 传入未启用的程序抛 KeyError.
- 不限是否启用的方法:
  - `load`: 旧项目的程序包与留痕可能引用未启用的程序.
  - `all(include_disabled=True)`: 含未启用的模板.
- 依赖 (第 7 批的裁定): 启用的模板对未启用模板的依赖一律丢弃, 不分 P2, P3.
  - 启用视图中的 depends_on 不含被丢弃的依赖. load, all, closure 与调度 (scheduler, graph 读 load(pid).depends_on) 都看到同一份.
  - 依赖指向根本不存在的程序时, 行为同现状.

### Agent 与节点

- `build_agents`:
  - 缺模板检查对全部模板 (含未启用的). 所以 YAML 被删时仍报 LookupError.
  - 只映射启用的程序. critic 关闭时 GEN-09 不在映射里; A6 仍直接调用 ReviewAgent.review.
- `ReviewAgent.review`: 第一项判断就是 `"critic" not in deps.features`. 成立时记 skipped, 理由为 "功能开关 critic 关闭, 不做独立复核". 不调复核模型, 置信度保持 A6 给出的值.
- `node_procedures(node, pack, library)`: 按 NODE_PROCEDURES 的顺序, 只取程序包中有的程序.
  - 挂了功能名的程序不在程序包中时跳过: 未启用的程序不在固定集里, 所以节点不执行它们.
  - 旧项目的程序包缺后来新增的程序时, 也不会再抛 StopIteration 或解包错误. 这对应 verify G3 的在途项目兼容.
  - 基线程序 (feature 为空) 不在程序包中是程序包出错, 抛 LookupError, 由 runner 记入 run_error, 不静默跳过.
- `GraphNodes.run_node(state, node, phase)`: 依次执行, 后一条在前一条的结果之上执行. 原来 p1_analytics 就这样执行两条, 现在五个节点共用.
  - completion 的 phase 每条都带. 第二条起阶段已是 P3_Completion, 不重复留痕.
- recover 补做仍按 NODE_PROCEDURES 定顺序. 过滤只去掉不在程序包中的程序, 不改相对顺序.

### 主图

- `compile_graph` 传 `nodes.deps.features` 给 `build_graph(nodes, features)`. 本条不按功能加节点, 由 X-06 与各组加.
- 基线结构守卫 (`tests/test_graph.py`):
  - 节点 18 个: 16 个业务节点加起止.
  - 29 条边: 每条写死起点, 终点, 是否条件边与出口名.
  - 静态中断为 4 个闸门.
  - 各组以后加节点时这张表不变.
