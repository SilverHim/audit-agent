## 方案取舍

- 遮蔽放在 call_llm 一处: R01 的 detail.via 与 links 都带人员节点 ID, 只遮 data 漏 rule_findings. 一处也覆盖 A7 与以后的 GEN-01; 留痕里也是遮蔽后的文本.
- data 比验收 4 多两项, 都很小:
  - client_profile {id, applicable_framework}: 画像指针要 ID, 提示词要框架值.
  - reporting_entity {id, name}: 模型要知道 links 里哪个端点是报告主体.
- C01 的三种来源列不同, 每行为 {source_type, party_key, record (jsonb)}, record 只放该来源的列. UNION 去重. 不带录入时间 (to_jsonb 的时区写法随会话设置) 与交易后余额.
- 银行流水同分录用 "整词含" (验收只写 "含"), 免得短名称命中长词.
- persons 带 id (提示词里是遮蔽后的写法) 与 links_with_entity (该人与报告主体之间的关系, 写法同 links, 带报告主体摘录那一行的指针): 用来与 links 对上, 也让模型能引报告主体的摘录 (R140 的证据含 Demo 摘录第 1, 2 页); 没有出生日期字段. 变基后另加的 fix 提交改的就是这一项 (原先只给关系的文字, 引不到摘录).
- document_reads 同 GEN-02 列全部可作证据的类型 (关联文件按 related_ids 取, 类型不定). 代价是补登记任何证据类文件, 不论关联谁, 都让 GEN-03 过期.
- 自查 (协调者要求): data 不带登记摘录的页面文字. 合同只给登记, 不给页; 关联文件里的登记摘录 (registry_extract) 不给. Xero 的摘录没有关联对象, 本来就不进 documents; 但审计师补登记关联对象后会进来, 摘录第 1 页印有长日期写法的出生日期 (12 April 1979), 人员检索的文件名带 yyyymmdd, 遮蔽都管不到. 所以在 R139 里就排除; 摘录的内容已在关系图 (links) 里.
