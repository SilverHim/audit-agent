## 方案取舍

- GEN-08 的代码单放 agents/ownership.py, evidence.py 只做分派. 两条程序没有共用的逻辑, 合在一个文件有六百多行.
- 申报清单比对 (按协调者裁定):
  - 申报项有 acn 或 abn 时按 ACN 比 (abn 取后 9 位).
  - 两者都没有时按名称比, 两边经 services/party_names.party_name_key: 不去前缀, 后缀取参数 entity_suffixes [pty ltd, pty limited, pty, ltd, limited], 同 GEN-05. R132 没有定义后缀常量, 所以这份列表写在 YAML 参数里.
  - 申报清单取 related_parties 与 ownership 中 kind 为 company 的项.
  - 规范化后为空的名称 (party_name_key 返回 None: 只有非拉丁字母, 或只剩公司后缀, 含非拉丁名加 "Pty Ltd") 不参与比对, 不算相等; 带附加符的名称按 R132 修正去附加符后比 ("Café" 同 "Cafe"). 五种情形见 `test_names_without_a_key_never_match`.
- 没有 ACN 的公司节点为 ORG-{名称}. 查不到摘录, 没有 ACN, 或超过 max_depth 的公司照样建节点 (searched 为假) 与关系, 不再往下穿透, 不抛错. 它们的 R02 由 R138 出, 届时只需加例外.
- searched 定为 "取得了登记结果": 查了而查不到也为假. 需求只写了 Sam 不检索为假; 这样定, R02 的公司与没检索的人在图上口径一致.
- 人员合并在同一份摘录内按规范化姓名 (同 R136 的 node_name_part). 不同摘录之间靠节点 ID (含出生日期) 自然合并. 例外是由某人的检索结果发现的公司: 其摘录里与该人同名的股东行并入该人的节点 (审核意见 03). 其余只持股的同名者不跨公司合并, 免得把不同的人并成一个.
- R01 的范围是发现的公司 (母公司链, 经人员检索发现的). 不含持股低于 significant_pct 的法人股东, 也不含人员检索发现的公司摘录里其余的法人股东: 它们只建节点与关系, 不出 R01 (审核意见 05, 06 的裁定). 人员节点不出 R01.
- R01 的 via_relations 取 via 与该公司之间的关系 (人员为其任职与持股; 母公司为其股东行), 写法如 "shareholder 0.5".
- 客户 ABN 查不到或没有 ACN 时, 写完那行留痕后抛 LookupError (即 R138 验收 3 的抛错一侧). 失败任务由 A1 照常代写.
- 存档时登记的状态直接为 extracted: 结构化结果从登记取得, 不经抽取. 渠道沿用缺省的 auditor_upload: DocumentChannel 没有 "登记" 一类, 加取值属于改契约, 超出本条范围. 上传人为空, 视作系统存档.
- 按留痕幂等重建 (find_success) 与关系图的版本号 +1 都留给 R138, 本条每次执行都查询, 图为第 1 版.

## 审核结论

第 1 轮严审通过 (7 条 minor, 3 条 nit). 按协调者裁定在 fix 提交里改 (09 不改):

- 01 人员检索那行留痕的摘要只写检索序号 (`ASIC person search #1`), 不带姓名与出生日期. `test_xero_penetration_order_and_trail` 加断言: 各行摘要不含出生日期 (ISO 与 yyyymmdd) 与姓名. 审计助理外发时遮蔽人员节点 ID 由 R305 做.
- 02 探针的 7 个 gap 用例挪进仓库:
  - `test_declared_check_uses_the_adopted_profile_version`: 两版画像, 采用 v1.
  - `test_declared_numbers_take_priority_over_names`: 只给 acn; acn 或 abn 不同而同名, 共 3 组.
  - `test_secretary_with_birth_date_is_searched`.
  - `test_shareholder_rows_merge_by_normalised_name`: "MORGAN, Riley" 并入 "Riley Morgan".
  - `test_undeclared_shareholder_without_acn_gets_r01`: Kiwi 未申报, acn 为空.
  - `test_client_without_acn_fails_after_recording_the_lookup`: 改为断言留痕先写, 那一行的 payload 与幂等键.
  - test_contracts 的节点 ID 用例: `organisation_node_id` 名称规范化后为空时抛错.
- 03 由某人的检索结果发现的公司, 其摘录里与该人规范化姓名相同的股东行并入该人的节点 (`build_graph` 以检索对象补足合并表). `test_shareholder_only_role_stays_on_the_searched_person`: 不再有 PER-MORGAN-ALEX-NODOB, R01 的 via_relations 为 ["shareholder 0.3"].

- 05, 06 合并裁定:
  - 母公司链 = 持股不低于 significant_pct 的法人股东逐层向上 (`parents` 按比例筛).
  - 低于阈值的只建节点与关系, 不查询, 不检索其高管, 不出 R01.
  - people 只取高管; build_graph 股东分支的出生日期删去.
  - YAML 注释与接口文档第 6 节写明原因.
  - `test_small_corporate_shareholder_is_not_penetrated`: 5% 的法人股东.
  - Xero 与 T6 用例不变.
- 07 接口文档第 8.1 节 outputs 与 document_types 两处补 GEN-08. YAML 删去 reads, 第 8.1 节 reads 一处写明由 R138 加.
- 08 冗余:
  - 去掉 search 的 pending 与 taken, 以及 search, parents 里的去重字典 (由 reach 去重, 留首次出现的).
  - searches 只记有没有结果.
