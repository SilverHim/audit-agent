## 改动摘要

- `knowledge/procedures/PLN-07.yaml`:
  - reads 加 `journal_entries` (A03 读总账; 加载校验要求 SQL 里出现的账表都在 reads 中).
  - params 加 `employee_expense_categories: [employee_expenses]`.
  - 新规则 A03 (emit rows, severity low, 不出例外): 总账分录中入账日期在 [period_start, period_end] 的行按月汇总, 审计期间的每个月一行: month (月初日期), revenue_cents (revenue_categories 的贷减借), expense_cents (类型 expense 的借减贷), employee_expense_cents (employee_expense_categories 的借减贷, 含在费用里); 按月升序, 没有分录的月份三项为 0 (第 1 轮改). 规则前加注释写明口径.

- `agents/risk_assessor.py`: `monthly_figures(rows)` 由 A03 的行出月度表 (按月排序, 金额为空记 0, SQL 的 Decimal 转整数分); PLN-07 的分析结果带上 monthly.

## 偏离需求原文之处

1. 需求范围没写 reads: A03 读总账, 加载校验要求 reads 含 journal_entries, 所以加上. 随之 R274 的过期口径变了, 让 PLN-07 过期的写入有三类 (计划阶段的过期只标记, 不可重跑, 同 R274; 没有程序 depends_on PLN-07, 不会传到 P2): (a) 单独重新导入总账 (同步本来就写科目表与试算表, 原先就过期); (b) 导入审批日志 (table_changes 另记 journal_entries, A03 不读审批列, 是多标, 与 CSH-02 原有的多标同理, 过期按表判断, 不细到列); (c) 管理层更正分录载入 (insert_adjustments 只写总账): Xero 的 AJE-X01 至 X05 记在 2026-09-30, 改变 9 月的月度数, 是真的过期. 更正通知接入编排后, FIN-01 材料的 stale_procedure_ids 会列出 PLN-07 (只作标记, A01 与 A02 的试算表口径其实没变), 那条需求与后续端到端验收应按此预期. 范围外改了 `test_rerun_stale.py` 两处期望值.
2. 范围外改了 `test_nodes.py` 的 PLN-07 参数快照 (多一个参数).

## 讲解

### 业务背景

- PLN-07 是计划阶段的初步分析 (ASA 315, ASA 520 的分析程序用于风险评估): 除了逐科目的期末波动 (A01) 与比率 (A02), 审计师还要看本期收入与费用按月的走势, 找异常的月份 (如期末月收入骤增可能有截止问题, 费用骤增可能是年末计提).
- A03 只出取数, 不出例外: 月度表放在 PLN-01/03 闸门页供审计师判断, 之后 GEN-04 (G3), FIN-15 F02 (G6) 读同一份月度数.
- 来源是总账分录 (不是试算表): 试算表只有期末余额, 按月要看发生额.

### A03 的口径 (验收 1, 2)

- 入账日期在审计期间内 (含首尾两天) 的总账分录, 按月初日期分组.
- 收入: 科目标准分类在 revenue_categories (缺省 [revenue]) 中, 贷方减借方 (收入为贷方余额, 取正). 与 A01 门槛, A02 毛利率用同一参数, 4200 利息 (other_income) 不算收入.
- 费用: 科目类型为 expense 的全部科目, 借方减贷方 (含销售成本, 员工费用, 折旧, 所得税等, 与试算表本期费用类合计口径一致).
- 员工费用: 科目标准分类在 employee_expense_categories (缺省 [employee_expenses]) 中, 借方减贷方. Numbat 为 6100 工资.
- 审计期间的每个月都出一行 (第 1 轮改): 没有分录的月份三项为 0, 整月缺分录 (如导入的总账漏了一个月) 在表里看得出来; 期间从月中起止时, 首尾两个月只计期间内的分录. 某列在该月没有分录时 SQL 给 0, Agent 对空值也记 0.

### 验收

1. Numbat 离线 (FakeRuleEngine 预置, `test_pln07_monthly_table_from_a03_rows`): ANALYTICS v1.monthly 12 行, 2025-07 至 2026-06 依次为需求所列 (首月 88000000 / 77321600 / 9566600, 末月 150000000 / 188462400 / 12767400); 收入合计 1200000000, 费用合计 1096400000, 员工费用合计 118000000, 同本期试算表.
2. Numbat 连库 (slow, `test_pln07_a03_monthly_figures_from_journal`): A03 SQL 对 data/demo 得到与验收 1 相同的 12 行 (NUMBAT_A03_ROWS 逐列相等). 另验: 期间缩到 2025-08-01 至 2026-05-31 时首尾两个月不出, 其余不变; 期间为 2025-07-16 至 2026-06-15 时仍是 12 个月, 中间 10 个月不变, 7 月收入与 6 月费用变小; employee_expense_categories 给空列表时员工费用列都为 0; revenue_categories 加 other_income 时每月收入加上储蓄利息; 期间从 2025-06-01 起多出一行 2025-06 (三项为 0); 删掉 2026-02 的全部分录后 2026-02 三项为 0, 其余不变.
3. 没有 A03 行时 monthly 为 [] (`test_pln07_without_a03_rows_has_no_monthly_table`); 行中某列为空记 0, 行不按月给时按月排序 (`test_monthly_figures_sort_by_month_and_count_nulls_as_zero`); 不含 monthly 键的旧 AnalyticsResult JSON 读回为 [], 新结果经 JSON 与检查点序列化读回相等 (`test_old_analytics_json_reads_empty_monthly`).
4. 前端: PLN-01/03 闸门页的初步分析区块显示月度表 (金额按 formatAud; 第 4 列表头为 “其中员工费用” / “of which employee expenses”); `bun run lint`, `bun run typecheck` 通过; generate-client 后 AnalyticsResult 类型含 monthly.
5. Xero 的 3 行在 GN-11 与 GN-16 验收.
6. Numbat 回归: ANALYTICS 的 ratios 与 exception_ids 不变 (`test_pln07_analytics_and_exception` 只多了 monthly); A03 不出例外, R55 例外仍 4 条; PLN-01/03 闸门材料的其余字段不变; 默认测试与连库测试全部通过.
