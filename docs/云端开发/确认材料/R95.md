## 改动摘要

## 偏离需求原文之处

1. 需求范围写 "加载程序库时静态校验全部 ref". 我对全部模板 (含功能未启用的) 校验, 同 R81 fixed 校验的做法: 写错的模板不因功能关着而漏检.
2. `resolve_params` 遇到名称写错的 ref 仍抛 KeyError (原行为), 判断条件与加载校验共用 `ref_problem`. 经程序库加载的模板已在构造时挡住, 这一支只防直接构造的模板.
3. ref 取整个嵌套模型 (如 `{ref: dataset.payroll_accounts}`) 时值为字典 (model_dump), 不是模型对象: params_snapshot 存进检查点与 Store, 用普通数据, 不依赖模型类. 需求没写这种用法, 我加了一例测试.
4. 验收 2 的 JSON 原文在测试里内联 (DESIGN_TRAITS). 第 5.2 节有一行超过 120 列, 拆成两段相接的原始字符串, 文本不变; 另断言它与补造目录的 dataset_traits.json 相同 (补造文件与第 5.2 节相同由 test_xero_demo_data 守住).

## 讲解

### 业务背景

- 跟数据来源有关的事实 (上期起始日, 录入时间是否可信, 作废冲回格式, 审计更正分录前缀, 薪酬科目等) 不该写死在程序 YAML 里, 由数据集声明给出 (设计稿 v2.1 第 5.2 节).
- 程序参数用 `{ref: dataset.<键>}` 引用, 建执行记录时解析写进 params_snapshot. 没有声明文件的数据集 (Numbat) 按缺省值运行, 结果不变.
- 本条只立机制与缺省值. 读 `data/xero_demo/<快照>/dataset_traits.json` 由 R96 做. 后续 JR-2 的画像引用在同一机制上只加 `profile` 命名空间.
- 本条不改任何程序 YAML; 第一个使用者是 R102 (PLN-07 的 `prior_period_start`).

### DatasetTraits (验收 1, 2)

- 字段与缺省值: dataset None, data_as_of None (不设上限), prior_period_start None (视为与本期等长), entry_timestamps_reliable True, entry_timestamps_note None, reversal_reference_pattern None, reversal_entry_no_template None, counterparty_prefixes ["payment to", "payment from", "payment:"], audit_adjustment_entry_prefix "AJE-", payroll_accounts None, payroll_register None.
- 继承 `Model` (frozen, extra=forbid): 多一个未知键报 ValidationError.
- 模型校验 `reversal_format`: 格式与模板同给或同空; 格式能编译且 `re.compile(p).groups == 1`; 模板含 "{1}". 消息用中文 (声明由人写, 不回传大模型).
- 测试:
  - `test_dataset_traits_defaults`: model_dump 逐键等于缺省值.
  - `test_dataset_traits_from_design`: 第 5.2 节原文 (内联) 解析出 prior_period_start 2025-07-01, data_as_of 2026-10-17, entry_timestamps_reliable False, 格式 "Reversal of ID (\d+)", 模板 "XJ-{1}", wages_expense ["477"], leave_provision ["805"]; 与补造目录的文件相同.
  - `test_dataset_traits_rejects_bad_declarations`: 未知键, 不能编译, 没有捕获组, 两个捕获组, 模板不含 {1}, 只给格式, 只给模板, 7 种都报 ValidationError.

### ref 的命名空间与解析 (验收 3, 4)

- `REF_NAMESPACES`: 前缀 → 取值的模型, 现在只有 dataset → DatasetTraits.
- `ref_problem(ref)` 的规则:
  - 不是文本: "ref 须为文本".
  - 在 STATE_REFS 或 ENGAGEMENT_REFS 中: 合格.
  - 前缀不是已登记的命名空间 (如 `profile.x`, `nosuch`): "未知 ref ...".
  - 只有前缀 (`dataset`): "ref dataset 缺字段, 写成 dataset.<字段>".
  - 字段路径逐层须是模型的字段: 字段不在模型里, 或上一层不是嵌套模型 (`dataset.audit_adjustment_entry_prefix.x`, `dataset.payroll_accounts.wages_expense.x`): "未知 ref ...". DatasetTraits 只有一层嵌套, 所以至多写到子字段, 不另设层数上限.
  - 嵌套模型从字段类型里找 (`nested_model`: `PayrollAccounts | None` 取 PayrollAccounts).
- 加载校验: ProcedureLibrary 构造时, 对每个模板每个 `{ref: ...}` 参数调 ref_problem, 有问题的全部列出, 抛 ValueError "程序参数的 ref 写错: X-REF.bad: 未知 ref dataset.no_such_key".
- `resolve_params`:
  - 状态 ref 为 None 仍抛 ValueError (重要性未定不执行);
  - dataset. ref 的值为 None 以 None 执行 (与状态 ref 不同);
  - 取值深拷贝, 改返回值不改声明对象.
- 测试 (临时 knowledge 目录加测试模板 X-REF, 参数 a: dataset.prior_period_start, b: dataset.payroll_accounts.wages_expense, c: dataset.audit_adjustment_entry_prefix):
  - `test_dataset_refs_resolve`: 第 5.2 节声明 → {a 2025-07-01, b ["477"], c "AJE-"}; 缺省声明 → {a None, b None, c "AJE-"}; 改返回的 b 后声明里的 wages_expense 仍为 ["477"].
  - `test_dataset_ref_to_a_nested_model_is_a_dict`.
  - `test_refs_are_checked_on_load`: 7 种写错的 ref (含 `dataset.no_such_key`, `dataset`, `profile.x`, `nosuch`), 构造即抛 ValueError, 消息含 "X-REF.bad" 与该 ref.
  - `test_existing_templates_pass_ref_checks_and_ignore_traits`: 现有模板 (含未启用的) 都过校验; 用两种声明解析结果相同.

### build_run 取项目数据集的声明 (验收 5)

- `perform` 先取 `deps.datasets.dataset_traits(engagement.dataset)`, 交给 `build_run`; execute (attempt) 与 fieldwork 都经 perform, 所以两条路径同一处取声明.
- 重放: perform 照现状先 build_run (取一次声明) 再看 Store; Store 中已有终态执行时取回它, 参数以 Store 中的 params_snapshot 为准.
- 测试 (test_nodes, 程序库带 X-REF, 项目数据集为 xero/20261017-q1, FakeDatasetLoader 对它返回第 5.2 节的声明):
  - `test_execute_and_fieldwork_resolve_dataset_refs`: execute 得 RUN-X-REF-1 的参数为 {a, b, c} 的声明值, Agent 收到的执行记录相同; fieldwork (实例 fw-0-0) 得同样的参数; 两条路径各以项目数据集调 dataset_traits 一次.
  - `test_replay_keeps_stored_params_when_traits_change`: 第一次 execute 写入 Store 后把声明改为缺省; 再 execute (重放) 取回的执行参数仍是原值, 不再调 Agent, dataset_traits 共被调两次.

### 载入器与组装 (验收 6)

- CsvDatasetLoader, XeroDatasetLoader 返回 `DatasetTraits()`; RoutingDatasetLoader 按前缀转发.
- `test_dataset_traits_default_until_read_from_supplements`: demo 与 xero/20261017-q1 都为缺省值; 路由把 xero/ 前缀转给预置了声明的假载入器.
- main.build_deps 与 make_deps 照常构造 (全部现有测试经过它们).

### Numbat 回归 (验收 7)

- 本条不改程序 YAML.
- `test_numbat_params_do_not_depend_on_traits`: Numbat 的 18 条程序用缺省声明与第 5.2 节声明建执行记录, 参数逐键相同.
- test_nodes 原有的逐值断言 (RUN-REV-08-1 {window_days 20, period_end 2026-06-30}, RUN-CSH-04-1 {as_of 2026-06-30} 等) 只加 traits 参数后通过.
- test_knowledge 原有 resolve_params 用例只加 traits 参数后通过.
- R55 (test_e2e_mock), R57 全部通过.
