# R272 确认材料: 程序缺数据时逐个等数据并提补交请求

来由: issue #2 (产品经理提; 10-19 用户选 "逐个程序等数据"). 方案的 4 个选择题按推荐定 (主代理 10-19 转达):

1. 前置未执行 (无数据) 时下游也记未执行.
2. 已标 "客户无此类资料" 的不自动重做.
3. 账表有任意一行, 文件有一份该类型即算有.
4. 程序一进项目就查, 早提请求.

本条按主代理拆分只做 (a) 部分. "客户无此类资料" 的接口, 传播到 no_data 与 FIN-01 材料归 R280. 第 1, 2 题在 R280 落实.

## 讲解

### 业务背景

- 10-19 live 测试: 新项目只导入三张必需表, DOC-04 在没有合同时 succeeded; P2 七条程序 0.15 秒内都 succeeded, 例外 0, 流程直接停在 FIN-01.
- "没有可测对象" 与 "测过无异常" 分不出来, 等于把审计师引向没有证据的无保留意见. A3 也只追三张必需表.
- 本条让程序在执行前看自己要的客户资料:
  - 缺了不执行, 也不建执行记录, 记 "等待数据".
  - A3 为缺的资料提补交请求, 审计助理照常列出.
  - 资料到了图自动接着跑. 有资料的程序先跑, 互不牵连.

### 程序要的资料 (inputs)

- YAML 写法 `inputs: {tables: [...], documents: [...]}`, 取值由 pydantic 按 TableKind, DocumentType 校验 (加载时).
- 六条: DOC-04 合同; CSH-04 银行账户; CSH-05, CSH-02 银行账户与流水; REV-08 发票, 发运单, 流水; REV-02 发票.
- 不写的:
  - 就绪必需的三张表: P1 等数据保证, 写了也永远满足; 也避免与 R15 体检请求的用途重叠.
  - 前置程序的结果 (REV-03 的合同抽取, DOC-06 的回函): 由 depends_on 表达. 所以验收 1 中 REV-03 是 "不派发", 不是等数据, 也不为回函向客户要资料.
- 写法校验 (第 1 轮 R272-07 改):
  - 程序库加载时 (同 fixed 的加载校验): 不能写必需的三张表; 不能写 other; 取值不合法时报错带程序编号与文件名.
  - GraphNodes 构造时 (同 R85 的 outputs, 要看图节点): P2 以外的程序只有 DOC-04 能写 inputs, 只有 p1_ingest 能在执行阶段补跑它.
- "有资料" 的口径 (第 3 题):
  - 账表看 `DataStore.stats` 的行数, 与就绪判断同口径.
  - 文件看新加的 `DataStore.document_counts` (按类型数 documents 表; 上传的文件分完类才有类型).
  - "本期有没有可测对象" 留给 R130 的规则级检查, 接口文档第 8.1 节写明.

### 状态怎么定 (inputs.input_versions)

- 只看状态为 planned, executing (要求重跑的, 第 1 轮 R272-05 加) 或 awaiting_data, 写了 inputs 的程序:
  - 还缺 → awaiting_data, data_request_ids 为还缺的资料的请求 ID (按声明顺序).
  - 不缺 → awaiting_data 回到 planned, planned 与 executing 不变.
- 只对 (状态, data_request_ids) 有变化的出新版本 (version +1). 所以数据齐全的项目一个新版本都不多出 (验收 4).
- `GraphNodes.refresh_inputs`:
  - 一个事务写入, 提交后写 transition 留痕; 到 awaiting_data 的 payload 带 data_request_ids.
  - 有程序新进入 awaiting_data 时随后跑一次 A3 体检 (提请求).
  - 版本号由状态推出, 重放时 put 同版本跳过.
  - 都没写 inputs 的程序 (PLN-07 等) 直接返回, 不读数据.

### 三处调用与图的走向

- P2 以外的程序每次执行前 (`execute` 里的 `inputs_before_run`, 首次与 rerun 都经过, 第 1 轮 R272-05 改):
  - DOC-04 缺合同时记 awaiting_data, 不执行.
  - 节点照常往下, P1 照常到 PLN-01/03 闸门 (验收 1 "P1 的 DOC-04 等待合同. 批准 PLN-01/03 后 ...").
- 执行阶段 `schedule` 节点:
  - 先对全部 P2 程序查一次, 再排调度表.
  - PLN-01/03 通过后第一轮就把 CSH-04, CSH-05, CSH-02, REV-08, REV-02 记为等待数据, 不论前置是否完成 (验收 1 要求 CSH-02, REV-02 也显示等待数据).
- `ready_procedures`:
  - 前置改为看整个程序包.
  - 原来只看 P2 内的前置, 假设 "P2 以外的前置在此之前已完成". 现在 DOC-04 可能还在等, REV-03 因此不派发.
- `route_schedule`: 派不出时一律回 fan_in. 卡住只在 after_fan_in 一处判断, 那里仍抛 ScheduleStuck, 不会空转.
- `after_fan_in` (先命中先走):
  1. DOC-04 在执行阶段回到 planned (等到了合同) → p1_ingest 补跑.
  2. 有可派发的 → schedule.
  3. 有待决任务 → await_events.
  4. P2 全部 completed 且没有程序在等数据 → completion.
  5. 有 awaiting_data → await_data.
  6. 其余照旧 ScheduleStuck.
- `p1_ingest` 出边改为条件边: 阶段为 P2_Executing 时回 fan_in, 否则到 p1_analytics. 补跑的 DOC-04 抽取失败时照 R87 在 p1_ingest 节点内等人, 恢复补做的读回顺序照 NODE_PROCEDURES["p1_ingest"], 不改 recovery. 只调 R87 的 `execute`, 不依赖 still_waiting 的内部写法.
- `await_data` 节点 (节点内只有这一个 interrupt):
  - 先对 awaiting_data 的程序重查, 有变化就返回, 回 fan_in.
  - 没有变化 → `interrupt({awaiting: inputs, procedure_ids})`.
  - 恢复后从头执行, 先重查. 空恢复时这次 interrupt 取回恢复值, 返回空片段, 经 fan_in 回到本节点新的一次执行再停下, 不空转 (测试 `test_recover_rechecks_and_empty_resume_waits_again`).
  - DOC-04 的补跑放 p1_ingest 而不放这里: 同 p1_await_data 的教训, 恢复值没被消费时会交给同一节点的下一个 interrupt (补跑失败后的等人).

### 等待种类 (对齐 R87)

- `WaitKind.inputs = "inputs"`, 载荷由 `waits.inputs_payload` 构造, accepts 一律 False.
- `runner.review_waits` 去掉 data 与 inputs 两种 (`waits.DATA_WAITS`): 总览的 awaiting_review 为假, DecisionSubmit 不把它当等复核.
- `awaiting_data` 仍只指 P1 的等数据就绪: "数据已齐" 按钮与 POST /data/ready 不受影响.
- 不复用 data 种类: 那种由审计师显式确认后恢复, 这种在数据到达后自动恢复. 合成一种, 执行阶段也会出 "数据已齐" 按钮.

### 自动继续与项目锁

- `DataService.holding` (导入提交, 改分类等) 与 `launch` 的后台作业 (Xero 同步, 文件处理):
  - 作业结束时锁还在手里.
  - 图停在 inputs 等待时, 把锁交给 `runner.launch(eid, Command(resume=INPUTS_CHANGED))` (`continue_waiting`, 同 confirm_ready 的交锁写法).
  - 否则照旧释放. 锁由 continue_waiting 交出或释放, 调用方不再管锁 (第 1 轮 R272-03).
  - 读检查点出错只记日志并释放; 读检查点时被取消也释放; 后台任务建不起来时 launch 已释放锁, 不再重复释放 (不会误放别人的锁).
  - 启动时先补做没处理完的上传文件, 做完再带动图 (第 1 轮 R272-04, 见上).
- 一条规则覆盖导入, 同步, 文件处理, 以及 R280 的 "客户无此类资料". 改分类之类没新资料的写操作也会触发一次重查, 没变化就再停下, 只多几次检查点.
