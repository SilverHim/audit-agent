## 讲解

### ABR ABN Lookup 的要点 (官方文档 9.9.7 版, 10-19 核对)

- 免费, 需注册: 读使用限制与用户指南, 接受 Web Services Agreement, 填表; ABR 用邮件发 authentication GUID.
- 方法 SearchByABNv202001 (新接入者用最新版本), 三种协议 (SOAP, HTTP GET, HTTP POST), 请求三项: searchString, includeHistoricalDetails, authenticationGuid.
- 出错也返回 HTTP 200, 错误放在 response/exception: SEARCH "No records found" 即查不到; WEBSERVICES 一类含 GUID 不被认可, 未注册该服务, 注册已取消, 系统故障等.
- 实测 (全 0 的假 GUID): 响应原样回显请求, 含 `<authenticationGUID>`. 这是 "原始响应一律不落地" 的原因.
- 条款里与本条相关的: 不得暗示联邦政府认可 (界面写 "ABN Lookup: ...", 不写 "政府核实"); 服务按 "as is" 提供, 可能中断 (所以查不了就转人工, 不让流程失败); 被通知撤回的信息须删除副本 (见 "环境限制").

### 留痕与可靠性

- 真查了登记 (数据集 mock 或 ABR): 留痕 `{abn, result}`, 证据为外部原件 (审计师直接向登记系统取得, ASA 500 A31).
- 查不了: 留痕 `{abn 或 acn, available: false, reason, result: null}`, 只是系统自己的记录, 证据为内部原件, 只作定位.
- 这条规则只写在 `judgment_engine.trail_evidence` 一处: ACC-04 写指针与判断引擎解析大模型引用的指针都调它. R288 时引擎一律改写成外部原件, 大模型引用 "未查询" 留痕时会被错标 (R288-11).

### GUID 怎么保证不外泄

- 请求走 POST 表单, URL 不含 GUID; 建客户端时把 GUID 登记进 httpx 与 httpcore 日志的脱敏过滤.
- 原始响应只在 `parse_abn_response` 里读: 不返回, 不记日志; 查不了时抛的 RegistryUnavailable 只带类别的说明, 不接原异常 (`from None`, 连接失败的原异常里有请求).
- `test_guid_never_leaves_the_adapter`: 假接口的 9 种响应 (都回显假 GUID) 各走一遍适配器, ACC-04 (组合登记来源) 与在线核对接口, DEBUG 日志全开, 检索日志全文, 全部留痕, 接口响应正文, 各异常的 str 与 repr, 请求 URL 与客户端的 repr, 都没有假 GUID; 先断言假接口确实回显了它.

  - 留痕: ACC-04 每次查询的 external_call 留痕 payload. audit_trail 只追加, 数据库触发器 audit_trail_append_only 拒绝 UPDATE, DELETE 与 TRUNCATE, 人工删除须用属主角色先绕过触发器.
  - 承接评分卡: RegistryCheck.detail (如 "Registered name: ..."), 评分卡是 Versioned, 历史版本都留在审计产出里.
  - LangGraph 检查点里的编排状态 (含评分卡).
  - 两层短时缓存: 后端 CachedAbnLookup (进程内, 300 秒) 与前端查询缓存 (浏览器内, 5 分钟).
  真收到撤回通知时由人工按以上位置处理; 本条不做删除机制, 是否另立需求做, 留给用户决定.
