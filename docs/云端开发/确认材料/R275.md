## 偏离需求原文之处

1. 验收 3 "59 个科目": 结果为 58 个科目加 1 处失败.
   - 科目表原文件 59 个科目, 其中 803 Wage Payables 的 Type 为空 (Xero 网页导出就是空的, API 里是 CURRLIAB).
   - 空值不在取值映射里, 也不该猜, 所以记为失败处: 第 44 行, 列 `*Type`, 值为空.
   - 其余 58 个的类别与 API 的 `account_class` 逐个相同. 这样 "不静默丢弃" 成立.
   - 若要 59 个都写入, 只能让方案把空值映射成某个类别, 那是猜. 我没这样做, 请审核方定.
2. 验收 4 "发票数与金额与 Xero 快照一致": 方案除跳过合计行外, 还用 skip 规则跳过三类行:
   - 贷项通知单 (Source 含 Credit Note);

   - 快照的销售发票只含已生效的 ACCREC (`LIVE_DOCUMENTS`). 这三类行按 "列 + 正则" 写在方案里, 套用代码不按单据状态写分支.
3. 新增 `dedupe` (需求原文没列这个变形):
   - 应收发票明细一张发票可有多个明细行, 每行都带同一发票合计 (生效发票中 ORC1006 三行, ORC1036, ORC1039 各两行).

4. `convert` 从 data_import 移到 table_plan. 需求原文建议 "沿用 convert 的类型转换", 我改成让 convert 本身成为方案的特例 (按 "不留两套写法"). 接口错误码与消息不变, 原有导入测试全部通过; 同一处 (行, 列, 值) 的失败只记一次, 同一列对应多个字段而该格坏时由两处变一处 (第 2 轮 R275-10).

## 讲解

### 业务背景

- 现有 "导入账表" 把第一个非空行当表头, 列对应只按列名匹配. Xero 网页导出的报表导不进去:
  - 开头有标题三行;
  - 按凭证或发票分组, 组标题单占一行;
  - 有合计行;
  - 试算表本期是借贷两列, 上期另一列.
- issue #3 要 A3 用大模型认出 "怎么规整", 再由代码确定性地套到全表. 大模型不输出数据行.
- 本条只做 "方案" 与 "套用":
  - 方案是一份 JSON: 读哪行做表头, 跳过哪些行, 哪个字段取哪列, 怎么变形;
  - 套用是纯函数, 同一方案套同一文件结果相同.

### 方案模型 (contracts/data.py)

- `TablePlan`:
  - kind: TableKind, 为空表示不是账表.
  - header_row: 原文件行号.
  - skip: `RowRule` 列表.
  - group_title: `GroupTitle`.
  - fields: 字段 → `FieldSource`.
  - periods: `PeriodSource` 列表.
  - dedupe, date_format, amount_unit.
  - 读到的公司名, 期间, 把握与理由不放进来 (归 R276 的识别结果).
- 跳过行按 "列 + 正则" (`RowRule`, re.search), 不按行号列举: 同类报表换期间也能套用. 但列按表头的显示名精确引用, Xero 试算表的上期列名带日期 (30 June 2025), 换期间须改方案里的这个列名 (第 1 轮 R275-08); 测试里同一试算表方案只换上期列名, 就套上了 11-30 的试算表. R276 每个文件都由大模型出方案, 不受影响; 要直接复用可让列来源按表头正则匹配, 留给 R276 定.
- `GroupTitle`: 只有 column 一列有值且匹配 pattern 的行才是分组标题. 命名捕获组的值向下填充, 字段经 `FieldSource.group` 取用.
  - "只有一列有值" 是为了不把数据行误当标题. 测试里 "ID 2 Sales" 带了科目与金额, 就按数据行处理, 日期解析失败.
- `FieldSource` 三选一:
  - column;
  - debit 与 credit: 借减贷, 两列都空为 0;
  - group.
  - 另有 part (一列带正负号拆借贷) 与 values (取值映射).
- `PeriodSource`: 本期与上期分列转成 period 行, 每个数据行每期出一行.
- 模型内校验 (结构, 不看工作表):
  - 来源恰好一种, 借贷两列同给;
  - part 只配一列, values 不配借贷两列;
  - 正则能编译, 分组标题至少一个命名组;
  - 字段用到的组名都在 pattern 里;
  - kind 为空时没有字段与分期;
  - 每期至多一次, 期间余额不取分组标题;
  - header_row ≥ 1, 不许多余的键.
  - 消息用英文: R276 的大模型输出内嵌方案时, 校验失败的消息会回传模型重试 (同 llm_outputs).

### 需求列出的变形 (issue 验收原文)

| 变形 | 写法 | 样例 |
|---|---|---|
| 分组标题向下填充 | group_title + FieldSource.group | 日记账 "ID n 摘要" → description; 发票明细的发票号 → invoice_no |
| 本期与上期分列转成 period 行 | periods | 试算表 |
| 借贷两列算余额 | FieldSource.debit/credit | 试算表本期 |
| 一列带正负号拆借贷 | part positive/negative | 小样例 Amount ±12.50 |
| 取值映射 | values (原文规范化比较, 表外算失败) | 科目表 Xero 类型 → 五类 |
| 金额单位 | amount_unit (为空时按原始表头) | Xero 导出按元; 小样例 cents 与 dollars 覆盖表头 |
| 日期写法 | date_format | 小样例 07/13/2025 按 mdy |

### 套用 (services/table_plan.py)

- `apply_plan`:
  - `sheet_from_rows` 取表头行: 不在表里报 "表头行 99 超出工作表 (共 12 行)"; 是空行报 "表头行 4 是空行".
  - 然后 `apply_sheet`.
- `check_plan` 依次核对, 不过抛 `MappingError`. 码与原 check_mapping 相同: INVALID_VALUE 或 MISSING_FIELD.
  - 是账表;
  - 字段都属于该表;
  - 分期只用于试算表, 且不另对应 period, balance_cents;
  - 借贷两列与拆正负只用于金额字段;
  - 取值映射的原文规范化后不重复;
  - 用到的列 (字段, 期间, skip, 分组标题) 都在表头里;
  - 必须字段与 ONE_OF 组都有来源.
- `Applier` 逐行:
  1. skip 匹配的跳过;
  2. 分组标题行记下组值与所在行号;
  3. 其余为数据行: 各字段取值并转换 (`convert_cell`), 有分期时每期一行;
  4. `finish`: 补缺省, 生成编号, 行模型校验, 唯一键 (dedupe).
  - `finish` 原样取自原 convert 的后半段, 包括审批日志只留对应了的字段.
- 失败处 (`ParseFailure`):
  - 行号为原文件行号.
  - 列为来源列名: 借贷两列为出错的那一列, 行模型校验或唯一键重复时为借方列; 分组标题取标题列, 行号取标题所在行; 第一个标题之前的数据行取该行.
  - 同一处 (行, 列, 值) 只记一次 (第 1 轮 R275-02).
  - 唯一键重复记在后出现的行上.
  - 某期余额坏了只少出这一期. 测试: 412 本期借方 "abc", 461 上期 "n/a" → 两处失败, 出 10 行.
- `convert` = `apply_sheet(mapping_plan(...), sheet)`. 账表导入提交的行与错误码与原来相同 (test_data_import 39 例与 test_data_imports_api 照过); 只有失败处去重 (第 1 轮 R275-02) 也作用于提交: 同一列对应两个字段 (如只有一列日期的发票) 而该格坏时, 由原来的两处相同失败变为一处, IMPORT_PARSE_ERROR 的 "N 处" 随之变小, 这是改进 (第 2 轮 R275-10, `test_one_bad_cell_mapped_to_two_fields_is_one_failure`).

### 验收逐条

1. 试算表 06-30 (`test_trial_balance_periods_from_columns`):
   - 12 行, 6 个科目, 本期上期各 6 行, 标题与 Total 不出行.
   - 本期等于 q1 快照 06-30 试算表 (`trial_balance_cents`), 上期全 0.
   - 另一例 (`test_trial_balance_plan_carries_over_to_another_period`): 同一方案换上期列名, 套到 11-30 的试算表. 本期 32 个科目等于 20261017-mock 快照 11-30 表; 上期非零余额等于 mock 的 06-30 表 (200 为 -420000, 贷方为负).
2. 日记账报告 (`test_journal_report_groups_fill_down`):
   - 1017 行, 368 笔, 借贷各 43969507.
   - 756 各行 description 为 "Inventory Opening Balance".
   - 与 q1 快照逐笔比较 (XJ-n): 各行 (科目, 借减贷) 的多重集合相同, 入账日期与录入时间相同. Posted Date 是悉尼时间, 按悉尼转 UTC 后与 CreatedDateUTC 一致.
   - Posted By 读出即在内存里遮蔽, 方案不对应它, created_by 全空.
3. 科目表 (`test_chart_of_accounts_maps_xero_types`):
   - 58 行加 1 处失败 (见偏离 1).
   - 类别逐个等于 API 的 account_class: expense 29, liability 16, asset 8, revenue 3, equity 2.
   - 映射表外的值 (`test_value_outside_the_map_is_a_failure`): 090 改成 "asset" (类型转换认得, 映射表里没有) 后记失败处, 57 行.
4. 应收发票明细 (`test_receivable_invoice_detail_matches_snapshot`):
   - 42 张, 发票号, 金额, 日期, 客户与 q1 快照的 sales_invoices 逐张相同, 合计 7329565.
   - ORC1006 三行合成一张, 1485.00.
   - dedupe (`test_dedupe_keeps_identical_lines_only`): ORC1006 第二行的合计改掉 → 1 处重复键失败; 关掉 dedupe → ORC1006 两处, ORC1036, ORC1039 各一处 (ORC1025 已作废, 跳过).
5. Numbat 七张表 (`test_numbat_identity_plans_equal_mapping`): 恒等方案的 JSON 等于 `mapping_plan(建议的对应)`. 从原样的行套用, 与 `read_sheet` 加 `convert` 逐行相同, 失败为空.
6. 对不上:
   - `test_plan_mismatches_are_reported`: 表头行越界, 表头行为空行, 列不存在 (把标题行当表头), 必须字段没对应 (MISSING_FIELD).
   - `test_plan_checks`: 6 例.
   - `test_periods_only_for_trial_balance`.
   - 解析失败按原文件行号: `test_failures_carry_file_line_numbers`.
7. 纯函数:
   - table_plan 只引 contracts 与 data_import, 不连库, 不调大模型.
   - 测试不标 slow.
   - 原始文件只读, 改单元格的用例都在内存副本上 (`edited`).
