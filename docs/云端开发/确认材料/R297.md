# R297 确认材料: 工作台时间线取最近的留痕

来由: 甲在 R152 方案中发现, 工作台时间线调 GET /trail?limit=500, 后端按写入先后取的是最早的 500 行. 呈递与对话留痕会让项目更早超过 500 行, 超过后新事件就不在时间线上了.

规模 S, 档位 high. 协调者指示直接按验收做. AuditTrail.list 加参数要同步接口文档第 4, 10 节; 原调用方不带新参数时, 行为不变.

## 改动摘要

- 契约 `contracts/ports.py`: `AuditTrail.list` 加两个仅限关键字的参数, 缺省时与原来相同:
  - `newest: bool = False`: 取最近的 limit 条 (从最新一条往前跳过 offset 条), 仍按写入顺序返回.
  - `before: str | None = None`: 游标, 只取排序键 (created_at, id) 小于这条留痕的; 不是本项目的 ID 时为空.
- 实现:

    - newest 先倒序取 limit 条, 再翻回写入顺序.
  - `tests/fakes.FakeTrail.list` 按同样语义实现 (排序即写入顺序).
- 接口 `GET /engagements/{eid}/trail` 加查询参数 newest, before, 原样传给 list. 已有的 kind, limit (1–500), offset 不变. 已执行 `bun run generate-client`.
- 前端:

## 讲解

- **为什么用游标而不用 offset.** 往前翻页时若用 offset, 翻页途中写入的新留痕会让各页整体后移, 上一页最早的一条会在下一页重复出现. 以已取到的最早一条为 before, 只取排在它之前的, 新写入的排在后面, 不影响往前翻. 排序键是 (created_at, id), 同一时刻的留痕按 ID 分先后. 游标比较用同一个键, 同一时刻的两条跨页时也不重不漏 (共用场景特意让 #4, #5 同一时刻且正好跨页).
- **刷新.** 数据写操作后 invalidateEngagement 会刷新这个查询. TanStack Query v5 刷新无限查询时:
  - 第一页仍按 initialPageParam 取最近一页;
  - 后面各页的游标由刚取回的页重新算 (getNextPageParam), 已翻出的页数保持不变, 仍连续不重不漏.
  - 新事件多于一页时, 最早那几条重新变成 "更早"; 按钮与 "项目已创建" 随之出现与隐去.
- **恰好整页.** 总数恰为页长的整数倍时, 多翻一次得到空页才知道到底. 这时按钮会多点一次, 之后消失并显示 "项目已创建".
- **方向.** 时间线仍从旧到新 (上旧下新), 与原来一致. 最近一页在当前事项上方, "更早" 在最上面.
- **不改的.** 审计留痕页 (`/engagements/$eid/trail`) 自己用 offset 分页, 本条不动. 对话工具的 search_trail 与 trail_pages.all_of_kind 不带新参数, 行为不变.

## 验收

1. 留痕超过一页时, 时间线显示最近的一页, 最新一条一定在内; 方向与现有时间线一致 (从旧到新):
   - 后端: trail_pages_hold 中 7 条取 newest 一页 3 条, 等于全序的最后 3 条, 最后一条为 #7. 假实现与 Postgres 都跑.
   - 前端: timeline-pages.test.ts 第 1 例, 首页拼出的最后一条为 TR-7, 这时不加 "项目已创建".
   - 界面核对见下: 113 条留痕, 首页 100 条, 最后一行是最新的一次取回.
2. 可以往前翻到最早的一条, 不重不漏:
   - 后端: trail_pages_hold 以上一页最早一条为 before 往前翻, 各页长 [1, 3, 3]. 拼起来等于原有调用取到的全序.
     - 翻页途中写入的 #8 不混进往前翻的页, 刷新首页能取到它.
     - 同一时刻的两条跨页.
     - 游标可以是别种类型的留痕 (与 kind 同用).
     - 别的项目或不存在的 ID 作游标时为空.
   - 前端: timeline-pages.test.ts 第 1 例, 翻到底后与全部留痕逐条相同, 加上 "项目已创建". 第 2 例: 恰为整页时多翻一次才停; 没有 ID 的条目不当游标.
3. GET /trail 原有调用方 (不带新参数) 的行为不变:
   - trail_pages_hold: `list(eid)` 与 `list(eid, limit=3, offset=2)` 仍从最早一条起.
   - test_api.py::test_trail_list_pages 的 `{limit: 2}` 一例, 以及原有的 test_trail_list_and_detail.
   - 对话工具与 all_of_kind 的测试照常通过.
4. 默认测试覆盖以上三点 (假实现与路由, 前端 lib); 中英文案齐; lint, typecheck, 前端测试通过 (见环境限制).
