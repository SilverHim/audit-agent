# R347 确认材料: 带规则例外的对象判断失败时也能重跑判断

来由: R317 真实模型走通 (GEN-02 XJ-430 语义级不过, 转 unattributed, 只能推翻). 规模 S, 档位 xhigh. 基于 6ff03a6 (R317, R353 合入后; 驱动已移到 tests/live_walk.py).

## 改动

- `services/review_queue.py`: ALLOWED 的 unattributed 一行加 rerun; 新常量 `RERUNNABLE` (ALLOWED 中含 rerun 的任务类型, 即 failed 与 unattributed), 下面三处共用.
- `orchestration/decisions.py` `rerun_group`: 一轮失败算一组 (Q17) 的组由 failed 扩为 RERUNNABLE. 整组一并关闭, 程序 executing 时就没有待决的可重跑任务, 不会再来第二个 rerun 盖掉这一版的 rerun_subject_ids.
- `orchestration/recovery.py` `closed_by` (补写留痕时推回一并关闭的任务) 同上.
- `orchestration/nodes.py` `failed_tasks` (P2 以外的程序在节点内等待时这一轮的组) 同上; unattributed 任务的 rerun 经 read_rerun 读回, 其余决定 (推翻, 认定错报) 照旧整体读回.
- 重跑本身不另写: 决定写出 executing 的程序版本, rerun_subject_ids 为任务的 subject_id, A6 按 in_scope 只判这个对象 (任务已 decided, 不再算 "已交人处理").
- 接口文档第 5 节需要人表的 unattributed 一行, 第 7 节 allowed 一句与决定效果表的 rerun 一行.
- 前端复核表单按 allowed_decisions 生成按钮, 不用改.
- 驱动 `tests/live_walk.review_body`: unattributed 任务同 failed 先重跑一次 (每个对象至多一次, 共用 LiveWalk.failures 计数), 重跑后仍是 unattributed 才按决定表推翻或认定错报; `tests/xero_harness.rerun_failed` 同改为 RERUNNABLE (同 rerun_group). 两处说明一并改.

## 方案取舍

- **组里含 unattributed (10-20 协调者定做法 1)**: Q17 "一轮失败算一组" 原样推广, 同程序同一轮仍待决的 failed 与 unattributed 一并重跑, P2 与 P2 以外 (节点内等待要求重判对象覆盖本轮整组) 同一规则. 对 B (failed) 重跑时 A (unattributed) 跟着重判, 得出的是 normal 任务, 仍由审计师复核; 审计师想自己定 A, 先对 A 作出决定即可, 之后的重跑只带还待决的. 原用例 `test_full_rerun_keeps_subject_in_human_hands` (R41) 按新规则改写, 见下.
- **成功后例外不另出版本**: 重判成功时例外仍是失败时出的 unattributed 版本 (下游只分 attributed 与否); 判断确认时 attribute_exceptions 出 attributed 新版本, 即 "例外随判断归因". 自动关闭的判断 (L3 以上) 在 judgments_patch 里当场归因, 同原有路径.
- **重跑上限**: 后端不限次数, 同 failed 任务; "每个对象至多重跑一次" 是演示驱动的规则 (验收 3, 驱动部分).
