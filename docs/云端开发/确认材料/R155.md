  - 状态迁移的参照为会话共用的 R55 一次 (conftest 的 `demo_run`, collab 关闭), 只取留痕.
- 共用流程函数加同一种钩子 `before_review(runner, eid, 复核记录)`, 缺省时行为不变:
  - `test_e2e_mock.finish_demo(reviews, before_review)`;
  - `xero_fakes.finish_xero17(before_review)`, `test_e2e_xero17.drive_xero17 / run_xero17(features, before_review)`.
- R55 的演示 (`test_e2e_mock.record_demo`) 改为会话级夹具 `demo_run` (conftest, loop_scope session): test_e2e_mock 的用例与它同一个事件循环, test_e2e_xero17 (R119, R120) 与本条只取它的留痕, 会话里只跑一次 (原先默认测试跑三次).
- `test_e2e_restart`: DOC-06 中断用例按功能集参数化 (baseline, collab).
- `test_persistence_postgres`: 新增 slow 用例 `test_collab_dispute_variant_real_storage`.
- `test_collab.py` 的主流程用例 (R149 验收 4) 并进验收 1, 不再把同一全流程跑两遍.

## 方案取舍

- 演示配置只改 `.env.example`, 不改 Settings 的缺省: 代码缺省保持基线, 不配置时现状不变. 检查点冻结的是功能集, 已启动的演示项目要用原来的设置继续 (FEATURES_MISMATCH 规则不变).
- 呈递不经 HTTP 接口: 接口取当前时间, 无法造出确定的 95 秒与 40 秒. 时间注入同 R153 的用例; 接口本身已由 R152 的用例覆盖.
- 争议变体 (验收 2) 放在 test_collab_flow, 没放进范围里写的 test_dispute.py:
  - 它和验收 1 共用呈递辅助与 R55 参照;
  - test_dispute 要引用 test_collab_flow, 而后者已经引用 test_dispute 的常量, 会循环导入;
  - test_dispute 保留基线 (collab 关闭) 的仲裁用例. collab 打开时仲裁前后的细节已在 test_collab (R150, R151).
- 验收 3 的 "M-5" 是设计稿里的叫法, 实际 ID 沿用 R119 的 M-D-CSH02. Xero 的呈递取决定前 60 秒, 需求没给秒数.
- 连库变体用争议变体: 主流程没有 in_dispute 与 consulted, 一次运行就能把四项都存回读出.
- Postgres 留痕按 (created_at, id) 排, 所以库里 CSH-02 那次呈递 (-95 秒) 排在 REV-02 (-40 秒) 之前; 假留痕按写入顺序排. 两边的断言各按各的顺序写.
