# R153 确认材料: 复核停留时长 (只记录)

来由: 草稿 AC-9; 第三档 G1 第 2 问 (呈递时间记留痕), 第 6 问 (只记录停留时长, 不开提醒). 规模 S, 档位 xhigh, 功能 collab.

## 改动摘要

- 契约 `contracts/models.ReviewRecord`: 加 `dwell_seconds: int | None` 与 `presentation_id: str | None`, 缺省都为空. 接口文档第 2.5 节同步.
- `services/presentation.dwell_seconds(entries, task_id, reviewer, decided_at)` (纯函数):
  - 在 kind presentation, payload.task_id 相同, actor 为复核人, 呈递时间不晚于决定时间的留痕中取最近一条;
  - 返回 (秒数向下取整, 留痕 ID); 没有时为 (None, None).
- `orchestration/decisions`:
  - `GraphDecisionSubmit.timed` 在校验通过后, 写入前填这两项: collab 打开时用 `trail_pages.all_of_kind` 读完 presentation 留痕再算; 关闭时为空; 调用方给的值不用.
  - `review_trail` 在 dwell_seconds 不为空时, payload 另带 dwell_seconds 与 presentation_id. 提交与恢复补写共用这一处, 补写时取决定上存的值.
  - 接口文档第 7 节 DecisionSubmit, 第 7 节决定留痕的 payload, 第 10 节呈递留痕同步.
- `api/schemas.ReviewRecordIn` 没有这两项, 请求体带了即 422 (只改了 docstring). 前端重新生成客户端, ReviewRecord 多两项.

## 方案取舍

- presentation_id 存进 ReviewRecord (范围只写了 dwell_seconds): 恢复补写时秒数与留痕 ID 都取决定上存的, 留痕与决定一致, 补写不读呈递留痕. 不存的话, 补写只能重算 presentation_id, 与存下的秒数可能对不上. 只多一个可空字段, 旧 JSON 照常读出.
- 停留时长在 submit 里算, 不在 _apply_review 里: 范围写的是 "校验通过后, 写入前". 这样也能在测试里只替换写入那一步.
- 同一时刻有两次呈递时, 取排在后面的那条 (留痕按 (created_at, id) 排, 第 1 轮修改改正了说法).

## 验收对照

1. 新字段缺省为空, 由服务端算; ReviewRecordIn 带任一项不过; 旧 JSON 可读: test_review_decisions `test_dwell_fields_are_not_taken_from_the_request`.
2. 纯函数: test_presentation `test_dwell_seconds`, 8 组输入 (第 1 轮修改后), 决定时间 10:01:35. 结果分别为:
   - 10:00:00 → 95;
   - 两次呈递取最近一次 → 35;
   - 晚于决定的, U-2 的, 别的任务的, 别种留痕的都不算;
   - 没有呈递 → (None, None);
   - 不足 1 秒 → 0; 与决定同一时刻的也算.
3. 和 5. Numbat 全流程, collab 打开 (`test_dwell_seconds_from_last_presentation`):
   - 先写 501 行别的任务的呈递, 再于 10:00:00 呈递 T-J-CSH-02-1-BA-01-v1, 10:01:35 提交 D-CSH02;
   - 存入的记录为 95 和这次呈递的 ID, decision 留痕 payload 同.
   - 把读完全部留痕换成只读一页 (500 行) 时这一例失败, 说明它确实依赖翻页.
4. 两次呈递, 晚于决定, U-2 的呈递, 没有呈递 (payload 不带这两个键): 见 2 与 9.
6. 恢复 (`test_recovery::test_review_dwell_kept_when_trail_backfilled`):
   - 决定写 Store 后 decision 留痕没写成; 中断后又补一次 10:01:00 的呈递 (重算会得 35);
   - recover 补写的留痕仍为 95 和原呈递 ID; 两次 recover 后留痕仍只 1 行.
7. 闸门决定不算: 同一流程里 D-ACC 的留痕没有这两项. GateDecision 也没有这两个字段.
8. 不做提醒: 没有阈值配置项, 总览, 队列与对话都没有改.
9. collab 关闭: `test_timed_fills_dwell_only_with_collab` 关闭那例中, 带上 1 秒与伪造 ID 的决定经 timed 后两项为空; 留痕不带见 `test_dwell_trailed_whenever_measured`. 现有测试一条没改.
