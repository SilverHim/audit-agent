## 改动摘要

- `contracts/services.py` 的 ValidationContext 加 `standards_of: str | None`, 必填 (可显式 None, 不给缺省值, 新调用方漏传时 mypy 即报):
  - 不为 None 时, 判断与 GEN-09 第一轮引用的准则片段须在该程序 YAML 的 standards 内;
  - GEN-09 填被复核的程序;
  - None 不核对: 抽取, 分类, 报告与 GEN-09 第二轮等不按引用级解析准则片段的调用方都显式写 None.
- `services/judgment_engine.py`:
  - PointerResolver 加参数 standards_of (必填, 在 eid 之后, R128 的 profile 之前). 准则片段已登记而不在该程序 standards 内时, 同未登记的片段一样解析不了, 原因为 "准则片段 {ID} 不在 {程序} 的 standards 内".
  - OutputValidator 的 _judgment 与 _critic 按 ctx.standards_of 建 resolver.
  - JudgmentEngine.judge 的校验上下文填本程序 (template.id).
- `agents/review.py`:
  - GEN-09 第一轮的校验上下文填被复核程序 (A6 的 ctx.template.id), 与提示词里列出的片段 (`engine.standards(ctx.template)`) 一致.
  - A7 取第一轮要给的证据时 (given_evidence) 也按被复核程序 (judgment.procedure_id) 核对: A6 判断里引了 standards 以外的片段 (A6 校验时该步 unsupported, 指针原样保留), 不作为第一轮证据给复核模型, 也不进 allowed_evidence, 与接口文档第 6 节 "A6 校验时原样保留的无效指针不给" 一致. 第一轮校验的 standards_of 留作兜底.
- `docs/开发接口文档.md` 第 5 节: ValidationContext 定义加该字段 (必填, 可显式 None); 四级校验表 "引用" 一行写明 standard 另须在 standards_of 程序的 standards 内, 不在时同未注册, 错误写明片段与程序. 第 6 节 GEN-09: 第一轮给出的证据中准则片段按被复核程序的 standards 核对, 不在内的不给, 也不进推理链可引用的证据.

### 不在 standards 内时怎么处理

按 10-20 校正后的目标实现 (需求清单 10fe4a2): 同引用了未登记的片段, 所在步骤标 unsupported, 错误记进报告, 不回传重试; 推理链与 evidence 中一个能解析的指针都没有, 或错报金额对不上时, 才整条判失败.

## 讲解 (按验收)

1. `test_output_validator::test_standard_must_be_in_the_program_standards` (参数化 4 组, 用 REV-02 的截止性草稿把准则一步换掉):
   - standards_of 为 REV-02, 引 AASB15-P38: 照常通过.
   - standards_of 为 REV-02, 引 ASA450-P05 (已登记, 不在 REV-02 里): 第 3 步 unsupported. 错误两条: "第 3 步指针 standard ASA450-P05: 准则片段 ASA450-P05 不在 REV-02 的 standards 内", 以及 evidence 中同一指针一条. 指针原样保留, 整条照常通过.
   - standards_of 为 CSH-02 (含 ASA450-P05): 照常.
   - standards_of 为空: 只核登记, 照常.
   - 接线: `test_judgment_engine::test_standard_outside_the_program_marks_its_step` (参数化 2 组), JudgmentEngine.judge 跑 REV-03 的草稿. 引 REV-03 自己的片段那步为 supported, 留痕 errors 为空; 换成 ASA450-P05 为 unsupported, 判断照常出, 留痕 errors 两条都写明 "不在 REV-03 的 standards 内". REV-03 与 REV-02 的 standards 相同, 只看步骤状态分不出 judge 填错了程序, 所以另断言 errors 里的程序. 这正是 R109 审核探针 M21 的情形.
2. GEN-09:
   - `test_output_validator::test_critic_standard_follows_the_reviewed_program` (参数化 2 组): ASA450-P05 在第一轮给出的证据内, 被复核的是 REV-02 时该步仍 unsupported, 错误写明片段与 REV-02; 是 CSH-02 时照常.
   - 接线: `test_review_agent::test_fragment_outside_the_reviewed_program_is_not_given` (标 external, 用 Xero 快照). A6 的判断引了 REV-02 自己的 AASB15-P31 与 standards 以外的 ASA450-P05:
     - given_evidence 给出发票, 分录行与 AASB15-P31, 不给 ASA450-P05;
     - 第一轮提示词的 Evidence 段列出 AASB15-P31, 整个提示词里没有 ASA450-P05;
     - 复核方仍引 ASA450-P05 的一步 unsupported, 判一致也因此记 not_applicable 转人工; 引 AASB15-P31 的一步 supported;
     - 第一轮留痕的 errors 写明 "准则片段 ASA450-P05 不在 REV-02 的 standards 内" (兜底的核对生效).
