# R324 确认材料: 被测总体 (契约, 规则引擎与 REV-08)

来由: Issue #50 验收 1, #49 验收 1 共用. 规模 M, 档位 xhigh. 基于开发头 e3654ef. 协调者 10-20 定: P2 的总体随暂存项 (StagedResult.population) 过检查点, 在 fan_in 与执行记录终态同一事务写入; 占位用 prompt_env 那套 Jinja2 环境, 只加 days_before 过滤器, 加载时用 jinja2.meta 核对变量, 不加派生参数.

## 改动摘要

- 契约:
  - knowledge: LocalizedText (zh, en 都要, 不为空); RuleSpec 加 population {sql, description} 与 check; ProcedureTemplate 加 scope.
  - models: PopulationItem, RulePopulation, RunPopulation (ID POP-{run_id}).
  - services: RuleResult.populations. state: StagedResult.population (NotRequired).
- 规则引擎: 执行了的规则各记一份总体. emit rows 以返回行为总体; exception 规则写了 population 时在规则 SQL 之后另执行总体 SQL, 没写的记为未记录 (count 为空); 检查命中的规则不记. 行到项目的取法见 rule_population: 各行 source_type 相同时才是对象类型; 行 ID 取 source_id, 没有时取 id; 其余列进 fields.
- 程序库:
  - prompt_env 与 json_default 从 judgment_engine 移到 procedure_library (避免循环引用), 加 days_before; 另有 render_text (纯函数).
  - 加载校验 population_problems, text_problems; read_problems 也扫总体 SQL.
- 节点:
  - run_rules 把结果记进 RunContext.rule_results; RiskAssessor 改用 run_rules.
  - run_population 只给 engine rule, 经过规则引擎且成功的执行建总体.
  - attempt 在事务内写总体. fan_in 按暂存项写, 改为失败项的不写. 重放不带总体.
- 存储: OUTPUT_KINDS 的 procedures 表加 RunPopulation.
- services/populations.py: total_cents, distinct_items (去重), judged_subjects (判断程序对象), extracted_documents (抽取程序文件).
- REV-08.yaml: scope; R01-R03 的 check 与 population (R01 内连服务完成记录, R02 左连, R03 连收款).
- 测试辅助: fakes 的 engine_result 按 YAML 给预置结果补总体 (NUMBAT_RULES, XERO_RULES 都包上); rev08_populations 由表独立算 REV-08 的总体 (Numbat, Xero 共用).
- 接口文档第 0, 2.3, 3, 5, 6, 8.1, 9 节.

## 方案取舍

- 总体怎么从 Agent 到节点: Agent 的片段只放状态字段. 放进片段要改 4 个现有用例的片段断言. 改 run_agent 的返回值要改 8 处直接调用它的测试. 所以用 RunContext.rule_results 收集, 由节点判定写不写.
- 判断程序 (REV-02, CSH-02, GEN-03) 也经 run_rules 取对象, 但不写总体: 需求写明对象清单由 Store 推出, 不另存. PLN-01 (engine manual) 同样不写.
- GEN-03 C01 一条规则合并分录与流水. 所以行类型不同时不报错, 对象类型为空, 类型留在 fields.
- "分录号" 取发票的 journal_entry_id (分录行 ID). 不再连总账, 免得 REV-08 多一类过期来源.
- 抽取程序的文件登记不记执行, extracted_documents 取的是程序当前的抽取对象.
- 改了两个现有用例, 都因 REV-08 多出总体 SQL:
  - test_rule_engine_checks 的零影响用例: 期望查询加上总体 SQL;
  - test_rerun_stale 的逗号连接用例: R03 的连接串现出现两次, 一并改写.
  - 意图不变. 另有两处测试 import 随 prompt_env 搬家.
