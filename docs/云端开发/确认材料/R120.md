## 方案取舍

- **DataService 做成方法**: `data_service()` 是 `RealRun` 的方法, 不加字段. `test_e2e_live_checks` 按位置构造 RealRun, 加字段会让它失效.
- **画像 ID**: Xero 项目 `fresh_profile=False`, 用数据集画像原样 (CLIENT-XERO-3C1332BB-Q1, 验收 1).
  - 同库再跑时, 建项目经 `adopt_profile` 沿用内容相同的已有版本, 不冲突. 实测同一测试库连跑两次都过.
- **大模型**: 组装根 mock 模式下按数据集只读运行副本, 而 RPT-03 两稿在 `tests/fixtures/llm_xero_only17`. 所以主模型与复核模型都换成 R119 的 `xero17_client()`, 做法是 SwitchableLLMClient.reload. 上传处理用的是同一个客户端.
- **数据与外部 mock**: 都按组装根取.
  - 快照为仓库的 `data/external/xero/api`, 补造为 `data/xero_demo`.
  - 函证与登记 mock 按项目数据集读补造目录.
  - 演示数据导入与确认数据已齐走真实 DataService.
- **document 指针 (验收 2)**:
  - 断言所有 document 指针与登记的 23 份文件 ID 都在补造 manifest 的 documents 中.
  - 回函 ID 由存档时的内容哈希算出, 与 manifest 相同, 所以不另取运行时的 ID.
- **数据版本**: 同离线, 为 10 (需求清单已按实测校正, 87716ff).
