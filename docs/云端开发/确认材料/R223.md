## 方案取舍

- **列的写法**:
  - 接受 JSON 数组; psycopg 解 json/jsonb 列时得到的就是 list.
  - 也接受 JSON 文本, 以便 SQL 用 `::text` 或字符串拼出.
  - NULL 视同没有附加指针, 用于 LEFT JOIN 无匹配的行.
- **没给 locator**: 附加指针的 locator 为空串, 表示指向整行. 主指针的 locator 是本行其余列名, 对别的来源没有意义, 所以不沿用.
- **主指针的 locator 与 detail**: 都不含 `extra_pointers`. 不带这一列的行, locator 与 detail 照旧.
- **报错**: 附加指针的种类与可靠性同主指针, 按同一张映射表 (银行来源为 external_copy).
  - 以下情况都抛 ValueError: 行类型不在表中, 缺 source_id, locator 不是字符串, 整列不是对象数组, 或不是 JSON.
  - 由规则循环包成 RuleError, 消息为 "程序/规则: 原因".
- **校验顺序的微小变化**: 主指针改为先判行类型再判 source_id. 原先先判 source_id. 两种错误照旧都是 RuleError, 现有用例不受影响.
- **范围外**: 映射表没有改去引用 judgment_engine.ROW_EVIDENCE, 以免规则引擎依赖判断引擎. 两表一致由现有的参数化用例 `test_rule_rows_point_like_the_output_validator` 守住.
