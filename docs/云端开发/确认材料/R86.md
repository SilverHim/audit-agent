## 讲解

### 业务背景

- critique C2: 闸门的信息分散在多处, 每加一道闸门要在四组文件里各改一遍:
  - graph.py 的 GATE_NODES 与按 GateId 建的出口.
  - query.py 的 GATE_OF_NODE 反转表与按闸门分支的材料.
  - decisions.py 的 GATE_MATERIAL, GATE_PROCEDURE, GATE_SPECIFIC 与按闸门分支的校验与效果.
  - recovery.py 的 MATERIAL_MODELS 与按闸门分支的重建.
- verify G3: 持续经营 (GC-09) 要在一个节点上挂两道闸门, 原结构会给同一节点加两次条件边, GATE_OF_NODE 只留后写的闸门.
- 本条把这些集中到一行登记, 一个节点可挂多道闸门, 闸门行可挂功能名. 不加新闸门, 现有 4 道闸门行为不变.

### 登记行 (验收 1, 6)

| 闸门 | 节点 | 材料 | 留痕程序 | 出口 |
|---|---|---|---|---|
| ACC-01 | gate_acc01 | acceptance_scorecard (SCORECARD) | ACC-01 | approve → p1_await_data, reject → declined, rerun → p0_intel |
| PLN-01/03 | gate_p1_risk | materiality_candidates (MATERIALITY) | PLN-01 | approve → assemble_pack, reject → p1_analytics |
| FIN-01 | gate_fin | uncorrected_schedule (SCHEDULE) | FIN-01 | approve → report_draft, reject → completion |
| RPT-01 | gate_rpt01 | report_versions (修订轮次最大的一份, pick) | RPT-01 | approve → archive, reject → report_draft |

- GateSpec 的字段:
  - 材料: material_field, material_model, material_id 或 pick (列表字段时从中取当前一份).
  - exits: 出口名 → 节点名, 或 `(features) -> 节点名` 的函数 (按功能取去处, 如以后 R160 的 FIN-01 reject).
  - fields: 决定 → FieldRule(必填, 只允许).
  - 钩子:
    - check: 专项取值校验.
    - effects: 效果与其输入.
    - rebuild: 恢复补做.
    - view: 材料视图.
    - before: 先于决定的出口 (ACC-01 画像更新后 rerun).
    - passed: 效果使材料出新版本时仍放行 (RPT-01 签字).
  - feature: 所属功能.
- `material(values)`: 状态中的当前材料. `stored(store, eid)`: Store 中的当前版本 (原 decisions.gate_target).
- 新闸门的登记清单 (接口文档第 7 节), 各段只加行, 主图, 决定提交, 查询与恢复补做不改:
  1. GateId 取值.
  2. GATES 加一行, 挂所属功能.
  3. 材料视图并入 GateMaterial.
  4. 材料模型登记进 OUTPUT_KINDS 的 gate_materials.
  5. 前端闸门页.

### 主图 (验收 1, 5)

- build_graph: 对 `node_gates(features)` 的每个节点加节点函数 (GraphNodes.gate) 与一条条件边 (`node_route` 加 `path_map`).
- compile_graph 的 interrupt_before 为 `gate_nodes(features)`.
- 基线下结构与改造前相同: test_graph 的基线结构守卫 (合并上游后的节点含 p1_await_data, 边 gate_acc01 → p1_await_data (approve), p1_await_data → p1_ingest, 出口名, 静态中断) 不改断言通过.
- `test_feature_gate_node_only_when_enabled`:
  - 临时登记行 (功能 journals, 新节点 gate_journals, 驳回出口为按功能取的函数).
  - 基线下节点不在主图中, 静态中断仍为 4 个.
  - 启用 journals 后节点出现且为静态中断, 条件边的出口为 approve → completion, reject → report_draft (函数按功能集取到), represent → 自身.
  - 停在该节点前的检查点: 项目冻结 critic,journals 时 waiting_for_human 为真 (recover 不往下推); 基线下为假.

### 组合路由 (验收 3)

- `gate_route(spec)`: 一道闸门的路由, 规则同改造前:
  1. before.
  2. 无决定 → represent.
  3. passed → approve; 决定绑定的材料不是当前版本或材料缺失 → represent.
  4. 按决定种类出闸门, 信息不足 → represent.
- `gate_at(specs, state)`: 节点上第一道没有放行的闸门; 都放行时为最后一道.
- `node_route(specs)`: gate_at 那一道的出口.
- 出口键: 节点只挂一道闸门时即出口名, 挂多道时为 "{闸门} {出口名}". 前面各道的 approve 不出节点, path_map 不列.
- `test_combined_route_decides_gates_in_order`: 测试内复制 ACC-01, PLN-01/03 的登记行, 节点名改为 gate_combo.
  - A 无决定 → represent, 当前为 A.
  - A 通过且绑定当前材料 → 看 B, B 无决定 → represent, 当前为 B.
  - B 通过 → "PLN-01/03 approve" → assemble_pack.
  - A 驳回 → "ACC-01 reject" → declined.
  - A 的决定绑定旧材料 → represent, 当前为 A.
  - path_map 恰为 5 项, 不含 A 的 approve.
- `test_combined_node_gets_one_conditional_edge`: 两行挂 journals 功能, build_graph 后 gate_combo 只有一条条件边. current_gate 按项目冻结的功能集取: 冻结 critic,journals 时为 PLN-01/03, 基线下为 None.

### current_gate (验收 2)

- 签名改为 `current_gate(next, values)`: next 中的闸门节点上当前要决定的那一道.
- 节点上有哪些闸门按项目冻结的功能集 (values 的 version_snapshot["features"], 没有时按基线) 取. 不用进程的功能集: 两者不同时 recover 与决定提交已先拒绝 (R76).
- 调用方: decisions (NOT_AT_GATE 与更新客户资料), query (总览与闸门材料), recovery (补闸门决定, 画像与复核决定), 上游的 data_service (回函修改只在停在闸门或等复核时可做).
- test_query.test_current_gate 改传 (next, 初始状态), 四个断言的结果不变.

### 专属字段 (验收 4)

- FieldRule(required, allowed): required 含 reason; allowed 为另外只允许在此填的闸门专属字段. 未登记的决定为 FieldRule().
  - ACC-01: reject, insufficient_info 须 reason.
  - PLN-01/03: approve 须 materiality, 可填 edits; 其余须 reason.
  - FIN-01: approve 须 reason 与 disposition; 其余须 reason.
  - RPT-01: reject 须 reason 与 annotations; insufficient_info 须 reason.
- `check_fields(spec, decision)`: 缺必填报 MISSING_FIELD, 其余专属字段填了报 FIELD_NOT_ALLOWED. 规则同改造前.
- `test_field_rules_equal_previous`: 4 道闸门 × 3 种决定共 12 例, 必填与只允许的字段都与改造前的规则 (原样抄录在测试里) 相同.
- 取值校验 (登记表的 check) 顺序不变:
  - 通用部分仍在 decisions: 材料版本, edits 的版本, 字段, 决定 ID.
  - PLN-01/03: 重要性区间, edits 的风险项存在且不重复, 通过时覆盖无缺口.
  - FIN-01: 意见类型只能 unqualified 或 qualified.
  - test_decisions 原有的校验顺序与错误码用例全过.
