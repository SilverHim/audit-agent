## 改动摘要

- `data/generate_demo.py`:
  - 加常量 `COLUMNS`: 各表的列, 与 data/demo 现有表头逐字相同. 写 CSV 时用它, 不再取 `backend.contracts.records` 中模型的字段. 契约后来加的可选字段 (Account.category, category_basis, JournalEntry.approved_at) 不进原始数据.
  - 加常量 `UPLOAD_RUNTIME = ("DOC-CLASSIFY", "DOC-06", "DOC-SHEET")`: 生成运行副本 llm/ 时, 除 tests/fixtures/llm 外, 也复制 tests/fixtures/llm_variants/upload 下这几条程序的固定输出 (同样替换别名). 见下面 "另一处漂移". DOC-SHEET 是乙的 R276 (a4a17fd) 加进清单与运行副本的, 变基到 a4a17fd 后一并列上.
- 新测试 `tests/test_demo_generator.py` (默认测试, 不重生成, 1 秒内):
  - `test_generator_columns_match_demo_headers`: COLUMNS 的表与 data/demo 的 CSV 一一对应, 每张表的列与表头逐字相同 (顺序也比); 列都是记录模型的字段.
  - `test_generator_copies_the_same_upload_fixtures_as_the_guard`: 生成脚本的 UPLOAD_RUNTIME 与 `tests/fixture_sets.UPLOAD_RUNTIME` (test_knowledge 守卫运行副本用的清单) 相同.
- data/demo 一字节未改.

## 讲解

- 列的漂移: 生成脚本按模型字段写表头. 契约给 Account, JournalEntry 加可选字段后 (迁移 0002, 0004), 重生成的 accounts.csv 与 journal_entries.csv 多出空列, manifest.json 的哈希随之变化. 改为常量后, 契约再加可选字段也不影响原始数据.
- 另一处漂移 (需求里没写, 修了才能通过验收 1): data/demo/llm 里有 DOC-CLASSIFY (8 个) 与 DOC-06 的两份回函副本 (12345601.json, 23456702.json).
  - 它们是 R14 (67a5377) 手工放进运行副本的上传处理固定输出, 与 llm_variants/upload 下的逐字相同; tests/fixture_sets.UPLOAD_RUNTIME 也规定这两条程序要同步进运行副本.
  - 生成脚本只复制 tests/fixtures/llm, 重生成到新目录时缺这 10 个文件, manifest.json 也少这 10 项, 确定性检查照样失败.
  - 现在生成脚本按同一份清单复制 (R276 之后含 DOC-SHEET 的 11 份规整方案), upload 下的 DOC-04 (agreement.json) 不在清单里, 照旧不进运行副本.
- 检查脚本不在 pytest 与 CI 里, 所以一直没被发现. 新的默认测试只守表头与清单, 完整的确定性检查仍靠 `uv run python data/check_demo.py`.
