## 方案取舍

- **报告记语言, 不记执行 ID:** AuditReportVersion 加 run_id 会触发合并校验 merge.check_own_run, 现有用例里不带 run_id 的报告随之失败. 改为报告稿自带 language (取起草它那次执行的), 判断与计划照旧按 run_id 查执行记录.
- **前端怎么拿到执行的语言:** 总览本来就读全部执行记录, 加一项 run_languages, 不另加接口; 轮询的总览随新执行更新.
- **取值校验在路由里:** 请求体 language 为字符串, 不在 zh, en 时报 422 INVALID_VALUE (验收 2); 写成 Literal 会落到请求体校验的通用 422, 没有错误码.
- **不取项目锁:** 后台执行时也能改 (取锁会常报 ENGAGEMENT_BUSY); 改之后才建的执行取新值. 锁定判断走存储的 writable 一路 (EngagementLocked → 423), 锁住项目行后读旧值再改, 并发的两次修改不会都记成 "en → zh".
- **留痕:** 同 rerun_trail 的写法写 decision 留痕, payload {action, from, to}; 没有决定对象, 不进 decisions 表, 不带防重复键. 先改项目后写留痕: 留痕写失败时接口报错, 语言已改而缺这一行, 没有可供 recover 补写的依据.
- **旧数据:** 执行记录与报告稿存在审计产出的 JSON 里, 不迁移; 旧行与旧检查点读回为 en (那时的输出都是英文).
- **修改入口:** 工作台页头的下拉, 选了即提交, 项目锁定时不可改. 新建表单缺省取界面语言.
- **标注的含义:** 标注的是执行记录记下的语言. 提示词按工作语言出中文属 Issue #51 后续的需求, 本条只负责记录与标注.
