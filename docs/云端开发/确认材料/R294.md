## 讲解

### 三种写法

1. 用例里直接取目录: `snapshot_dir("20261017-q1")`, `supplements_dir("20261017-q1")`, `raw_dir()`, 用例标 `@pytest.mark.external`. 例: test_dataset_loaders 的更正分录用例, test_sheet_intake 与 test_import_batches 读网页导出, test_table_plan 的 `raw()` 与 `snapshot()` (后者缓存 Snapshot 对象, 同原先模块级的 Q1, MOCK).
2. 收集阶段要路径的 (模块常量, 参数化, 登记表): 用 `snapshot_location`, `raw_location`, `supplements_path` 只拼路径, 用例经 `needs(...)` 或模块的 `pytestmark = [external, usefixtures(...)]` 先取核对数据的 fixture. 例: test_demo_default, test_dataset_mocks, test_xero_case 的 `needs_snapshot = needs("q1_snapshot", "q1_supplements")` (原来是 `skipif(not 目录.is_dir())`); test_xero_supplements 与 test_xero_demo_data 用模块 pytestmark (原来整个模块按目录存在与否跳过).
3. 有数据才多断言的: `optional(snapshot_dir, ...)`. 例: test_clients 的客户列表 (有快照时另核对 Xero 那一行), test_knowledge 的数据集特征 (有补造目录时另比 dataset_traits.json), test_dataset_loaders 的 mock 快照分支, test_xero_supplements 的 "补造目录下没有该快照".

参数化里不能放 usefixtures (pytest 不许), 所以 test_sheet_intake 的联网用例改为参数 `(是否网页导出, 文件名, 表种类)`, 网页导出一行标 external, 用例里经 raw_dir 取路径 (排在取模型配置之前, 跟踪了却找不到时不因没配模型而跳过); 用例 ID 与原来相同. 连库用例 (test_persistence_postgres, test_demo_import_db) 同样把定位提到 "没配 TEST_DATABASE_URL 就跳过" 之前.

### 标在哪些用例上

规则: 经 tests.external 取 Xero 数据的用例都标 external, 包括经辅助函数间接取的 (fakes.xero_snapshot, xero_document, xero_fakes 的各函数, test_xero_link 的 FakeXero). 为了不漏标, 用审计钩子 (sys.addaudithook 的 open, os.listdir, os.scandir 事件) 在默认测试串行跑一遍时记下每个用例 (含其 fixture) 打开或列出 data/external, data/xero_demo 下的哪些路径, 与 external 标记对照; 每个用例开始前清空 tests.* 与 backend.* 的 functools 缓存, 免得缓存掩盖读取; conftest 会话 fixture 的原目录哈希守护不计. 探针放在会话的临时目录, 不入库; 只记路径是否命中, 不读不打印内容. 第一遍 (ed4640b 上) 查出 96 个读了却没标的用例 (多是 R114 起已经经 xero_snapshot 定位, 但从没标), 按 ast 找到函数逐个补标. 变基到 2772464 后再跑一遍: 第十六批与 R270 新增的用例里读外部数据的都已标 (test_demo_import 与 test_demo_import_api 是模块级标记), 读了却没标的只剩下面 test_clients 的 8 个; 收集阶段读外部数据的为 0.

没标的: test_clients 的 8 个用例只因接口经应用自己的配置 (DATASET_ROOT) 列出 `data/external/xero/api` 下的数据集目录, 用例不取, 也不依赖其中的数据 (没有快照时列表少一行, 断言照样成立). 同理 test_datasets_api 的 demo 一例改为把 Xero 根指向不存在的临时目录 (原来用仓库的快照根, 却不断言 Xero 行).

标了却没读到文件的 (只在默认测试里看): test_dataset_mocks 的 "mock 快照没有补造目录" 用例 (要求 mock 快照在, 定位只看文件在不在, 不打开) 与 test_demo_import_plan 原有的模块标记, 照留.

### 不改的直接路径

grep `data/external`, `data/xero_demo`, `"external" /`, `"xero_demo"` 的其余命中都不是定位外部数据:

- tmp 下的副本目录名 (`tmp_path / "xero_demo"`, 注入副本的 `api/`, `xero_demo/`), test_llm_call 在 tmp 下自造的数据集目录.
- test_external.py 在 tmp 下自造的假仓库 (测定位函数本身), `tracked("data/external/...")` 的参数.
- test_cuad_fetch 与取数工具 tests/tools/cuad_fetch.py: 工具的缺省目标 `DEFAULT_DEST`, 用例断言它与 `git check-ignore` 的路径 (测工具与 .gitignore, 不读数据).
- test_xero_demo_data: `.gitattributes` 规则的字面量与 `git check-attr` 的路径; 生成脚本输出守卫的参数 (`--out data/xero_demo/../xero_demo/20261017-q1`) 与别名路径 (测守卫认路径的写法; 快照一项改为按脚本常量 `generator.SNAPSHOTS` 推出).
- docstring 与注释.
