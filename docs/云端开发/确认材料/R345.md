来由: 10-20 用户 "进入端到端测试, 模拟用户行为进行测试, 使用真实模型". 规模 M, 档位 high (只加测试工具, 免审). 父提交为开发头 d45b4fb. 不改产品代码, 发现的问题列在下面, 由协调者另立需求.

## 改动摘要

- `tests/e2e/walk.mjs`: Node 版 Playwright 驱动 Chromium, 英文界面, 按状态走 (同 R311 的 drive).
  - 每轮先读总览, 待决任务与数据概览, 再定下一步, 依次看: run_error, 已归档, 待决复核任务, 概览建议导入的演示资料, 等数据就绪, 当前闸门. 都不是时记 "流程停住".
  - 页面操作: 注册登录; 新建项目 (客户下拉的演示公司); 数据管理页按 "Demo data" 的按钮导入; 点 "Data complete, continue planning" 并写理由确认; 闸门在 /gate 表单视图决定; 复核在 /reviews/<任务> 表单视图提交.
  - 闸门决定: ACC-01 approve; PLN-01/03 按 R119 的重要性; 打开 planning 时 PLN-15 先退回再批准 (勾不需要专家); FIN-01 mock 选无保留, live 选汇总表的候选意见; RPT-01 先退回 (段落批注) 再签字.
  - 复核决定取 R311 的 decision_table: 确认, 推翻, 认定错报 (附错报草稿), 争议处置, failed 任务每个对象至多重跑一次.
  - 每步截图 `shots/NNN-<步骤名>.png`, 提交前另截一张填好的表单 (`-form`); 记控制台报错与失败请求; 超时记 "卡住"; 认不出的状态记问题并停下, 不硬闯.
- `tests/e2e/harness.py`: 起后端, 起前端, 跑驱动, 写报告.
  - 后端: 真实的 create_app 与 lifespan, 配置取环境变量, 连 TEST_DATABASE_URL, 检查点用 postgres; 启动时的 recover 换成空操作.
  - 前端: 在 src/frontend 起 vite dev, 配置与依赖缓存都在输出目录.
  - 报告: report.md 含概况, 问题表 (步骤, 页面, 现象, 截图, 期望), 各步, 用量 (调用, token, 花费), 判断的建议动作与固定输出对照.
- `tests/e2e/test_browser_walk.py`: test_browser_walk_mock 与 test_browser_walk_live, 都标 slow, external.
  - live 另标 live(max_calls=160), 取 live_budget, 配置经 live_llm_settings 取, 没配时跳过.
  - 汇总与硬性检查复用 R311 的 evaluate, assert_hard, warn_soft.

## 方案取舍

- 用 node 版 Playwright: /opt/node-tools 已有, Chromium 在 /opt/pw-browsers; 不往 Python 依赖加 playwright.
- 推进只经页面, 读状态经接口 (总览, 待决任务, 数据概览), 用来决定下一步与核对. 判断停在哪, 从页面文字推断不如接口可靠.
- 闸门与复核用表单视图: 控件有稳定的 id, 与工作区的对话卡片是同一个决定组件 (GateDecisionCard, 复核表单). 工作区的对话流本身没有逐项走, 列在环境限制里.
- 后端与驱动在同一个测试进程: 后端预算装在 lifespan 建好的依赖上 (同 R311 install_budget), 走完用同一个 runner 做 R311 的汇总.
- recover 换空操作: 测试库是共用的, 里面有别的用例留下的项目, 走查只管自己新建的这一个.
- vite 原地起, 不复制前端: 前端的 node_modules 链到主仓库, 那里不能写.
  - 依赖预构建缓存 (cacheDir) 与配置文件都放在输出目录, 所以 node_modules/.vite 与 .vite-temp 都不写.
  - 配置文件用 .mts, 因为输出目录没有 package.json, 要按 ESM 读.
  - 第一版的副本做法曾把缓存写进主仓库的 node_modules/.vite, 已报协调者, 已改.
- 404 NOT_AT_GATE 不算失败请求: 停在闸门以外时页面也会问 GET /gate, 提交决定后还有 R346 那一次. 报告概况单列它的次数.
- 控制台的 "Failed to load resource" 不另记: 同一失败已按请求记过.

## 跑法

在 wt-jia 下, 四个库变量指向测试库 (写法同交接说明, 不在这里写口令), 迁移在 head, 检查点表已建:

```
DATABASE_URL=... DATABASE_OWNER_URL=... TEST_DATABASE_URL=... TEST_DATABASE_OWNER_URL=... \
uv run pytest -m slow -p no:cacheprovider tests/e2e/test_browser_walk.py::test_browser_walk_mock -q

LLM_ENV_FILE=<含 LLM_MODEL 与 LLM_API_KEY 的文件> <同上四个库变量> \
uv run pytest -m slow -p no:cacheprovider tests/e2e/test_browser_walk.py::test_browser_walk_live -q
```

工具: node, /opt/node-tools/node_modules/playwright (E2E_NODE_MODULES 可另指), /opt/pw-browsers (PLAYWRIGHT_BROWSERS_PATH), src/frontend/node_modules; 缺任何一项时跳过. 输出目录 E2E_OUT 可另指.
