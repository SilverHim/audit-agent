## 方案取舍

- **参数与建 Run 同口径, 但不调 nodes.build_run**: agents 不导入 orchestration. 两行解析写法相同, 用例逐条与 build_run 的参数快照比对, 防止两边走岔.
- **校验分级**:
  - 引用级失败即返回, 不再查语义.
  - 语义级的问题一并列出: 程序说明缺, 多或重复; 时间表早于期末 (等于期末可以); 缺必备段或只有空白; 段里重复 overall_strategy; EQR 依据为空.
  - 两级都不重试. 校验缺上下文时抛 ValueError, 不静默放过.
- **失败与修订**: Agent 抛 ValueError, 经 run_agent 转为 failed 执行与只能 rerun 的任务. 第 2 修订找不到针对上一修订的驳回时抛 LookupError, 不按无理由重拟.
- **PLN-15 本身不改状态** (仍 planned, Q5): 由 R205 的闸门批准完成.
- **固定输出里有两项提示词输入没有的事实** (请确认): 外勤 10-19 至 10-22 与报告日 10-23 (项目没有计划日期字段); 超级年金应付 826 (试算表只列有余额的科目). 两项都按验收 3 与设计稿第 2.3, 2.7 节写, 接口文档第 6 节已注明. 真实模型拿不到这些; 时间表只校验不早于期末.
- **提示词不渲染程序名称** (R203 的写法), 模型只看到编号与参数. 程序说明是按程序含义写的.
