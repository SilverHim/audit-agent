## 讲解

- **为什么对应关系放在 test_xero_fixtures 而不放进 FIXTURE_SETS.**
  - 范围写明 FIXTURE_SETS 的 Xero 一行与 test_knowledge.py 不在本条登记.
  - REV-02 要从发票 ID 找到关联合同, 须读快照. 放进登记表, test_knowledge 的守卫就会依赖快照.
  - 放在这里, 只在出现 REV-02 的 fixture 时才读快照.
- **为什么文件 ID 从 PDF 内容算.** 验收写的是 "DOC- 加该 PDF 的 sha256 前 12 位". 从文件算, 不信 manifest 的 document_id, manifest 写错也查得出. 页码与类型仍按 manifest 核对 (原有的 (b)).
- **现在的正本只有 DOC-04 与 DOC-CLASSIFY.** REV-03, REV-02, CSH-02, GEN-09 的 Xero fixture 由 R109 以后的需求加, 加了就自动受这条核对. 那些对象的对应关系由自测先核对 (用 Numbat 的同程序 fixture 改指针造).
- **对照用例为什么改原用例而不新增.** 原用例直接调 extract_contract, 抹掉执行 ID 后与 xero_contracts() 比较. 经 IngestAgent 的版本覆盖了它的断言, 并多核对留痕行数与执行 ID; 两个并存就是同一事实测两遍.
