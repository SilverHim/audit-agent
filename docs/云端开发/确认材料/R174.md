## 方案取舍

- **凭证号不重写:** R156 已在 `contracts.models.verified_adjustment_entries` 定了 "已验证更正分录" (接口文档第 2.5 节, 承接 AP-51). verified_entry_nos 只是从状态取 misstatements 交给它, 不在 adjusted_tb 里再写一份条件. 需求说 "取数做成公共的一处", 这里是两层: 定义在 contracts, 取数入口在 adjusted_tb.
- **adjusted_balances 自己筛:** 收全部试算表行 (只取 period current) 与分录行 (只取凭证号在 entry_nos 中的). 调用方可以直接传 `trial_balance(eid, "current")` 与 `journal_entries(entry_nos=...)`, 也可以传更宽的行, 结果相同. 返回按科目代码排序的 dict, 与函数的行序一致.
- **函数排序用 COLLATE "C":** 与 Python 的 sorted 一致, 不随库的区域设置变化 (同 0018 的做法). 没写 coalesce: `= ANY(NULL)` 不为真, NULL 与 {} 都只取试算表, 连库用例断言两者相同.
- **函数也按 p_eid 筛:** 行级安全已限定到绑定的项目, p_eid 的条件是让 "绑定 A 而传 B" 时不把 A 的行当成 B 的返回. 连库用例两个方向都断言了.
- **M01 同口径怎么验:** 不在用例里另写一遍 M01, 而是取 PLN-01 模板的 SQL, 把余额来源那一段 (trial_balance JOIN accounts, 本期) 换成 `adjusted_trial_balance(:eid, :entry_nos)` (断言那一段恰出现一次), 其余不动. 列表为空时与原 SQL 的结果相同, 都是 3243100, 1080529, -1322696.
- **不动现有模板:** FIN-15, FIN-02 属 G6 段, 本条只提供函数与 ref; 现有模板都不引用新 ref (验收 7).
- **迁移编号:** 基线 head 为 0021, 本条取 0022. 并行的其他分支若先合入 0022, 合入时改编号与 down_revision (需求写明 "编号取合入时下一个"); 测试 `test_migration_chain_has_one_head_with_adjusted_trial_balance` 会在撞号时失败.
