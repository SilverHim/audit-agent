# R355 确认材料: 无归因任务的呈递也给大模型没通过校验的原因

来由: R347 严审意见 R347-10; 走查驱动一项为 10-20 协调者并入. 规模 S, 档位 high. 分支 yi-r355, 基于开发分支 439ff03 (含 R347). 不需迁移.

## 改动摘要

- `services/presentation.py`: 新 `call_failure` (last_llm_call 那行的 level_failed, errors, attempts, trail_id; 找不到为空), failed 与 unattributed 共用; `failure_of` 的 unattributed 在规则三项之外并入它, source 仍为 exception; 新 `reads_llm_calls` (带对象的 failed 与 unattributed 任务才读 llm_call 留痕); `last_llm_call` 在任务不带对象时为空.
- `api/routes/reviews.py`: 呈递按 `reads_llm_calls` 决定是否读 llm_call 留痕 (原来只有带对象的 failed 读, 不改这里 unattributed 拿不到调用).
- `contracts/views.py`: PresentedFailure 的说明写明各出处填哪几项, 四个字段的注释加上 exception. 接口文档第 10 节的模型与 "判断呈递" 的 failure 一条同步. 重新生成 openapi.json 与 src/client (只有说明文字).
- 前端: `lib/presentation.failureParts` (失败原因一栏依次显示的几段: 规则与明细, 调用次数与没通过的校验, 错误); `concierge.tsx` 的 FailureDetail 按它渲染, 两种出处用同一段调用的显示.
- 走查驱动 `tests/e2e/walk.mjs`: unattributed 任务也先重跑一次, 规则同 R347 的 HTTP 驱动 (`tests/live_walk.review_body`): 计数键同 rerun_key, 每个对象至多一次, unattributed 重跑后仍失败才按决定表推翻或认定错报, 下 rerun 时同程序同一次执行 (run_id 相同) 其余待决的可重跑任务一并计数 (同 decisions.rerun_group, R347-14); 可重跑的任务类型由配置给 (live_walk.RERUNNABLE, 由 review_queue.RERUNNABLE 推出), 驱动里不另写. `tests/e2e/test_browser_walk.py`: browser_walk 可让指定对象先失败几次 (主模型换成 FlakyLLM 包装), 新用例 `test_browser_walk_mock_reruns_unattributed`.
- 测试: tests/test_presentation.py (新用例, 带对象 failed 的用例改用共用的装配); 前端 tests/presentation.test.ts.

## 方案取舍

- **不填 subject_id:** 验收 1 只列规则三项与调用的四项; 对象已在任务上 (task.subject_id), unattributed 的 failure 不另写.
- **路由一并改:** 范围里没列 reviews.py, 但呈递原来只为带对象的 failed 读留痕, 不改这里验收 1 经接口不成立; 判断写成 presentation 里的一个函数, 路由与 failure_of 的说明都引用它.
- **前端抽成纯函数:** 前端用例只测纯函数, 显示哪几段由 failureParts 决定, 组件只做渲染; 例外一支的行距与调用一支统一为同一个容器 (failed 任务的显示不变).
- **不带对象的保护:** last_llm_call 原来只被带对象的 failed 调用; unattributed 也走它后, 任务不带对象时不能按 "空对象" 去配没记对象的行, 加一行判断并有用例.
- **走查驱动的自测:** mock 走查本来没有失败任务, 走不到这一支; 照 R347 的 HTTP 驱动自测 (offline_walk 的 FlakyLLM), 让 ORC1026 (带 REV-08 的 R03-1) 前 3 次输出不是 JSON. 同组计数这一支 mock 里没有同一次执行的两条失败, 按 HTTP 驱动最终版的条件照搬 (同程序且同 run_id).
