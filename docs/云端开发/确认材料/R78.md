## 讲解

### 业务背景

- 原来 mock 模式只有一个 fixture 目录 (LLM_FIXTURES_ROOT). Xero 项目也读 Numbat 的固定输出, 两套数据集的 fixture 会互相弄红守卫 (critique C14).
- 设计第 9.1, 9.5 节与主代理裁定第 2 至 4 批定下:
  - Xero fixture 的正本放 tests/fixtures/llm_xero.
  - 运行副本由生成脚本复制到补造目录的 llm/.
  - mock 按项目数据集选目录.
  - 守卫按数据集参数化.
- 本条只立机制与守卫. 各程序的 Xero fixture 由各程序段写.

### 契约与 prompt_hash (验收 1)

- `LLMRequest.eid`: 所属项目. mock 按它定目录; live 不用, 不发给服务商.
- prompt_hash 只算 system 与 messages, llm_call 留痕的 payload 也不含 eid.
- 实测: 分别在本条之前 (6ce964a) 与之后跑 R55 全流程, 15 行 llm_call 的 (程序, fixture_key, prompt_hash) 逐行相同.

### DatasetFixtureLLMClient (验收 2)

- `directory(eid)` 依次判断:
  - eid 为空, 没有项目存储, 或查不到项目: LLM_FIXTURES_ROOT.
  - 数据集不以 "xero/" 开头 (如 demo): LLM_FIXTURES_ROOT.
  - 快照名不是一段目录名 (含 "/" 或为 "." / ".."): LLM_FIXTURES_ROOT.
  - DATASET_ROOT/xero_demo/<快照>/llm 存在: 该目录; 否则 (如 20261017-mock 没有补造目录) LLM_FIXTURES_ROOT.
- `complete`: 目录为根目录时走 MockLLMClient 本身; 否则用该目录的 MockLLMClient. 读法相同: {procedure_id}/{fixture_key}.json, 退回 default.json, 都没有为 fixture_not_found.
- 两点实现上的取舍:
  - 用 DATASET_ROOT 推出目录 (同需求原文), 不经载入器的补造核对. 补造目录的哈希核对在建项目与载入时已做, 这里只读 JSON.
  - 做成 MockLLMClient 的子类, "mock 模式下是 MockLLMClient" 的现有断言 (test_llm_live, test_llm_settings) 不用改.
- 组装根与 make_deps 的主模型, 复核模型都包着它. GEN-09 (复核模型) 的 Xero fixture 因此同样读运行副本 (验收 5).

### 目录约定与生成脚本 (验收 3)

- 正本: tests/fixtures/llm_xero/<程序>/<对象>.json, 各程序段写.
  - fixture_key 同接口文档第 4 节.
  - document 指针直接用 manifest 的文件 ID (DOC- 加 sha256 前 12 位).
- 生成脚本:
  - 先删掉补造目录的 llm/, 再写 README.md ("Synthetic – for demonstration only", 说明来源), 再原样复制正本的 */*.json. 正本删掉的文件不会留下旧副本.
  - 正本根目录, 程序目录或文件是符号链接时拒绝, 在清空之前查, 被拒时 llm/ 保持原样.
  - llm/ 下各文件列入 manifest.files (synthetic 为真).
- 校验脚本的重新生成比对 (check_determinism) 从正本重新生成, 所以正本改了而没重跑生成脚本时, 校验也会报出.
- 为什么写 README.md: 正本目前为空, git 不记空目录. 有了说明文件, 运行副本根才存在, FIXTURE_SETS 的守卫不会报 "运行副本未生成". 正本目录也放一份说明作占位.
- 加或改 fixture 的需求须重跑生成脚本并一起提交 (README 与接口文档写明).

### 守卫 (验收 4)

- FIXTURE_SETS 加 xero 一行: tests/fixtures/llm_xero, data/xero_demo/20261017-q1/llm, 该目录的 manifest, 期望 PDF 函数为空.
- (a) test_knowledge 的两个守卫按登记表各跑 numbat 与 xero:
  - 运行副本与正本的文件集合与内容相同.
  - 指针在 manifest 中且页码不超过页数.
  - numbat 的断言不变.
- `tests/test_xero_fixtures.py` 的 `fixture_problems` 只对 Xero 核对 (b) 至 (d):
  - (b) document 指针的 source_id 在 manifest.documents 中, 1 ≤ page ≤ page_count, 所指文件类型不是 other.
  - (c) 目录名是程序库中 (含未启用的) 带 llm 段的程序; 文件能按该程序的输出模型解析. GEN-09 的 {对象}-r2 按 VERDICT_SPEC 的输出模型.
  - (d) 按集合包含断言, 不写死文件清单, 目录为空时通过.
- 自测 `test_fixture_problems_are_reported`: tmp 正本里放各种文件.
  - 合格的 CSH-02 fixture (指针改指 Xero 回函) 不报.
  - 以下各被报出: 未知程序目录, 没有 llm 段的 ACC-01, 不符合输出模型, 指针不在 manifest, 页码超出, 页码为 0 或空, 指向 other 类型 (fs_v1.pdf).
- Numbat 的 fixture 文件一个没改. test_fixture_document_ids_in_manifest[numbat] 与 assert_fixtures_used_once 只看 tests/fixtures/llm.

### Numbat 回归 (验收 5)

- demo 项目的 eid 查到的数据集是 demo, 所以读 LLM_FIXTURES_ROOT (测试为 tests/fixtures/llm). R55 的 llm_call 行数与各 fixture_key 不变, 含 GEN-09 两行.
- 直接构造 MockLLMClient 的测试 (test_e2e_live_checks, test_dispute, test_llm_call) 不变.
