## 讲解

### 业务背景

Xero Demo Company 的快照只有账务数据. 审计演示还需要约定书, 登记摘录, 合同, 回函, 工资册, 更正分录等文件, 这些只能补造. 补造有两条硬约束:

- 原始数据不改: 快照只读, 补造文件放在独立目录 `data/xero_demo/<快照名>/`, 每份标明合成.
- 不写出 Xero 登录账号联系人: 快照的 contacts.json 里有用户本人的姓名与邮箱. 生成脚本不读这个文件, 校验脚本只在内存里拿它比对, 确认任何补造文件, 生成规格, 设计文档与 Xero fixture 里都没有出现.

补造内容很多 (第 4 节 29 份文件), 分 R63 至 R68 六条做. R63 搭框架: 生成规格的结构, 白名单读取, PDF 写法, manifest, 校验, 确定性. 同时生成第一批结构化文件: 数据集声明 (程序参数 `{ref: dataset.<键>}` 用), 客户画像 (覆盖载入器从组织信息推出的通用画像) 与计划预置.

### 生成规格 `data/xero_demo_spec.json`

全部合成内容 (人名, 日期, 条款, 号码, 正文) 都写在这里, 脚本不现编, 所以改内容只改规格, 两次生成逐字节相同. 顶层键与需求验收 1 一致:

- `header`: PDF 每页第一行的页眉原文.
- `traits`, `profile`, `planning`: 原样写成 dataset_traits.json, client_profile.json 与 planning 两份.
- `registry`, `documents`, `contract_links`, `delivery_notes`, `bank_accounts`, `receipts`, `payroll`, `adjustments`, `financial_statements`, `manual`: 本条为空. 其中 `documents` 是每份 PDF 的登记信息 (类型, 可靠性, 文件日期, 关联对象, 登记途径, xero_refs), manifest 从这里取.
- `notes`: 说明快照里 NAB, National Australia Bank, Ridgeway Savings, Business Savings Bank 是 Demo 的占位银行名, 两户都在虚构的 Wattlebrook Bank Limited (第 2.2 节).

画像 ID 是 `CLIENT-XERO-3C1332BB-Q1`, 带后缀是为了与载入器给 20261017-mock 生成的 `CLIENT-XERO-3C1332BB` 区分 (第 2.6 节).

### 生成脚本 `data/generate_xero_demo.py`

用法: `uv run python data/generate_xero_demo.py [--snapshot 20261017-q1 或快照目录] [--out 目录] [--inject 场景]`.

- `Snapshot`: 只读的快照目录, 接口与载入器的 `adapters.xero_dataset.Snapshot` 相同, 所以能把它传给载入器的映射函数.
  - `load(name)` 只许白名单 `READABLE` (accounts, invoices, credit_notes, journals, bank_statements, organisation, dataset) 与 trial_balance_*, 其余抛 ValueError.
  - `file_hashes()` 只读字节算 sha256, 不解析, 不含 contacts.json.
- `resolve_snapshot(value)`: 不含路径分隔符时是快照名 (在 `data/external/xero/api/` 下), 含分隔符时是目录路径.
- `inside(path, root)`, `same_path(a, b)`, `out_problem(out, snapshot_dir, inject)`: 输出目录守卫.
  - --inject 只许仓库外已存在的副本目录.
  - 普通生成只许 `data/xero_demo/<快照名>` 或仓库外的目录.
  - 两种模式下, 已有的输出目录里有符号链接或硬链接时都拒绝 (防止顺着链接改到别处的文件).
  - 不合规时 main 返回 2, 不写任何文件.
- `write_json(directory, name, value)`: 两格缩进, 不转义非 ASCII, 末尾换行.
- `write_pdf(path, pages, footer, header)`: 后续各条共用的 PDF 写法, 照 `data/generate_demo.py`.
  - 版式: A4 (595 × 842), Courier 9pt, 行距 13. 每页第一行是页眉原文, 空一行后是正文. 页脚 Helvetica 8pt, 写 "{footer} | Page n of N".
  - `invariant=1` 使两次生成逐字节相同.
  - 先检查每页正文不超过 `PAGE_LINES` (56) 行, 每行 (含页眉) 不超过 `LINE_WIDTH` (95) 字, 超限抛 ValueError (只写页号与行数), 由规格自己分页.
- `RefIndex(snapshot)`: 快照里可引用的对象, 用于核对 manifest 的 xero_refs.
  - 认的对象: 科目代码, BA-{银行科目}, SI-{InvoiceID} (只含已生效的销售发票), XJ-{分录号} 与分录行 XJ-{分录号}-{n}, BT-{科目}-{序号}.
  - 编号与范围复用载入器的 `journal_entries_from_api`, `journal_rows`, `map_bank_transactions` 与 `LIVE_DOCUMENTS`, 这些函数只读白名单文件.
  - 不用 `build_tables` 与 `map_sales_invoices`, 二者会读 contacts.json.
  - `missing(refs)` 返回找不到的.
- `profile_prefix(snapshot)`: 由组织 ID 推出画像 ID 应有的前缀 `CLIENT-XERO-{短 ID}-`, 缺组织信息时为 None.
- `generate(snapshot_dir, out)`: 按顺序做以下几步.
  1. 快照目录不存在, 缺组织信息, 或画像 ID 前缀不符时以 SystemExit 失败.
  2. 写数据集声明, 画像与计划预置.
  3. 调 `render_registry_pdfs`.
  4. 调 `write_manifest`.
- `render_registry_pdfs(directory)`: 按目录里的登记 JSON 重绘同名 PDF. 登记 JSON 由 R64 生成, 现在是空操作, 先定下签名供注入测试导入.
- `write_manifest(directory, snapshot_dir, injected=None)`: 重算目录内除 manifest.json 外每个文件的 manifest 项.
  - files 段每项: path, sha256, synthetic true, generator, xero_refs. xero_refs 取自规格 documents 段.
  - documents 段每份 PDF: path, sha256, document_id `DOC-{sha256 前 12 位}`, type, reliability, page_count, document_date, related_ids, registration, synthetic. 来自规格 documents 段, PDF 在规格里没有登记信息时失败.
  - snapshot 段: 快照名与各文件哈希 (不含 contacts.json).
  - xero_refs 里有快照找不到的对象时以 SystemExit 失败, 信息列出找不到的编号.
  - 不写时间戳与绝对路径. 测试副本传 injected 时写场景名.
- `main(argv)`: 先查输出目录, 再生成; --inject 时只重绘登记 PDF 并重写副本 manifest. 普通生成后调用校验, 不过返回 1.

### 校验脚本 `data/check_xero_demo.py`

用法: `uv run python data/check_xero_demo.py [--snapshot 20261017-q1] [--dir 补造目录]`.

`check(directory, snapshot_dir, *, determinism=True, scan=SCAN_PATHS) -> list[str]` 返回说明 (如没有快照时跳过了什么), 任一项不过抛 `CheckError`. 异常信息每行一项问题, 只写文件名. 步骤:

1. 读 manifest.json, 用结构模型 `Manifest` 严格校验 (顶层与 files 项不许多字段, documents 项只要求 path 与 sha256, 登记字段留给 R64 核对). 不合格只报这一项.
2. 下面各项用 `guarded` 包住, 某项意外异常时记 "{文件}: 校验中断 ({异常类名})" 后继续, 不带异常消息, 免得带出文件内容.
   - `check_manifest`: 重算哈希; 目录里有而清单没有, 或清单有而目录没有的文件; documents 段与 files 段的哈希一致; 每份 PDF 都在 documents 段; spec_sha256 等于当前规格; 正式目录不许有 injected.
   - `check_synthetic`: 每个文件 synthetic 为真, generator 为生成脚本; 每份 PDF 每页文本层含页眉原文; 画像 notes 以 "Synthetic – for demonstration only" 开头.
   - `check_models`: client_profile.json, planning 两份按 ClientProfile, AuditObjective, RiskItem 严格校验 (领域模型本来就不许多字段, strict 再禁止类型转换); dataset_traits.json 的键集合等于第 5.2 节的 11 个键 (`TRAIT_KEYS`).
3. 有快照时再做:
   - `check_snapshot`: 快照名与各文件哈希等于 manifest 所记, 不符即 "补造文件与快照不匹配"; 画像 ID 以快照组织 ID 推出的前缀开头.
   - `scan_login_contact`: 见下.
   - `check_determinism`: 另生成到临时目录, 逐文件逐字节比较; 无法重新生成时记原因 (生成脚本的 SystemExit 写消息, 其余异常只写类名).
4. 没有快照时跳过第 3 步, 说明含 "没有本地 Xero 快照"; 第 1, 2 步照常.

登录账号联系人扫描 (第 9.4 节口径):

- `login_contact(snapshot_dir)` 在内存里读 contacts.json, 取 IsCustomer 与 IsSupplier 都为假, 且有 FirstName 与 EmailAddress 的联系人.
  - 必须恰好 1 条. 快照里双否的联系人有 39 个 (含员工与银行), 所以要加 FirstName 与 EmailAddress 两个条件.
  - 返回全名 (FirstName 加空格加 LastName) 与邮箱.
  - 文件缺失, 无法解析或条数不对都抛 CheckError, 信息只写条数.
- `normalize` 统一转小写, 连续空白视为一个空格. PDF 文本层与 JSON 字符串里名字可能被换行隔开.
- `text_of(path)` 取要扫描的文本: PDF 取文本层 (内容流是压缩的, 不能按字节扫); JSON 另加解码后的全部字符串 (处理 \n, \u 转义); 其余按 UTF-8 读.
- 扫描范围: 补造目录全部文件, 生成规格, 设计文档, `tests/fixtures/` 下的 llm_xero, llm_xero_only17, xero_injections, llm_injected (不存在的跳过).
- 整串匹配, 不单独匹配姓或名, 因为短字符串会在普通单词里误中.
- 命中或读不出文本层的 PDF 只报文件名.
