## 改动摘要

- 契约 `contracts/ports.py` (FinancialDataStore):
  - `journal_entries(eid, *, entry_nos=None, source_docs=None) -> list[JournalEntry]`.
  - `accounts(eid, codes=None) -> list[Account]`.
- `persistence/stores.py` (PostgresFinancialDataStore): 两个方法各一条查询 (按项目绑定, 走行级安全).
  - journal_entries: `entry_no IN (...) OR source_doc IN (...)`, 只拼给了的条件, 按 id 排序.
  - accounts: codes 给了才加 `code IN (...)`, 按 code 排序.
- `tests/fakes.py`:
  - FakeFinancialStore 加 `accounts` 构造参数 (科目表可注入), 两个方法同真实实现的语义 (分录行取自 records 中的 journal_entry 行).
  - NUMBAT_ROWS 补 SJ-2026-0612-1/-2, SJ-2026-0618-1/-2 四行, 第 1 轮另补 SJ-2026-0547-1/-2 与 CR-SI-2026-0547-2 (R99-04); 新增 NUMBAT_ACCOUNTS (1100, 4100).
  - xero_financial_store 把映射出的科目表一并装进假存储.
- 测试:
  - test_fakes: 补的行与 data/demo 载入所得相同; journal_entries 与 accounts 的语义.
  - test_persistence_postgres (slow): Numbat data/demo 上的验收 2.
- 接口文档第 4 节 FinancialDataStore 加两个方法.

## 偏离需求原文之处

1. "两个条件都为空抛 ValueError", "codes 为空取全部" 中的 "为空" 我按 None 处理 (同 `contracts(ids=None)`): 两个都为 None 抛错; 给了空列表的条件取不到行 (`entry_nos=[], source_docs=[]` 得 [], `accounts(eid, [])` 得 []). 调用方从数据算出的列表可能为空, 这时得空结果, 不报错, 也不变成取全表.
2. 需求写 "NUMBAT_ROWS 补 ... 与科目 1100, 4100". NUMBAT_ROWS 是 record 可取的行 (按行 ID 建 NUMBAT_RECORDS), 科目没有行 ID, 也不是 record 的行类型, 所以科目另放 NUMBAT_ACCOUNTS, 经 `FakeFinancialStore(accounts=...)` 注入.
3. 范围外加了一处: tests/fakes.py 的 xero_financial_store 同时装入 Xero 科目表. 现有测试不读它, 只为之后 JR-3, MD-3 在 Xero 假存储上取科目.

## 讲解

### 业务背景

- REV-02 的上下文要有发票入账的整笔分录 (借应收, 贷收入), 提示词据科目名与标准分类认出收入行 (设计稿 v2.1 第 5.1 节 REV-02 一行, 核查 M3).
- critique C12 推荐合并签名 `journal_entries(eid, entry_nos=None, source_docs=None)`: JR-3 按凭证号取, MD-3 按单据号取. 本条先立, 之后只复用, 不再改 Protocol.
- 本条只加读取方法, 不改任何调用方; REV-02 上下文的改动在后续需求.

### 签名与语义 (验收 1)

- journal_entries:
  - 满足任一给定条件的行; 同一行两个条件都满足只出一次 (SQL 的 OR, 假存储按行 ID 存).
  - 按行 ID 升序.
  - 两个条件各管各的列: 单据号不会当凭证号匹配, 反之亦然.
  - 两个都为 None 抛 ValueError "journal_entries 须给 entry_nos 或 source_docs, 不取全表".
- accounts: 按代码升序; codes 为 None 取全部. 标准分类按载入时所存 (各载入路径写入前都按名称补分类); 迁移 0002 之前载入的旧项目为空, 本方法不补 (同 DataStore.account).

### Postgres (验收 2, slow)

`test_journal_entries_and_accounts`, 项目载入 data/demo:

- `entry_nos=["SJ-2026-0612"]`: [SJ-2026-0612-1 (1100, 借 14200000), SJ-2026-0612-2 (4100, 贷 14200000)], 与假存储 NUMBAT_ROWS 中的两行逐字段相同.
- `source_docs=["SI-2026-0612"]` 得同样 2 行; 两个条件同时给仍是 2 行.
- 凭证号 SJ-2026-0618 加单据号 SI-2026-0612: 4 行, 按 ID 排序.
- 拿单据号当凭证号查得 []; 两个空列表得 [].
- 另一项目 eid ("other-project") 得 [] (行级安全).
- 两个都不给抛 ValueError.
- `accounts(eid, ["4100", "1100"])`: [1100 Trade receivables asset receivables, 4100 Sales revenue revenue revenue], 等于 NUMBAT_ACCOUNTS (含 category_basis name).
- `accounts(eid)` 23 个, 按代码升序; 空列表与另一项目得 [].

### 假存储 (验收 3)

- `test_numbat_sales_entries_and_accounts_match_dataset`: 按 CsvDatasetLoader 的解析读 data/demo 的 journal_entries.csv 与 accounts.csv (科目按名称补分类), 假存储的 8 行分录 (4 笔整笔) 与 2 个科目与之逐字段相同, 默认测试与连库测试取到同样的行.
- `test_journal_entries_by_entry_no_or_source_doc`: records 倒序存入, 断言同验收 2 的形状, 另有 8 行的并集 (含 SI-2026-0547 的销售与收款两笔) 按 ID 排序.
- `test_accounts_by_code`: 科目倒序注入, 按代码升序; None 取全部, 空列表与不存在的代码得 [].
- main.build_deps 与 make_deps 照常构造 (全部现有测试经过它们); mypy strict 通过.

### Numbat 回归 (验收 4)

- 现有调用方不变 (本条没有调用方).
- NUMBAT_ROWS 只增 7 行: NUMBAT_RECORDS 只多 7 个 journal_entry 键, 原有键取到的行不变. 现有测试没有引用 SJ-2026-06xx 的 record (发票的 journal_entry_id 指向它们, 之前取不到, 也没有测试去取).
