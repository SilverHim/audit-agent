## 改动摘要

- 契约 `contracts/state.py`:
  - `REQUIRED_KEYS`: 由 initial_state 的参数给出的 5 个键.
  - `STATE_DEFAULTS`: 其余 22 个键的缺省值登记表.
  - `fill_defaults(values)`: 补上缺的登记键, 返回新字典.
  - `initial_state` 改为由登记表生成, 结果与原来逐键相等.
- 编排:
  - `graph.py`: 登记节点函数与路由函数时各包一层 fill_defaults (`node_with_defaults`, `fieldwork_with_defaults`, `route_with_defaults`).
  - `query.py`, `decisions.py`, `recovery.py`, `runner.py`: 读 `snapshot.values` 处都经 fill_defaults.
  - `checkpoint.py`:
    - 白名单抽成 `allowed_types()`, `_STATE_MODULES` 加注释说明登记方式.
    - 顶层枚举字段由 EngagementState 注解推出 (`top_level_enums`, `TOP_LEVEL_ENUMS`).
    - 转回枚举抽成 `restore_enums`, AuditPostgresSaver 调它.
- 文档 `docs/开发接口文档.md`:
  - 第 3 节: 签名, "缺省值与旧检查点" 一段, 新增状态字段的登记清单 (5 步), 各组将加的字段表与 misstatements 的 reducer 说明.
  - 第 9 节: OUTPUT_KINDS 守卫.
  - 第 9.1 节: AuditPostgresSaver 按 TOP_LEVEL_ENUMS 转回.
- 测试:
  - 新增 `tests/test_state_compat.py`, 13 个用例.
  - `tests/test_persistence_postgres.py` 的全流程连库测试加枚举读回断言.
- 本条不加状态字段.

## 讲解

### 业务背景

- 后续各组要往 EngagementState 加 10 个字段 (下表). 演示库里可能有在途项目, 其检查点是加字段之前存的, 没有这些键 (critique C12, verify G3).
- 节点与路由按 `state["键"]` 取值, 缺键就抛 KeyError. 例如 FIN-04 (qc.py) 读 `ctx.state["uncorrected_schedule"]`, 总览读 opinion_route.
- 另外两处写死的地方:
  - 检查点白名单只收 contracts/models.py 与 contracts/services.py 的类型, 新类型放在别处时读回被拒.
  - AuditPostgresSaver 写死只转回 phase 与 opinion_route 两个枚举.
- 本条只建兼容机制与登记方式, 字段由各组的需求加.

### 缺省值登记表 (验收 1)

- `REQUIRED_KEYS` = engagement_id, phase, version_snapshot, client_profile_version, procedure_pack. 项目启动时由 initial_state 的参数给出, 检查点里一定有.
- `STATE_DEFAULTS` 登记其余 22 个键: 列表为 [], 单对象与 int | None 为 None.
- `fill_defaults(values)`:
  - 复制入参, 对缺的登记键补缺省值, 列表用 copy.copy 取新的空列表, 不与登记表共用.
  - 已有的键原样保留 (同一对象).
  - 未启动的项目 (检查点为空) 只补登记的键, 不补 REQUIRED_KEYS. 所以 `resume_required` 里 `values.get("client_profile_version")` 照旧用 get.
- `initial_state` = fill_defaults(5 个必有键).
- 测试:
  - `test_state_defaults_cover_every_key`: `default_problems(EngagementState)` 为空; 登记表加必有键恰为注解的全部键.
  - `default_problems` 报三类问题:
    - 未登记的键, 报键名.
    - 登记了状态中没有的键.
    - 缺省值与类型不符: 列表须为 [], 可空须为 None, 既不是列表也不可空的须列入 REQUIRED_KEYS.
  - `test_default_check_names_unregistered_and_wrong_defaults`: TypedDict 子类 ExtendedState 加 going_concern 与 audit_plans 两键而不登记, 报 "未登记缺省值: going_concern" 等; 另造三种错的登记表各报一条.
  - `test_initial_state_equals_previous_literal`: 与原来逐个写出的 27 个键逐键相等; 两次调用的列表不是同一对象, 改一个不影响另一个与登记表.
  - `test_fill_defaults_fills_missing_keys_only`.

### 节点与路由的包装 (验收 2 的机制)

- `node_with_defaults(node)`: 返回 `async wrapped(state)`, 先 fill_defaults 再调 node.
- `fieldwork_with_defaults(node)`: fieldwork 收的是 Send 带来的 FieldworkInput, 补的是其中的 state. 旧检查点里待派发的 Send 带的是旧状态, 所以也要补.
- `route_with_defaults(route)`: 同理, 用于 route_schedule, after_fan_in 与四个 gate_route.
- 三个包装都用 functools.wraps, 保留原函数的名字与注解. LangGraph 按签名决定是否传 config 等参数, inspect.signature 顺着 `__wrapped__` 取到原签名, 与原来相同.
- 类型: 节点用 Protocol `StateNode` (参数名须为 state, 与 LangGraph add_node 的声明一致); fieldwork 用 `FieldworkNode`, 仍需忽略类型检查 (原来就有, 错误码由 arg-type 变为 call-overload).
- 测试:
  - `test_wrappers_fill_defaults_before_calling`: 缺 uncorrected_schedule 与 opinion_route 的状态, 加一条 FIN-01 决定:
    - 不包时 FIN-01 路由取决定绑定的汇总表, 抛 KeyError.
    - 包了读到 None, 返回 represent.
    - 节点与 fieldwork 包装都把补过的状态交给原函数.
  - `test_every_node_and_route_is_wrapped`: build_graph 登记的每个节点 (按包装函数的代码对象认) 与 6 个路由函数都经过包装. 基线与全部功能启用两种情形都核对, 以后功能组加节点时漏包会失败.

### 读检查点处 (验收 2)

- 10 处 `snapshot.values` 改经 fill_defaults:
  - `query.overview`: 原来用 get 取 4 项, 改为按键取.
  - `query.gate`.
  - `runner.resume_required`.
  - `decisions.submit` (闸门) 与 `_apply_review`.
  - `recovery.gate_values`, `backfill_transitions`, `catch_up_gates`, `catch_up_profile`, `catch_up_review`.
- DecisionSubmit 从检查点只读 procedure_pack, phase (必有键) 与 judgments (带 reducer); 材料与风险清单等读 Store. 现在的字段在这里不会缺键, 经 fill_defaults 是为以后的新字段.

### 模拟旧检查点 (验收 2)

- `drop_channels(saver, thread_id, channels)`: 从 InMemorySaver 中该线程最新检查点的通道版本表 (channel_versions) 删去这些通道. 读回时 LangGraph 按版本表取通道值, 删去的通道就没有值.
- `test_old_checkpoint_without_new_channels_runs_to_fin`:
  - 删通道的一次:
    - make_runner 加 Numbat 全部 P2 脚本 Agent, 跑到 ACC-01 闸门.
    - 删去 misstatements, uncorrected_schedule, opinion_route.
    - 先断言 snapshot.values 中没有后两个键. misstatements 带 reducer, LangGraph 读回补空列表, 断言为 [] 或缺键.
    - 断言 phase 仍为 Phase 枚举.
    - 总览与闸门材料不抛错, 总览 opinion_route 为 None.
  - 之后按 test_flow 的决定走:
    - ACC-01 approve, PLN-01/03 approve.
    - 逐条复核, 每次提交前读一次总览.
    - `assert_numbat_result` 断言停在 FIN-01 闸门前, FIN-04 读到 misstatements 出 SCHEDULE.
  - 停在 FIN-01 闸门时:
    - 总览 run_error 为空.
    - 闸门材料为 CompletionMaterial, 错报与 Store 相同.
  - 与不删通道的一次比:
    - 程序包相同.
    - SCHEDULE 相同.
    - 留痕逐行 (model_dump) 相同.
  - 接着提交 FIN-01 approve (qualified): 走到 RPT-01 闸门, 检查点 opinion_route 为 OpinionType.qualified.
- 变异核对 (本地做, 都失败):
  - 节点包装不补.
  - 总览不补.
  - fieldwork 包装不补.
  - 路由包装不补.
  - fan_in 节点或其路由不包.
  - 去掉 opinion_route 的登记.
  - restore_enums 不转.
- 总览不补时, ACC-01 闸门处读总览就抛 KeyError; 节点包装不补时, FIN-04 读 uncorrected_schedule 抛错, 停不到 FIN-01.

### 检查点类型与顶层枚举 (验收 3)

- `allowed_types()`: _STATE_MODULES 中定义的 Pydantic 类与枚举 (不含从别处导入的), checkpoint_serde 用它建 JsonPlusSerializer. 行为与原来相同.
- 测试辅助 `state_types(hint)`:
  - 递归收集注解里出现的 Pydantic 类与枚举.
  - 进入 TypedDict 的键 (如 StagedResult) 与 Pydantic 模型的字段类型, 也进入 list, 联合与 dict 的参数.
  - Literal 与 Any 跳过.
- `test_state_types_are_in_checkpoint_allowlist`: 收集到的类型含 Phase, OpinionType, AgentId, Judgment, UncorrectedSchedule; 不在白名单的为空.
- `test_type_guard_names_classes_outside_state_modules`: 测试模块里定义 LocalPlan (Versioned, 字段 list[LocalItem]), LocalItem (字段为 LocalKind) 与 LocalKind (StrEnum), TypedDict 子类加 audit_plans 与 plan_kind 两键. 报 [LocalItem, LocalKind, LocalPlan], 字段里套着的类型也报出.
- `top_level_enums(state)`:
  - 取类型为某个枚举, 或枚举 | None 的顶层键.
  - 现为 {phase: Phase, opinion_route: OpinionType}.
  - 上面的 TypedDict 子类多出 plan_kind; 列表字段不算.
- 为什么只管顶层: Postgres 检查点把值为 str, int 等基本类型的通道直接存进 JSON, 不经 msgpack 与白名单, StrEnum 读回成字符串; 列表与模型存为 msgpack, 枚举随白名单恢复.
- `restore_enums(channels)`: 按 TOP_LEVEL_ENUMS 原地转回, None 与缺键不动. `test_restore_enums_converts_strings_in_place` 不连库测它.
- 慢测试 `test_full_workflow_real_storage` (memory 与 postgres 两种检查点):
  - 归档后读检查点, `phase is Phase.Archived`, `opinion_route is OpinionType.qualified`.
  - 本地把 AuditPostgresSaver 的转回去掉时, postgres 一种失败 (中途留痕处就因 phase 是字符串报错).

### 审计产出表登记 (验收 4)

- 测试辅助 `versioned_fields(state)`: 去掉可空与 list 后为 Versioned 子类的顶层字段 → 类型.
- `test_versioned_state_fields_have_output_tables`: 类型名含需求列出的 16 种, 全部在 OUTPUT_KINDS 中.
- `test_output_guard_names_unregistered_field`: 上面的 TypedDict 子类报 "audit_plans: LocalPlan".

### 登记清单与将加的字段 (验收 5, 接口文档第 3 节)

- 加状态字段时同一次提交里依次:
  1. EngagementState 加键, STATE_DEFAULTS 登记; 新类型放在 models.py 或 services.py, 放在别处时登记模块.
  2. merge.AGENT_FIELDS 登记写入者 (DecisionSubmit 写的不登记).
  3. 重放取回方式 (X-04 的 FIELD_REPLAY), 多写入者的模型带 run_id.
  4. 元素为 Versioned 的, 类名登记进 OUTPUT_KINDS, 新表配迁移.
  5. 第 3 节字段写入归属表加一行.
- 各组将加的 10 个字段照需求原表列出, 并注明 MD-1 把 misstatements 的 reducer 改为 upsert_by_id 时旧检查点照常读回.
