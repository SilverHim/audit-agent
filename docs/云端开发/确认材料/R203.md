## 方案取舍

1. **run_id 的含义**: 写出这一版的那次执行. RUN-PLN-15-2 起草 PLAN-2, 同时把 PLAN-1 置 superseded, 两个对象都记 RUN-PLN-15-2. 这样合并时能过 R136 的 `check_own_run` (带 run_id 不带 procedure_id 的对象须属于本次执行). 批准由 A1 在闸门写出, 不经合并, 沿用起草时的 run_id.
2. **重放用 by_procedure**: 按第 3 节登记表. 同一 ID 会被不同执行改版: PLAN-1 v1 由第 1 次写, v2 superseded 由第 2 次写. 回退检查点重放时要连带取回之后的执行, 下一次执行才能接着取号. 这与合规检查相同. 批准版沿用起草的 run_id, 仍属 PLN-15 的执行, 重放取得到.
3. **适用框架复用 ReportingFramework**: 按协调者的提醒, 与 ACC-08 的 TermsFacts.framework 同一枚举 (tier1_gpfs, tier2_gpfs, spfr), 计划直接取 TERMS 的值. 没有 TERMS (功能 acceptance 关闭) 或约定书没写明时为空.
4. **ID 与修订号一致**: 模型校验 ID 须为 PLAN-{revision}. 这条需求没要求, 是为了让第 0 节的规则不靠调用方自觉.
5. **GATE_SPECIFIC 加 plan_confirmation** (gates.py 一行, 在需求列的范围之外): 不加的话, R205 之前带确认项的 ACC-01 等决定会被照收并存下. 加了之后, 已登记的四道闸门带它都报 FIELD_NOT_ALLOWED, R206 验收 1 的这一项提前成立.
6. **test_gates**: 原来的等价用例按 `list(GateId)` 参数化, 加 PLN_15 后 spec_of 找不到登记行. R198 已把它改为只取登记表中的基线闸门, 变基后沿用. 本条新加的 plan_confirmation 用例按登记表全部闸门参数化.
7. **分派表先占位**: `test_every_referenced_output_model_is_registered` 要求模板引用的输出模型都登记. 本条登记 `check_plan`, 抛 NotImplementedError (项目约定的占位写法). 不登记 structure_only, 免得 R204 之前接上执行时计划只经结构校验就通过. 引用与语义校验 (R204 验收 4) 由 R204 实现.
8. **片段 ID**:
   - 需求写 ASQM1-P34F, 已登记的是 ASQM1-P34f (子项规则, 见 ASQM1.yaml 注释), 按登记的写.
   - ASA570-P10 的 procedures 原只列 GEN-04, 补上 PLN-15. 这只是信息字段.
   - 其余 11 个片段已列 PLN-15.
   - 片段原文都已在, 不缺 docs/参考资料.
9. **reads 与 params** (需求没列):
   - reads [accounts, trial_balance]: 提示词带本期试算表, 计划之后账表变了, PLN-15 即过期.
   - params 写 period_start, period_end 两个 ref: 期间进参数快照, 重放取同值.
10. **提示词**:
    - 英文, 不渲染程序名称 (模板的 name 是中文).
    - 第 1 修订不出现 "## Revision".
    - terms 为空时写明没核对约定条款, 并要求不写框架与约定书日期.
    - 叙述各段的要点取设计稿第 6.6 节, 写成通用的, 不含 Xero 的具体事实.
11. **前端 locale**: 按 GateId 取值的四张表 tsc 要求齐全, 所以加了 PLN-15, 程序名一并加上. 闸门页的材料与 gateIntro 随 R205 的 PlanMaterial 加.
12. **必填表的位置**: 需求写 "第 2.5 节必填表", 但该表在第 7 节. PLN-15 两行加在第 7 节, 并注明 R205 登记之前报 NOT_AT_GATE; 第 2.5 节的字段注释写明规则.
13. **旧用例的模拟字段改名**: test_state_compat 里模拟 "忘了登记" 的字段原名 audit_plans, 与真字段同名, 改为 forgotten_items; 外来类型用例的 audit_plans 改为 local_plans.
