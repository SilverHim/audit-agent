## 方案取舍

- **名称规范化:** 复用 `services/party_names.party_name_key`, 不另写.
  - 对方名称一侧去说明前缀与 entity_suffixes;
  - 总账一侧只去前缀, 不去后缀;
  - 整词比较写成 `" key " in " text "`.
  - 这三点与 GEN-03 C01 的 SQL 相同.
  - 参考号切词也用 party_names 的 `folded` 与 `separated` (去附加符, 只转 ASCII 小写, 非字母数字换空格).
- **走 X-05 的判断公共流程:** 取对象函数只返回 Subjects, 判断, A7 复核, 降级与 classify 都在 `judging.judge_all` 与 `judgments_patch` 里. 去向全按 ReviewQueue 现有规则, 不另写分支.
- **重跑与 R165 的 `judging.earlier_findings`:**
  - GEN-06 的规则例外都来自前置程序 GEN-07. GEN-06 自己不建例外, 所以不适用 earlier_findings, 后者管的是 "本程序此前执行出的例外".
  - 判断失败时 GEN-07 的例外出 v2 unattributed. 重跑时取当前结果里的这一版, 同 REV-02, GEN-02, GEN-03 取前置程序未归因例外的写法. 用例 `test_only_open_findings_in_scope_are_subjects` 断言 rule_findings 为该 v2.
  - 取前置程序未归因例外的写法原有五处: REV-02, GEN-03, CSH-02 的 cash_subject, GEN-06, 以及按凭证号分组的 GEN-02 (送审时写 "四处", 漏了 CSH-02); 加上 earlier_findings, agents 里共六份. 普审修正 R179-02 抽出 `judging.open_findings`, 六份都改调它 (GEN-02 见普审修正).
- **行的类型:** 取例外的主证据指针 (source_id 等于 source_ids[0] 的第一个) 的 source_type. 不按规则编号判断, 也不读 detail.
- **相关凭证:** 用 E01 的行匹配, 命中的凭证再经 `journal_entries(entry_nos=...)` 取全部行. 由于 E01 已剔除作废对, 作废对不会命中; 对象自身的凭证从结果里去掉.
- **排序:** related_entries 按 (入账日, 凭证号自然序, 行 ID), 自然序用 fieldwork 的 `entry_order`. 相关发票按 E02 的顺序 (入账日, ID). 验收 5 中 XJ-720-2 的两张发票 ORC1001 在 ORC1026 前, 与之一致, 而按 ID 排序会反过来.
- **"本期" 发票:** 按名称取发票时只取入账日不晚于期末的, 流水对象与分录对象同一口径. 流水对象另经 journal_entry_id 取相关凭证上的发票, 期后的也算, 所以 E02 要取到窗口上限. 例如 Ridgeway 的 ORC01025 (10-06) 就是这样取到的.
- **trial_balance 的科目:** 流水对象取其银行账户的 gl_account_code, 例如 BT-090-0092 带 090, 与验收 5 一致. 每行带科目名称与分类, 让模型看得懂科目代码. 试算表没有该科目时 balance_cents 为 null, 例如 XJ-676-2 的 720, 期末没有余额.
- **documents:**
  - 对 {对象 ID, 本凭证号, 相关凭证号, 相关发票 ID} 逐个调 `related_documents`, 每项带各页文字, 同 GEN-02, GEN-03;
  - 按文件 ID 去重并排序;
  - 不按客户 ID 取. 持续经营的备忘录等只关联客户的文件归 GEN-04.
- **window:** 由参数快照算出, 与 SQL 的 bounds 同式, 只放 data.window, task.params 不另加.
  - 快照经 Store 读回时日期为字符串, 两种都收.
- **reads 与 document_reads:**
  - reads: [journal_entries, accounts, sales_invoices, delivery_notes, bank_accounts, bank_transactions, trial_balance, documents];
  - document_reads 同 GEN-02, 列全部可作证据的类型.
  - 按 R304 的守卫, 列了 registry_extract 后 GEN-06 进出生日期守卫 (见下条).
- **出生日期守卫 (test_no_birth_dates):** 改了两处.
  - 依赖闭包里状态中还没有执行记录的程序先执行 (普审修正 R179-06), 由 owner 在 AGENTS {A5, A6, A8} 中的 Agent 执行; GEN-06 的前置 GEN-07 (A5, 结果取 XERO_RULES) 因此先执行, 否则 GEN-06 没有对象. GEN-08 已在状态里, 不再执行. OWNERS 只用来断言受查程序的 owner.
